# 天策 Tiance

> 让多个 AI 在真实项目中协作，并把请求、工具、分支、记忆和产物都摊在用户眼前。

天策不是在聊天框外再包一层“智能体”外壳。你可以让一个 AI 创建和调度更多可见会话，让它们在同一项目中分工、交接、调用工具并留下完整结果；模型请求、思考片段、工具调用、Token 用量、分支关系和生成文件都能回到人的视野里。

它也不只负责“聊”。内置的 Markdown 转 Word 工具能把标题、表格、图片、脚注、Mermaid 和 LaTeX 公式一起交付为正式 DOCX；公式优先转换成 Word 原生可编辑数学对象，表格则根据真实字体、内容和换行代价动态分配列宽。无法可靠表达的结构才降级成图片或保留源码并给出警告。这个原则贯穿整个项目：复杂能力可以强大，但过程不能靠静默丢失和黑箱兜底换来。

普通对话、AI 子任务、会话分支、自动命名、记忆压缩以及项目和全局记忆管理，都进入真实会话。项目文件、工具调用、模型配置和最终产物也各有可检查的来源。新用户可以直接使用默认设置；熟悉以后可以逐层进入项目、会话、工具和配置；开发者则能继续修改同一套源码和运行环境。

## 像晶体一样生长

天策采用一种近似晶体生长的结构。不同项目集共享同一个基本单元，也遵循相同的连接规则。新的能力不是作为附件挂在系统外面，而是从已经成立的项目、会话、工具和关系中继续生长。整体的整洁，不依赖把每项功能修剪成相同外观，而来自内部规则的一致。

这种统一不等于抹平差异。角色、主题、工具和供应商使用适合自己的文件与界面，项目层只提供共同的身份、生命周期和 AI 工作空间。普通用户、专业用户和开发者看到的是不同“晶面”，下面连接的仍是同一批真实项目、会话、文件、工具和运行状态。

## 天策现在是什么

- **项目是 AI 工作发生的地方。** 文件、会话、分支、记忆和产物留在同一个工作范围内，AI 不必站在项目外面工作。
- **各种集共享项目骨架。** 当前项目类型包括普通项目、知识、经验、角色、主题、工具和供应商；每一集的数据根目录也会作为普通项目加入，用普通根会话协助管理整集。知识集和经验集目前只有普通项目骨架与入口，专用设计和开发尚未开始。
- **AI 工作统一成为可见会话。** 人与 AI 的对话、AI 创建的子会话、历史分支和系统功能会话使用同一套运行与记录结构，并在前端按关系组织。
- **多 AI 协作不是后台黑箱。** AI 可以查询、创建、配置、唤起或停止其它会话，也可以向目标会话发送任务并等待回复；每个参与者仍是项目里可以打开、追溯和继续交流的普通会话。
- **三栏工作台承担真实工作。** 左侧组织项目，中间纵览会话、分支、文件和产物，右侧保持当前交流。模型思考、工具调用、执行状态、用量和结果会沿同一条可视链路展开。
- **工具通过明确边界进入系统。** Python 工具、前端实时能力和桌面系统能力各自运行在合适的位置，通过稳定合同连接；AI 向另一个 AI 发消息时，也沿人与会话相同的路径工作。
- **Markdown 可以成为真正可编辑的 Word。** 转换器会继承模板样式，并处理目录、列表、任务项、表格、图片、脚注、Mermaid 和数学公式；LaTeX 公式优先经过 MathML 转成 Word 原生 OMML，表格列宽则通过实际字体测量和换行代价动态求解，而不是一律截图或平均分列。
- **长会话可以继续向前。** 累计摘要承担会话级记忆；项目记忆和全局记忆则使用独立事件与变更投递，在不随意破坏请求前缀的情况下进入已有会话。
- **内容可以从在线市场流通。** 七类现有项目类型都已进入统一市场入口，默认连接公开共享仓库，也可以通过 GitHub 授权读取私人仓库。知识和经验目前流通的仍是普通项目快照，不代表其专用功能已经完成；下载后的内容仍然是可以查看、修改和继续对话的本地项目。
- **供应商差异有统一住所。** 声明型差异进入供应商和模型规则文件，复杂协议转换留给对应适配层，不把不同供应商的特殊判断散落到业务代码中。

## 当前阶段

天策仍在持续开发，目前更适合希望了解、试用、研究或共同改进这套产品的人，还不是一个接口与数据格式已经长期冻结的稳定发行版。

项目从 2026 年 4 月底开始迭代，2026 年 8 月 2 日首次系统整理并开放源码。这是一个由业余产品经理主导、主要借助 AI 编程完成的个人项目。作者本人不具备独立代码审查能力，因此现有测试、开发记录和 AI 审查报告不能等同于专业人工代码审查，也不能据此宣称项目已经通过完整的安全性与稳定性审计。

已经形成的主线包括项目与会话体系、可视化分支、多 AI 协作、工具系统与三条桥、累计摘要压缩、项目与全局记忆投递、多格式文件预览和编辑、Markdown 数学公式渲染与 Word 转换、供应商适配、统一在线市场以及 Windows 内置运行环境。

知识集和经验集的专用设计与开发还没有开始，目前只是沿用普通项目结构。设定集项目化、基础角色集与各集默认角色也属于后续方向。正在继续收口的是供应商声明规则在全部协议与操作中的执行覆盖，以及市场从当前开发状态走向稳定发布。README 只描述当前真实边界，不用未来规划填满功能清单。

## 在 Windows 上启动

当前构建与发布主线是 Windows。仓库已经包含内置 Python、后端依赖和编译后的前端，不要求为了启动软件另外安装 Python 或 Node.js。

```powershell
git clone https://github.com/LikeMirage/Tiance.git
cd Tiance
```

随后双击根目录的 `Tiance.exe`。请保留完整目录结构，不要只移动单个 EXE 文件。

首次使用需要在模型集里添加自己的供应商配置和 API Key。仓库与客户包不预置私人密钥。当前没有可直接运行的 macOS 或 Linux 发行包。

## 源码开发

天策没有另做一套与正式运行割裂的“开发版”。桌面壳启动时会优先连接本机的前端开发服务；没有检测到开发服务时，才使用 `2_ReactWeb/dist` 中的构建结果。后端和桌面壳默认继续使用仓库内置环境。

前端要求 Node.js `>= 22.12.0`，包管理器统一使用 pnpm：

```powershell
cd 2_ReactWeb
pnpm install
pnpm dev
```

保持前端开发服务运行，再从仓库根目录启动 `Tiance.exe`，桌面窗口就会加载实时前端。构建与基础验证命令为：

```powershell
cd 2_ReactWeb
pnpm check
pnpm test:conversation-state
pnpm build
```

后端和桌面壳分别使用 Python `>= 3.11`。通常无需为它们重复安装依赖；如需脱离内置环境单独开发，可依据各自的 `pyproject.toml` 建立独立 Python 环境。真实环境变量以三个示例文件为准：

- `1_PythonServer/.env.example`
- `2_ReactWeb/.env.example`
- `3_PyWebView/.env.example`

## 仓库结构

| 目录 | 职责 |
| --- | --- |
| `1_PythonServer/` | FastAPI 后端：项目、会话、模型、工具、记忆、市场和文件业务 |
| `2_ReactWeb/` | React 前端：三栏工作台、看板、编辑器、预览和前端能力桥 |
| `3_PyWebView/` | 桌面壳：窗口、后端生命周期和有限操作系统能力 |
| `Data/` | 内置运行环境，以及按项目组织的本地数据、主题、工具和供应商配置 |

三个部分的边界是有意保留的：后端保存业务事实，前端组织人的视线，桌面壳只承担浏览器做不到的系统能力。统一不靠把所有职责塞进同一个进程。
