# 音视频转写

独立 Python 工具。上传本地音轨至字节云端，生成完整转录文件；支持常见音视频及微信 SILK 语音；无需 Node、桌面转码软件、模型集 Key 或天策能力桥。调用名为 `audio_transcribe`。

只接受三个参数：

| 参数 | 必填 | 默认值 |
| --- | --- | --- |
| input_path | 是 | 音频或视频文件路径 |
| output_dir | 否 | 天策当前工作区；独立运行时为当前目录 |
| formats | 否 | `["json"]`，可选 json/txt/srt/ass，可多选 |

```json
{"input_path":"D:/录音/会议.m4a","output_dir":"D:/转录结果","formats":["json","txt","srt"]}
```

## 安装和独立运行

天策使用的 Windows x64 CPython 3.13 可直接使用工具自带的精简 PyAV / FFmpeg 模块，位于 `program/vendor/cp313-win_amd64/`。它负责读取音轨信息、压缩音频分段复制，以及其他格式的解码、切分和 FLAC 编码；普通 Python 依赖只有 `program/requirements.txt` 中的 httpx。无需安装完整 PyAV、imageio-ffmpeg 或 ffmpeg.exe，也不需要配置系统 PATH。

```powershell
python -m pip install -r program/requirements.txt
'{"input_path":"D:/录音/会议.m4a"}' | python program/main.py
```

标准输入一个 JSON 对象，标准输出一个 JSON 对象；日志在 stderr。失败返回非零退出码。程序不导入天策后端。天策按既有机制安装并加载普通 Python 依赖，自带模块由工具自己的代码加载。

其他 Python 环境（Python 3.10 及以上、不同系统或架构）需要另行安装 `av==16.0.1`，工具会使用该环境的 PyAV。自带的精简模块是 Windows x64 CPython 3.13 原生库，不能直接跨平台复用。构建来源、版本、校验值及重建步骤见 `native-build/README.md`。

## 微信语音与 SILK

直接把原始 `.speex` 或 `.silk` 路径传给 `input_path`，不需要另行转换。按文件头识别标准 `#!SILK_V3` 和微信的 `0x02 + #!SILK_V3`；其他文件继续走原媒体读取流程，不按后缀误判编码。

工具自带 `program/vendor/silk/windows/silk_v3_decoder.exe`（179,037 字节）。预处理校验包边界，在独立临时目录使用短 ASCII 文件名运行解码器，再封装成 24 kHz、单声道、16 位 WAV，接续原有分段、上传和导出流程。24 kHz 为 SDK 默认输出采样率，不代表提高原录音的信息量。单包录音在临时输入补一个相同包以满足 CLI 的预读要求，输出剔除补齐部分。

原输入不修改，结果与 `job.json` 的输入路径仍指向原文件；`source_decoding=silk_v3_to_wav` 记录预处理，直接上传该 WAV 的分段标为 `audio_processing=silk_decoded_wav`。临时文件在正常返回或异常退出处理时清理。解码、封装也使用工具同一个总执行预算。损坏、缺包、截断、解码异常明确返回失败，不上传部分音频。

自带 SILK 解码器仅支持 Windows，不要求 Python 原生扩展或系统安装。缺失解码器会报依赖缺失，不临时联网下载安装。来源、固定版本和 SHA-256 在 `program/vendor/silk/source.json`，相关许可在同目录。

## 文件与时间轴

每次在输出目录中新建 `<源文件名>_asr_<唯一后缀>` 子目录，不覆盖原文件和既有结果。最终文件仍使用源文件名。

- JSON 是句段数组，字段为 text/startMs/endMs/words；words 由云端提供，时间单位毫秒。保留原文字和异常零时长词条，返回异常计数，不擅自修复或删除。
- TXT/SRT/ASS 为本地导出。字幕字数、行数、ASS 样式使用固定默认值，不作为输入参数。
- `job.json` 保存状态、实际切分边界、实际并发数、各段状态和任务 ID、音频处理方式及上传字节数、源文件指纹、统计和输出位置。并发任务更新同一记录时会串行写入。
- `parts/*.raw.json` 保存各段完整云端识别响应，包含未映射到标准 JSON 的附加字段；它们的时间戳仍是段内时间。不要把这些原始时间戳与合并后的时间轴混淆。
- 返回正文只含路径、大小、时长和统计；全文在文件中，不截断。

段数为 `min(20, ceil(总秒数 / 600))`，然后基本等长分配。10 分钟以内保持一段，三小时分成 18 段各 10 分钟，五小时分成 20 段各 15 分钟，十小时分成 20 段各 30 分钟。600 秒是目标大小，不是硬上限；不会为了严格小于目标多切一段，也不会留下短尾段。复制 AAC 压缩数据时，共用切点对齐到音频帧边界，各段与理想等长的偏差小于一帧，末尾覆盖到音轨结束。策略常量统一在 `program/jianying_asr/media.py` 的 `SEGMENT_SECONDS` 和 `MAX_PARTS`，不增加 AI 调用参数。

每次调用总共只有 1～20 个分段，全部建立并发任务，不再分出更多段等待第二批；非法超过 20 段的内部计划会在上传前报错。20 路已用真实录音测试，但不代表上游承诺不排队。各段使用独立 HTTP 连接和同一设备标识。音轨提取一次处理一段以控制 CPU、内存占用，上传和云端识别与后续提取重叠；上传完成即可清理临时音轨，不等云端识别结束。这不是整个天策的全局并发限制。

短的受支持纯音频仅在请求完整音轨时直接上传。需要分段或提取视频第一条音轨时，优先复制已验证的 AAC-LC/MP4 压缩包到 M4A，不重新编码、不降低采样率或声道；切片总体积接近原音轨，仅增加少量容器和解码预备数据。当前快路径要求音轨起点为零、标准单/双声道、1024 采样帧、连续且有效的时间轴；HE-AAC、ALAC、其他容器或布局保留原有 FLAC 处理方式，不凭文件扩展名强行复制。符合快路径但读取时发现时间轴损坏或覆盖不全，会明确报错，不静默跳过音频。

FLAC 路径保持采样率和声道，按解码后的采样位置裁切。16/24 位整数音频无损保留，浮点音频转换为 FLAC 支持的整数格式；FLAC 可能明显大于原压缩音频。两条路径都逐包/逐帧处理，不把完整音频读入内存，不修改源文件。并发不增加本机上传带宽，不保证切得越短越快；本轮真实录音对比见 VALIDATION.md 第五阶段。

拼接始终按原分段顺序，给句段和词级时间戳加上实际切点偏移，不按完成先后拼接。输出时间戳按格式要求取整到毫秒。AAC 后续片段带负时间戳解码预备包，MP4 edit list 将它们排除在播放区间外；本地音频包与云端词级时间轴均已实测，不能把预备包时长额外加进合并偏移。所有段成功才导出完整文件；分段边缘可能影响识别分句，不能保证跨段语句的识别准确率与整段提交完全相同。

## 失败、取消与时限

总执行预算唯一来源为 `.tool/tool.json` 的 `runtime.timeout_seconds`，初始 3600 秒，包含提取、上传、等待和导出。这个小时是处理等待预算，与音频分段长度无关。可修改标准配置；没有额外五分钟轮询上限。网络操作与音轨处理共用剩余预算，逐包复制和逐帧解码、编码时检查预算。整个网络请求（连接、上传、等待响应头和读取响应体）受剩余总时间约束，零星返回数据不会重置总截止时间；到期取消本地网络等待并返回 `TIMEOUT`。查询间隔 2 秒，查询遇到 429/5xx 或连接异常时在预算内等 5 秒重试同一个任务，返回警告记录重试次数。上传和提交不自动重试，避免重复上传或重复创建任务。

均分后单段即使达到 3 小时，也按该段提交，不凭未经验证的猜测设两小时上限；这不等于保证上游接受任意时长。处理合同如下：

| 情况 | 处理 |
| --- | --- |
| 上游明确拒绝时长、大小或其他条件 | 记录失败；保留上游业务错误码和说明，HTTP 拒绝则记录 HTTP 状态码。不自动截短、重编码、再次细分或重复提交。 |
| 已提交任务暂时没有结果 | 在同一个总预算内等待或查询；没有响应也受绝对剩余时间约束。 |
| 空 HTTP 响应、无效 JSON、缺少必要结果结构 | 明确返回 `INVALID_RESPONSE`，不当成空字幕成功。 |
| 有效结构明确返回空 utterances | 保存原响应和空结果，标注“云端返回空转写”；不能据此断言原音频无语音。 |
| 任意分段失败或超时 | 整次返回 `ok=false`；成功分段仍保留，不能导出或声称完整全文。 |

进度和结果先写入独立临时文件，再原子替换目标文件。Windows 临时共享占用导致替换失败时，最多额外重试 5 次，合计等待不超过 0.93 秒；活动任务仍受同一总预算约束。持续权限错误会正常返回失败并保留旧有效进度，不无限重试。这是本地文件写入恢复，不是另一层识别超时。

已取得任务 ID 就立即写入 job.json，失败保留已完成原始结果和任务 ID，不假称全文完成。某个分段失败时，其他分段继续至完成或共用总预算耗尽；最终返回 `completed_parts`、`total_parts`、`failed_parts` 及结果目录。每个失败项包含段号、原音频起点、时长、错误阶段、错误码、原因，以及已经取得的任务 ID。阶段为 preparing（音轨准备）、uploading（上传）、submitting（提交）、processing（结果查询）、saving（保存和验证）；计划阶段失败可能为 pending。超时后的最终失败记录不再要求工作预算尚有剩余，但文件写入仍可能失败并报告 checkpoint_error。重跑会创建新的目录和新的云端任务；本版本没有自动恢复入口。若平台先达到外层时限而强制终止进程，平台会报告超时，工具可能来不及返回 JSON 或更新最终状态；之前的原始结果仍保留。强制取消也可能留下 running 状态或系统临时音频，不保证云端任务已取消。

上传采用分块读取，只发送一次音频 PUT，再提交 CRC 校验。实测原客户端额外的第二次全量 PUT 返回 HTTP 400；去掉它后识别仍成功，因此不保留这次重复传输。所有鉴权错误省略签名 URL 和临时凭据。

## 天策接入

工具项目 UUID 与 `manifest.id` 保持不变，市场包从 1.0.0 升至 1.1.0；展示名改为“音视频转写”，当前调用名为 `audio_transcribe`。包 ID 保持稳定以便原工具就地更新，不新增重复工具。

新工具默认关闭、动态加载；在工具集启用即可。配置位于 `.tool/tool.json`。平台是否允许并发调用多次工具，由其中的 execution.parallel 决定；单次工具内部的分段并发独立于这个开关。不修改用户已有的启用状态、会话选择或权限策略。

当前权限合同每个参数只能声明一个主要类型：必填 input_path 标为公网访问以覆盖不可省略的云端上传，显式 output_dir 标为文件写入；默认输出在工作区。实际副作用还包括读取输入文件、写结果和临时音频。常规音轨在当前 Python 进程中处理，不启动 FFmpeg 子进程；SILK 预处理会启动工具自带的解码器，等待时间受同一总预算约束。天策参数权限不是操作系统沙箱。

接口实现移植自 https://github.com/xifan2333/jianying-subtitle ，参照提交 b14e42cfd29a9e829a4b5a2edb75166ced89de12。保留 GPL-3.0-only 许可与来源说明，见 LICENSE、NOTICE。自带 PyAV、FFmpeg、zlib 的许可位于 vendor 内的 dist-info/licenses 目录；SILK 解码器来自 kn007/silk-v3-decoder，其 MIT 与 Skype SDK 许可位于 `program/vendor/silk/`。没有去除第三方署名。

这是上述开源项目所用云端接口的第三方实现，没有官方稳定性或长期免费承诺。音轨会发往字节服务器；没有本地语音模型。语言选择、热词、说话人区分等尚未验证，不提供无效开关。

## 验证

本工具仍是独立 Python 工具，不依赖天策后端。`program/jianying_asr/engine.py` 是与后端逐字节同步的识别核心；`runner.py` 保留工具配置适配，读取本工具的 `runtime.timeout_seconds`。后端拥有自己的完整副本，不在运行时加载本工具。

在天策源码根目录修改核心后，运行 `python scripts/sync-speech-core.py --from-tool`（先改后端则用 `--from-backend`），再执行 `--check` 及两边测试。同步范围、录音与取消语义见源码文档 `docs/输入框语音与独立转写核心.md`。工具单独分发和升级时不需要此同步脚本。

安装依赖后运行 `python -m unittest discover -s tests -v`。离线测试不上传音频；联网验收记录见 VALIDATION.md。
