## 当前工作区的状态

这是完整但尚未实现业务的 Python 工具模板，`.tool/tool.json` 的 `state.enabled` 为 `false`。`program/main.py` 只返回 `TOOL_NOT_IMPLEMENTED`，不会伪装成业务执行成功。输入暂为不接受任何字段的对象；案例为空，避免无效示例进入模型上下文。

显示名称与调用名已经写入清单。未指定调用名时，创建器用新项目的 UUID 生成唯一调用名；正式制作时可以改为稳定、清楚的英文名称，但须核对当前工具集中不重名。

## 建议的制作顺序

1. 理解用户目标，确定文件、网络、程序或天策内部数据的实际作用范围。
2. 阅读上述资料；先检索已有工具和通用能力，复用现有接口和运行帮助函数。
3. 保持工具关闭，定义输入参数、输出、权限和超时；再实现 `program/main.py` 及必要模块。
4. 所有日志写 stderr；标准输出只保留一个最终 JSON 对象。结果必须如实区分成功、失败、部分完成和未知状态。
5. 加入真实案例，安装实际依赖，完成直接入口、平台参数校验、权限和真实调用验证。
6. 制作完成后按用户意愿决定是否开启。需要开启时编辑 `.tool/tool.json`，仅把 `state.enabled` 改为 `true`；确认目标会话也允许该工具。没有启用意愿就保持关闭，并报告完成状态。

## 文件与应用边界

本项目的 `.Tiance` 是会话和调用记录，不是工具程序配置。不要直接修改它或工具集的 `catalog.json` 来模拟产品行为；分类与项目创建应走现有接口。工具集“新建工具”按钮仍只创建项目和初始会话，本创建器额外装配模板和资料。

工具可以使用自己的模板、资源和私有依赖。普通业务工具通常无需修改天策后端；需要未开放的宿主数据、凭据或新前端能力时，必须完善通用能力合同和授权边界，不能靠直接导入服务、读内部数据库或绕过访问密码解决。

## 创建异常时

创建器先完整读取模板和文档，再创建项目，按顺序写文件，最后写 `.tool/tool.json`。写入中断会返回已经创建的项目与已写入文件，保留现场供修复，不自动删除或重建。断线后结果未知时，先检查目标分类，避免重复创建。创建器依赖前端在线，不能当作无人值守后台服务。
