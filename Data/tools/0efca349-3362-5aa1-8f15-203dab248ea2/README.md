# 对外消息发送

独立 Python 工具，无额外第三方依赖。通过天策 `external_messaging` 能力桥复用 Telegram、飞书或微信连接，密钥不进入工具文件或参数。

输入、返回与边界详见 `.tool/input.schema.json`、`.tool/examples.json`。回复远程请求时，使用当前消息来源标注中的 `platform`、连接 ID 和聊天 ID；需要查询可用连接时使用 `list_connections`。发送时必须明确填写目标。`send_text` 使用 `text` 发送纯文本；`send_file` 使用 `file_path` 发送文件，可附 `caption`。不推断上一条消息的发送人，不要求任务由手机发起。

手机端用户通过 Telegram、飞书或微信远程指挥时，看不到天策中的思考、工具调用和中途文字，只自动收到最终回复或错误。一直不发消息，会让用户无法判断请求是否收到、任务是否开始、进展如何或是否卡住。

因此，收到远程请求后，无论任务长短、后续要经历多少次工具调用循环，AI 都必须首先调用 `send_text` 向来源用户确认收到，并简要说明接下来做什么，然后再开始实际任务。关键步骤开始前主动说明行动，结束后报告实际结果和下一步；遇到阻碍、失败或需要用户决定时及时通知，交付文件时说明内容和用途。不能用天策中的中途文字代替工具发送，也不能等到最终完成才回复。进度按关键阶段汇报，不机械地逐个工具调用刷屏；普通进度发送后继续执行任务。

此工具单向发送，不等待回复，不建立等待任务，也不改变手机正在选择的会话；若必须获得用户答复才能继续，发出问题后结束本轮，等待用户下一条消息。原调用名称 `external_send_file` 保留，已有工具选择和文件调用不变。

微信需要指定接收者近期发来的有效回复凭据；无法取得时明确失败，不改发给其他人。长文字、文件和说明可能分为多条消息；返回未确认或部分成功时先核对目标聊天，不自动重发。发送成功只表示平台确认，不表示用户已读或已答复。
