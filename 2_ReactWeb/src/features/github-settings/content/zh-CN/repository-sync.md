# 仓库与同步

## 先分清三种仓库用途

| 类型 | 用途 | 从哪里操作 |
| --- | --- | --- |
| 私人在线市场 | 浏览并安装单个项目、工具、主题或其他内容 | 各集的在线市场 |
| 集合同步仓库 | 整体备份一个集合，并在不同电脑间同步 | 各集的“云同步”看板 |
| 普通 Git 仓库 | 管理当前普通项目的提交、分支和版本历史 | Git 与 GitHub 工具 |

三者可以复用同一次 GitHub 登录，但仓库格式和操作入口不同，不能把一个普通代码仓库直接当作在线市场索引。

## 新手建立第一个同步仓库

1. 先在“登录”标签完成 GitHub 登录和完整授权。
2. 让 AI 创建一个私人仓库，或在 GitHub 网页创建空仓库。
3. 如果安装 App 时选择了 `Only select repositories`，回到 GitHub App 设置中把新仓库加入授权范围。
4. 打开目标集合的在线或云同步看板，选择该仓库并完成绑定。
5. 第一次提交前先检查变化清单，再确认执行。

建议一个集合使用一个独立仓库。这样目录清晰，也更容易判断一次同步会影响哪些内容。

## 安全同步流程

### 从远端拉取

`选择仓库 → 检查拉取 → 查看新增、修改和删除项 → 确认拉取`

### 提交到远端

`选择仓库 → 检查提交 → 查看新增、修改和删除项 → 确认提交`

检查阶段不会修改本地或远端内容。生成检查结果后，如果本地或远端又发生变化，旧结果应失效并重新检查，避免把过期判断直接执行。

## 集合同步和 Git 工具怎样选择

- 要同步整个项目集、工具集或主题集：使用对应看板中的“云同步”。
- 要维护当前普通项目的代码历史、分支、提交和远端：使用 Git 与 GitHub 工具。
- 要从私人仓库挑选一个内容安装：把符合市场合同的仓库设为私人在线市场来源。

涉及覆盖、删除、合并或强制推送时，先阅读差异再确认，不要只根据一句“同步完成”判断结果。
