# Быстрый старт

## 0. Проверьте доступ к GitHub

Для входа и работы с репозиториями нужен доступ к `github.com`, `api.github.com` и странице проверки устройства GitHub. Сначала откройте [GitHub](https://github.com/) в браузере. Если соединения нет, проверьте сеть, DNS, системный прокси, брандмауэр и правила организации. Разрешённый прокси можно настроить в сетевых настройках Tiance.

Не запускайте вход многократно без сети: код устройства имеет ограниченный срок действия. После восстановления соединения начните заново.

## 1. Установите GitHub App Tiance Desktop

Откройте [страницу установки Tiance Desktop](https://github.com/apps/tiance-desktop/installations/new). Обычному пользователю нужно **установить готовое приложение**, а не создавать собственное GitHub App.

## 2. Выберите личную учётную запись или организацию

- Для первого использования рекомендуется личная учётная запись.
- В организации может потребоваться одобрение администратора. Кнопка `Request` не означает ошибку Tiance.

## 3. Предоставьте достаточный охват и права

Новым пользователям рекомендуется **All repositories**. Тогда текущие и будущие репозитории будут доступны без повторной настройки.

Если репозиториев ещё нет, всё равно завершите установку и вход. Затем попросите AI в Tiance создать первый репозиторий — при **All repositories** он автоматически войдёт в разрешённую область.

Приложению нужны следующие права:

| Разрешение | Уровень | Назначение |
| --- | --- | --- |
| Metadata | Read | Определение репозиториев |
| Contents | Read and write | Файлы, ветки, теги и релизы |
| Administration | Read and write | Создание, изменение, Fork и удаление репозиториев |
| Pull requests | Read and write | Создание, проверка и слияние PR |
| Issues | Read and write | Issues, комментарии и метки |
| Actions | Read and write | Просмотр и управление запусками |
| Workflows | Read and write | Изменение файлов workflow |

Подтвердите новые разрешения, если GitHub запросит это. Доступ только для чтения не позволяет публиковать и синхронизировать изменения.

Опытные пользователи могут выбрать **Only select repositories**.

## 4. Завершите вход по коду устройства

1. Откройте вкладку «Вход» на этой странице.
2. Нажмите «Войти в GitHub».
3. Введите показанный Tiance код на официальной странице GitHub.
4. Подтвердите доступ и вернитесь в Tiance — страница обновится автоматически.

Не отправляйте код устройства AI. Полученные данные авторизации безопасно сохраняются на этом компьютере.

## 5. Проверьте настройку

На вкладке «Вход» убедитесь, что:

1. Отображается правильная учётная запись.
2. Нет сообщения об отсутствующих возможностях GitHub App.
3. Нужный репозиторий отмечен как доступный для чтения и записи.

Если репозиториев пока нет, достаточно проверить учётную запись и права App, а затем попросить AI создать первый репозиторий.

## Собственное GitHub App (для сборок разработчика)

Обычным пользователям этот раздел не нужен. Разработчику собственной сборки следует:

1. Создать App в GitHub `Settings → Developer settings → GitHub Apps`.
2. Включить **Device Flow**. Callback и Client Secret для Tiance не нужны.
3. Отключить Webhook, если он не используется отдельно.
4. Настроить перечисленные выше Repository permissions.
5. Установить App на учётную запись; проще всего начать с **All repositories**.
6. Скопировать **Client ID** и добавить в `1_PythonServer/.env` исходного проекта:

```text
GITHUB_CLIENT_ID=ваш Client ID
```

Перезапустите Tiance. Не сохраняйте Client Secret или токены в репозитории.
