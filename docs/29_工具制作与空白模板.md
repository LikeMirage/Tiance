# 工具制作与管理

核验日期：2026-11-10。工具仍是独立项目，启用、动态加载和并发开关保存在 `.tool/tool.json`。工具管理不改变普通 Python 工具的运行合同。

## 管理入口

显示名称升级为“工具管理”，保留调用名 `create_blank_tool` 和原工具项目 ID，避免已有会话的工具选择失效。能力桥为 `tool.projects v2`。

| action | 主要参数 | 行为 |
| --- | --- | --- |
| list_categories / create_category | 创建时 name | 查询或创建工具分类 |
| list / get | list 可按 category_id；get 用 project_id | 查看项目、路径和配置 |
| create_tool | category_id、name；可选 call_name | 创建新工具项目，再写标准文件和说明 |
| initialize_current | 可选 call_name | 在调用会话的已有工具项目补齐缺失文件 |
| rename / move | project_id 与 name / category_id | 使用现有项目管理流程 |
| set_state | project_id；enabled / dynamic / parallel 至少一个 | 只修改明确传入的开关 |
| delete | project_id、confirm=true | 使用现有项目删除与系统回收站流程 |

新模板强制关闭；已有工具的开关不会因补齐文件而改变。完成制作和验证后按用户意愿开启，目标会话的工具选择仍独立生效。删除不能指向本次调用项目或正在执行的管理工具。

## 原地初始化的共同边界

工具管理、角色管理与主题管理都以执行上下文中的调用项目为目标，不使用当前界面正在查看哪个项目，也不接受任意目标路径来初始化。

后端 `project_scaffold.py` 统一验证：项目已登记、项目和分类类型正确、真实根目录是对应集根目录的直接子目录；工作区本身以及模板写入路径均不得通过目录链接或符号链接逃离范围。拒绝 `.Tiance`、绝对路径、上级路径和重复目标。前端的检查不能代替后端检查。

初始化只补缺失文件。全部内容先准备好，再通过现有批量文本事务写入；任一提交失败则回滚本次文件，已有用户文件不覆盖。创建目录与写入模板不是跨接口事务：写入失败时返回已知项目身份，在该项目继续初始化；创建响应丢失则报告结果未知，先查列表，不能盲目重建。

普通文件编辑功能不受这条模板初始化边界影响。这里限制的是管理工具放置标准模板的位置。

## 角色、主题与会话

- 角色管理 `manage_roles` / `role.projects v1`：分类、列表、详情、新建、原地初始化、重命名、移动、删除。说明复制到 `docs/role-development/README.md`。新角色复用界面的默认角色文件初始化流程；原地补缺采用中性模板，不把“角色创建者”的工作提示词误写入目标角色。
- 主题管理保留 `theme_designer` 调用名与原 Python 运行方式。保留设计、配色、创建、复制、编辑、切换和恢复；新增原地初始化。删除统一走项目回收流程。说明复制到 `docs/theme-development/README.md`，复制主题不带 `.Tiance`。
- 会话管理 `conversation.management v3`：角色为完整配置基础（包括模型），显式覆盖项最后应用；可单独选择继承调用者模型。复刻复用用户编辑分支的复制流程，归 AI 子会话，不切换用户界面。详见[前端能力桥与会话管理](09_前端能力桥与会话管理工具.md)。

三种创作者角色的提示词同步指向各管理工具、资料入口和原地初始化检查；默认角色选择仍由设定集保存，既有会话不会被改写。

## 生命周期与验证

前端工具仍经过统一 Schema、权限、租约、执行证据与结果提交机制。新版管理动作的 action 包含写入，因此按现有“每个参数一个权限类型”的规则保守声明全局天策写入；查询动作只读取数据，但也经过该权限策略。delete 的 confirm 另声明删除权限。没有增加按工具名跳过检查的例外，也不承诺 ask 一定弹窗，实际由会话审批模式决定。

验证覆盖：三类目录及链接边界、已有文件保留、整组写入回滚、外部创建竞争、角色/模型覆盖、AI 运行中复刻的历史边界、子会话分类、未切换当前会话、桥版本及参数合同。源码变动后构建前端并重启应用，以载入新后端和桥版本。
