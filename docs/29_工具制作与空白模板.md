## 当前入口

“开发与运行”分类中的“新建空白工具”，调用名 `create_blank_tool`：

| action | 参数 | 结果 |
| --- | --- | --- |
| list_categories | 无其他参数 | 分类 ID、名称和只读状态 |
| create_category | name | 真实工具分类 |
| create_tool | category_id、name；可选 call_name | 新项目、完整模板、资料入口、默认关闭状态和指引 |

创建器自身启用，生成的新工具始终关闭。模板内的 Python 入口只报告尚未实现。制作并验证完成后，根据用户意愿决定是否将新项目 `.tool/tool.json` 的 state.enabled 改为 true；会话工具选择独立生效。

## 接入与执行边界

前端新增 `tool.projects v1` 能力，复用原有分类、创建项目和保存文件接口；模板由执行工具自己的项目文件读取接口加载。后端仅为通用 client 请求补充已有的 tool_project_id，沿创建请求和事件序列化传递；没有添加新建工具专属后端路由或复制项目生命周期。

请求先经过现有参数和权限校验。模板完整读取并检查后才创建项目；其余文件写完后最后保存 tool.json。新清单强制关闭，即使源模板被误改为启用也不会直接开放。模板不覆盖 .Tiance，不向已有项目写入，不自动删除项目，不切换用户当前项目。

写入失败或取消返回已知项目与已完成文件，供继续修复。创建 POST 的响应丢失时报告结果未知，不自动再次创建。前端重放使用已有租约和执行证据，不能声称它实现了服务器端项目创建事务。此工具需要前端在线；更新后端和前端代码后需重启应用才能使用新的能力合同。
