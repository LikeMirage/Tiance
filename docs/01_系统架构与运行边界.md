# 系统架构与运行边界

> 当前实现基线：`0.3.23`。

## 三个运行部分

| 部分 | 目录 | 当前职责 |
| --- | --- | --- |
| FastAPI 后端 | `1_PythonServer/` | 项目、会话、模型请求、工具、记忆、市场、文件和持久化 |
| React 前端 | `2_ReactWeb/` | 工作台、编辑器、预览、页面状态、会话流和 client tool 执行器 |
| pywebview 桌面壳 | `3_PyWebView/` | 创建窗口、选择后端端口、管理后端进程、系统托盘、更新器和有限本机能力 |

`Data/` 保存预置与本地内容，`runtime/` 保存随包运行时，`system/` 保存版本和更新相关文件。正式安装包会包含这些目录以及编译后的 `2_ReactWeb/dist/`。

## 启动流程

1. `Tiance.exe`/launcher 确认安装目录和版本文件。
2. 桌面壳按配置选择嵌入式 Python，并在 `18000-18020` 中选择后端端口。
3. 后端通过 `/health` 对外提供就绪检查。
4. 桌面壳优先尝试 `TIANCE_FRONTEND_DEV_URL`（默认 `127.0.0.1:18100`）；不可用时加载 `2_ReactWeb/dist`。
5. 前端通过启动参数或环境配置确定 API 根地址，随后建立 HTTP、SSE 或 WebSocket 连接。

开发服务器优先属于当前实现，不是文档建议。正式打包或安全敏感环境不应在同一端口运行无关服务，具体限制见[当前限制与风险边界](11_当前限制与风险边界.md)。

## 职责边界

- 后端保存业务事实；前端状态只是展示和交互投影。
- 前端分页、折叠、虚拟列表和缓存不得改变模型上下文或持久化事实。
- 桌面壳只提供浏览器无法完成的本机能力，不应承载项目业务规则。
- 供应商差异放在协议适配器、Profile 和声明规则中，不应散落到页面或通用会话流程。
- 具体工具不应通过特殊消息类型或数据库字段获得通用层特权。

## 数据版本边界（2026-10-30）

本项目不保留应用自身旧数据格式的自动兼容、转换和迁移程序。空存储直接初始化当前结构；遇到不支持版本时明确报告，不替用户清空或转换数据。项目目录、工具、供应商继续使用现行文件合同，数据库只保存其各自负责的事实。此约束不取消标准协议适配、当前格式正常默认值或用户主动触发的维护操作。具体存储范围见 [项目、会话与存储](02_项目会话与存储.md)。

## 公共 HTTP 客户端的使用和回收（BE-046）

`app/infra/http_client.py` 统一管理代理、超时和连接池。请求入口必须使用
`async with lease_http_client(get_shared_http_client()) as client:`，并把流式响应的整个读取区间放在这个作用域内；不要取出客户端后跨越一个 `await` 再登记使用，也不要缓存裸客户端用于后续请求。

修改网络配置后，已有连接池从可复用集合移出，新请求使用新配置。仍有请求使用的旧池保留到最后一个使用者退出，再在所属事件循环关闭；没有请求的旧池立即安排关闭。正常结束、异常、取消以及流式生成器关闭均释放使用计数。同步设置接口可从工作线程触发回收，不直接跨线程关闭网络连接。应用退出仍统一清理尚存客户端。

模型请求、供应商能力桥、GitHub、在线市场、更新下载和网络诊断遵循同一生命周期，不按具体供应商或工具名区分。测试：`1_PythonServer/tests/test_http_client_retirement.py`。

## 内置语言与用户语言的读取（BE-138）

内置语言包的读取与结构校验按文件路径、修改时间、大小和文件标识缓存；安装更新或修改内置文件会使缓存失效。缓存只保存当前一套内置资源，不缓存 `Data/locales` 下的用户语言和选择设置。用户文本修改、新增/删除自定义语言，以及补齐缺失词条的原有机制继续生效。

这项修复减少接口内重复读取；原复核的约 26～28 毫秒开销不能据此认定为持续高 CPU 或整体卡顿原因。
