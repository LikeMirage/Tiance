# 前端能力桥与桌面壳

## client tool 链路

有些能力依赖实时界面状态，例如打开标签、显示会话或读取当前编辑器选择。模型仍发起标准工具调用，后端创建 `client_tool_request`，前端按预先登记的能力名执行并提交结果。

```mermaid
sequenceDiagram
    participant M as 模型
    participant B as 后端工具循环
    participant F as 前端能力桥
    participant E as 已登记执行器
    M->>B: tool call
    B->>F: request_id + name + arguments
    F->>E: 参数校验后执行
    E-->>F: structured result
    F-->>B: claim / submit result
    B-->>M: 正式 tool result
```

能力名不是任意 JavaScript 函数名。前端注册表拒绝重复能力，未登记能力失败。项目归属必须来自工具调用上下文；当前可见项目只能影响纯 UI 展示，不能作为业务写入的兜底身份。

## 生命周期

后端维护等待请求、领取和结果提交。前端用单飞表避免同一进程内重放造成重复执行。取消等待不等于回滚已经完成的文件、会话或界面动作。

当前实现仍需要加强多执行器身份、请求租约和断线收敛。任何网页或窗口都不能仅凭自报 `executor_id` 获得高权限结果提交能力。

## 桌面 Shell API

pywebview 向前端暴露有限本机接口，包括窗口控制、原生文件/目录选择、路径显示或打开、托盘和更新相关动作。前端业务不应在各 feature 中直接读取 `window.pywebview`；应通过共享 desktop bridge 统一检测能力、处理失败和约束参数。

## 桌面启动和关闭

- 桌面壳选择后端端口并管理后端子进程。
- 前端开发服务可用时优先加载，否则使用 `dist`。
- 正常退出先经过未保存文档确认，再保存窗口尺寸、准备后台任务退出，最后销毁窗口；窗口销毁后的桌面收尾负责停止网关、后端和释放安装锁。收起到托盘不停止下载。
- 窗口尺寸属于尽力保存的偏好：原生尺寸查询与 HTTP 保存合计最多等待 2500 毫秒，超时中止请求并继续关闭/收起；迟到的尺寸查询不再触发保存。这一时限不作用于文档和会话。
- 桌面壳使用本次启动的后端实例 ID 和租约 Token，直接向后端 `POST /api/desktop/exit-preparation`。接口停止接受新的市场操作，取消未进入提交阶段的任务，返回真实剩余任务数。壳每 100 毫秒查询，单次本地请求最多等待 8 秒；文件提交没有强杀期限，窗口保留并显示正在退出，直到提交完成或回滚。
- 准备退出或销毁窗口失败时保留窗口，尝试通过 `DELETE /api/desktop/exit-preparation` 恢复接收新任务；已经取消的下载不会自动重试。后端不可达时明确显示退出失败，可重试退出。启动租约凭据不进入前端。
- 后端通用退出任务表只维护可取消/提交中的生命周期，业务结果仍由各市场拥有。线程任务必须结束后才能清理临时目录，避免取消协程却留下线程继续写入。该约定适用于正常退出，不能保证强制结束进程或断电时的文件完整性。
- 每个清理动作都应独立保护，前一项失败不能跳过后续资源释放。

## 性能面板与采样

状态栏显示天策进程树的 CPU 和内存汇总，性能页显示当前软件与本机整体占用，不保存或绘制历史曲线。页面沿用四个统计页的统一紧凑尺寸。

前端仅在性能页展开时每 5 秒请求一次，其余可见状态每 15 秒更新状态栏，窗口页面隐藏时停止定时请求，恢复可见后按采样间隔恢复；请求串行，没有逐帧动画或额外图表库。桌面壳用锁与 5 秒快照缓存合并重复请求，仅追踪自身及子进程，读取 CPU、RSS 和全机汇总内存，不扫描全机进程的路径、命令行或环境，不查询进程名称，不增加硬件传感器或 GPU 轮询。

`psutil.cpu_percent(interval=None)` 的系统基线按调用线程保存，不适合 pywebview 不同桥接线程间直接复用。采样器改为保存 CPU 原始时间差分基线；初次无基线时 CPU 返回空值，界面显示待取数符号。Windows 的 interrupt/dpc 和 Linux 的 guest 字段不重复计入总时间。

会话存储通过后端 `GET /api/workspace/storage` 单独按需统计，不能接入桌面壳的 CPU 采样器。服务从统一项目目录取得所有项目集已登记的根路径，去重后只枚举其 `.Tiance`；累计文件逻辑大小，不读取正文或打开会话数据库，不创建/升级数据库，不计安装程序与工作区文档。数据库分项包括 `tiance.db` 及 WAL/SHM/journal，其他文件单独汇总。

存储统计只在性能页可见时请求，前后端均保留五分钟缓存；收起和隐藏停止前端定时请求，没有后台持续扫描。后端互斥合并并发请求，枚举最多 50,000 项、每步检查两秒时间预算；不跟随符号链接和 Windows 重解析点。达到预算或存在无法读取/跳过的项目时返回 `complete=false`，界面用 ≥ 和简短提示显示已统计的下限，不把部分结果冒充总量。时间预算在文件系统调用之间检查，不是操作系统 I/O 的强制超时。CPU、内存和存储统计都不写用量账本或会话库。

## 信任边界

回环地址不是身份认证。正式运行必须把前端页面、当前后端实例和 Shell API 绑定到同一次启动，不能只信任 `localhost`、`file://` 或某个固定开发端口。

HTTP CORS 不保护 WebSocket。WebSocket、client tool claim/result、供应商配置和本机文件接口需要自己的会话身份与来源校验。
