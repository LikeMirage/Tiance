# 前端能力桥与桌面壳

## client tool 链路

有些能力依赖实时界面状态，例如打开标签、显示会话或读取当前编辑器选择。模型仍发起标准工具调用，后端创建 `client_tool_request`，前端按预先登记的能力名执行并提交结果。

```mermaid
sequenceDiagram
    participant M as 模型
    participant B as 后端工具循环
    participant F as 前端能力桥
    participant E as 已登记执行器
    M->>B: tool call
    B->>F: request_id + name + arguments
    F->>E: 参数校验后执行
    E-->>F: structured result
    F-->>B: claim / submit result
    B-->>M: 正式 tool result
```

能力名不是任意 JavaScript 函数名。前端注册表拒绝重复能力，未登记能力失败。项目归属必须来自工具调用上下文；当前可见项目只能影响纯 UI 展示，不能作为业务写入的兜底身份。

## 生命周期

后端维护等待请求、领取和结果提交。前端用单飞表避免同一进程内重放造成重复执行。取消等待不等于回滚已经完成的文件、会话或界面动作。

- 前端工具等待的总期限来自该工具 `.tool/tool.json` 的 `runtime.timeout_seconds`。创建请求时固定截止时间，派发、领取、执行和结果回传共用该预算；领取、心跳及重连均不重置预算。用户停止会话也会终止等待。
- 原来“创建后 30 秒未领取或未续约即失败”的处理已移除。当前领取应答使用 `lease_duration_seconds=30`，前端按其三分之一间隔查询请求是否仍有效；该字段仅用于通信节奏，不再表示所有权或工具请求的到期时间。短暂断线、页面暂停不能据此判定工具失败或把动作交给另一个执行端。状态查询串行，失败不堆积请求。
- 领取通信失败在工具预算内按 1、2、4、5 秒间隔串行重试，后续维持 5 秒间隔；没有重试次数导致的额外截止期限。明确的鉴权/参数错误不自动反复请求，恢复后同一请求重放仍可重新领取。失败 Promise 不永久占住单飞条目，也不产生旁路未处理 rejection。
- `attempt_id` 是同一次领取的幂等标识，记录在当前页面的执行证据中，后端只在首次领取时保存并原样回传；它不是权限凭据。领取成功但响应丢失时，同一个标识可以继续确认领取。新的标识不能覆盖已登记标识，也不能据此接管已执行的动作。
- 页面执行证据分为 `claiming`、`executing`、`completed`。恢复尚未开始的同一次领取可以继续执行；已完成结果只重传结果；已开始但结果未知的动作保留“执行中断、无法确认”的失败语义，不自动重做。调用方项目、会话、工具能力仍沿原有合同传递，没有按具体工具名称设置特殊超时。

多执行器身份仍须遵守网关及会话授权边界；领取标识仅用于幂等和防重复，不能替代身份认证。任何网页或窗口都不能仅凭自报 `executor_id` 获得高权限结果提交能力。

## 桌面 Shell API

pywebview 向前端暴露有限本机接口，包括窗口控制、原生文件/目录选择、路径显示或打开、托盘和更新相关动作。前端业务不应在各 feature 中直接读取 `window.pywebview`；应通过共享 desktop bridge 统一检测能力、处理失败和约束参数。

## 桌面启动和关闭

- 桌面壳选择后端端口并管理后端子进程。
- 前端开发服务可用时优先加载，否则使用 `dist`。
- 正常退出先经过未保存文档确认，再保存窗口尺寸、准备后台任务退出，最后销毁窗口；窗口销毁后的桌面收尾负责停止网关、后端和释放安装锁。收起到托盘不停止下载。
- `close_window(request_id)` 只接受当前关闭请求的 ID；移除了无 ID 直接关闭路径。前端请求退出先发起握手，不能绕过未保存检查直接销毁窗口。
- 标题栏关闭、Windows 原生关闭和托盘退出由壳的 `WindowCloseCoordinator` 合并为一个关闭请求，用请求 ID 区分迟到的回应。托盘传递明确的退出意图，直接进入未保存内容检查，不再询问是否收起到托盘。
- 前端仅在关闭请求存在时每秒回报等待/保存状态，调用串行，取消或收起后停止；正常使用没有这项轮询。组件卸载停止回报，但不冒充用户取消。壳连续 5 秒未收到回应或 JS 分发报错时，使用 Win32 原生确认框询问继续等待或退出。通知发出不代表已处理；检测计时独立于 JS 调用线程，即使 `evaluate_js` 不返回也能提示，且不会堆积分发线程。
- 原生兜底确认退出后仍调用相同的后端退出准备接口。后台收尾超过 30 秒只提示继续等待或强制退出，不自动强杀，也不重复启动收尾；后台失败提供重试、明确的强制退出和保留窗口。只有用户明确选择强制退出才绕过未完成收尾，提示说明可能丢失数据或中断文件写入。正常完成与原生提示并发时，等待提示结束再销毁窗口。此兜底不承诺原生 UI 线程或整个进程失效时仍可响应。
- 窗口尺寸属于尽力保存的偏好：原生尺寸查询与 HTTP 保存合计最多等待 2500 毫秒，超时中止请求并继续关闭/收起；迟到的尺寸查询不再触发保存。这一时限不作用于文档和会话。
- 桌面壳使用本次启动的后端实例 ID 和租约 Token，直接向后端 `POST /api/desktop/exit-preparation`。统一退出协调器停止接收新会话和市场操作，取消会话、记忆压缩等后台任务，并等待消息收尾、文件提交或回滚及审计记录保存完成。接口立即返回是否就绪和待完成工作计数；重复查询不会重复取消正在收尾的任务。壳每 100 毫秒查询，单次本地请求最多等待 8 秒；业务保存没有这一强杀期限，窗口保留并显示正在退出，全部成功后才销毁窗口。窗口销毁后的 8 秒后端进程退出保护仅作用于后续进程退出。
- 准备退出或销毁窗口失败时保留窗口，尝试通过 `DELETE /api/desktop/exit-preparation` 恢复接收新任务；恢复前先等待在途收尾结束，不能在旧任务尚未停止时重新开放入口。已经取消的生成和下载不会自动重启。审计保存失败保留待保存缓冲，再次退出可重试写入。后端不可达时明确显示退出失败，可重试退出。启动租约凭据不进入前端。
- 后端通用退出任务表只维护可取消/提交中的生命周期，业务结果仍由各市场拥有。线程任务必须结束后才能清理临时目录，避免取消协程却留下线程继续写入。该约定适用于正常退出，不能保证强制结束进程或断电时的文件完整性。
- 每个清理动作都应独立保护，前一项失败不能跳过后续资源释放。

## 性能面板与采样

状态栏显示天策进程树的 CPU 和内存汇总，性能页显示当前软件与本机整体占用，不保存或绘制历史曲线。页面沿用四个统计页的统一紧凑尺寸。

前端仅在性能页展开时每 5 秒请求一次，其余可见状态每 15 秒更新状态栏，窗口页面隐藏时停止定时请求，恢复可见后按采样间隔恢复；请求串行，没有逐帧动画或额外图表库。桌面壳用锁与 5 秒快照缓存合并重复请求，仅追踪自身及子进程，读取 CPU、RSS 和全机汇总内存，不扫描全机进程的路径、命令行或环境，不查询进程名称，不增加硬件传感器或 GPU 轮询。

`psutil.cpu_percent(interval=None)` 的系统基线按调用线程保存，不适合 pywebview 不同桥接线程间直接复用。采样器改为保存 CPU 原始时间差分基线；初次无基线时 CPU 返回空值，界面显示待取数符号。Windows 的 interrupt/dpc 和 Linux 的 guest 字段不重复计入总时间。

会话存储通过后端 `GET /api/workspace/storage` 单独按需统计，不能接入桌面壳的 CPU 采样器。服务从统一项目目录取得所有项目集已登记的根路径，去重后只枚举其 `.Tiance`；累计文件逻辑大小，不读取正文或打开会话数据库，不创建/升级数据库，不计安装程序与工作区文档。数据库分项包括 `tiance.db` 及 WAL/SHM/journal，其他文件单独汇总。

存储统计只在性能页可见时请求，前后端均保留五分钟缓存；收起和隐藏停止前端定时请求，没有后台持续扫描。后端互斥合并并发请求，枚举最多 50,000 项、每步检查两秒时间预算；不跟随符号链接和 Windows 重解析点。达到预算或存在无法读取/跳过的项目时返回 `complete=false`，界面用 ≥ 和简短提示显示已统计的下限，不把部分结果冒充总量。时间预算在文件系统调用之间检查，不是操作系统 I/O 的强制超时。CPU、内存和存储统计都不写用量账本或会话库。

## 信任边界

回环地址不是身份认证。正式运行必须把前端页面、当前后端实例和 Shell API 绑定到同一次启动，不能只信任 `localhost`、`file://` 或某个固定开发端口。

HTTP CORS 不保护 WebSocket。WebSocket、client tool claim/result、供应商配置和本机文件接口需要自己的会话身份与来源校验。

## 访问身份与登录生命周期

访问密码仍是单密码控制，不引入账户、角色或 JWT。网关是浏览器登录状态的唯一来源，登录记录只保存在当前网关进程内，重启失效，不写会话数据库。

- “桌面客户端免输密码”只认可当前桌面实例的随机凭证，不再依据回环 IP 放行。壳每次启动生成不同的桌面与内部后端凭证，通过匿名 stdin 管道把二者登记给网关；原生 WebView2 CookieManager 写入桌面专用 HttpOnly Cookie，JavaScript 桥只返回是否完成。授予身份的桥接方法校验当前文档的确切应用地址，不能因 `allow_remote_shell_api` 开启而向外部页面授予身份。
- 桌面身份绑定启动实例；开启桌面免密时不使用浏览器空闲计时。关闭免密、修改密码或撤销登录都会切断旧连接，仍被信任的桌面实例可重新连接。免密不适用于同一电脑的普通浏览器或本机反向代理。
- 浏览器随机令牌只存 HttpOnly、SameSite=Strict Cookie，HTTPS 时附加 Secure；服务端只保存令牌摘要。一小时无用户活动失效，最长登录有效期为 24 小时。输入、点击、触摸、滚轮经节流上报活动；不监听程序自动滚动也能触发的 scroll 事件。AI 输出、工具执行、API 轮询与心跳不刷新活动时间。
- 每个页面每 30 秒续约一次存活状态，页面租约为 90 秒。页面关闭发送 `session/leave`；最后一个页面离开后保留 15 秒刷新重连宽限。各标签页使用独立页面 ID，关闭一个不影响另一个；迟到心跳不能复活已关闭页面。浏览器崩溃、断网或后台冻结时由租约到期收回，不依赖关闭事件一定送达。网关每 15 秒清理过期记录，每次请求也检查到期，因此连接清理最多再延迟一个清理周期。
- 登出、空闲/绝对期限到期、修改密码和撤销登录均通过同一会话撤销信号终止其代理请求、WebSocket 与事件流。前端收到未登录响应后回到密码页。登录失效不是 AI 暂停指令：已提交给 conversation run manager 的任务继续执行，重新登录可恢复订阅。
- 网关仅接受 IP/localhost Host；自定义反向代理域名由 `TIANCE_GATEWAY_ALLOWED_HOSTS` 逗号列表显式声明。TLS 在代理终止时，另用 `TIANCE_GATEWAY_ALLOWED_ORIGINS` 声明准确的 HTTPS Origin。普通请求头、User-Agent 和转发头均不能授予桌面身份。HTTPS 仍需在外部访问设置或可信代理上配置。
- Python 后端继续仅监听回环，同时验证独立的 `X-Tiance-Gateway-Token`。网关覆盖外部同名头并移除浏览器 Cookie；后端在进入业务路由前移除内部凭证。健康检查和静态前端公开，注册表 app/domain/tools/host_capabilities.py 中精确列出的专用 POST 入口使用独立的短期能力授权（Python 工具在 runtime.host_capabilities 声明，不按工具名绑定），不能豁免整个路由前缀。关闭准备请求由壳携带内部凭证和原有实例租约双重校验。
- 网关健康接口声明 `security_protocol=2`，桌面壳拒绝启动旧网关，防止仅更新源码而实际程序仍使用旧鉴权方式。修改网关源码后必须重建并验证 `runtime/gateway/TianceRemoteGateway.exe`。

开发时若设置 `TIANCE_SHELL_MANAGE_BACKEND=false`，独立后端和壳必须显式配置相同的 `TIANCE_GATEWAY_INTERNAL_TOKEN`（64 位随机十六进制）；缺失时拒绝启动，不能降级为无鉴权后端。正常桌面启动自动生成并传递，不需要用户配置。

## 文档预览与供应商切换（2026-10-30）

- PPT 加载只解析文档、确定页码和初始缩放；统一绘制入口随后渲染主预览。`ready` 状态改变不触发同页重绘，初次适配缩放完成前不先绘制一次。缩略图有自己的绘制目标，不算主预览重复绘制。
- PDF 模块加载共享在途 Promise，失败即清除该 Promise，允许再次打开或点击“重试”。模块初始化错误还可能被浏览器自身缓存；仅模块加载失败时提供“重新加载界面”，并提示先保存未保存内容。Chromium 实测：HTTP 503 后第二次动态导入可重新请求；模块顶层异常则同页两次均失败，刷新后重新请求成功。文件损坏与模块加载失败分开显示。
- 模型集的供应商选择与打开先经过通用未保存文档检查，用户确认后再同步供应商和项目身份；取消后两者都保留。后台同步按已选项目识别供应商，不用供应商状态变化绕过检查切换项目。
