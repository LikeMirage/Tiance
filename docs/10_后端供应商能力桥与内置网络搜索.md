# 后端供应商能力桥与内置网络搜索

> 实现基线：2026-08-02。这里的“后端桥”准确名称是后端供应商能力桥。

一个普通 Python 工具有时需要使用当前会话供应商已经提供的能力，例如 OpenAI、Anthropic 或 Gemini 的内置网络搜索。最直接的做法是让工具读取供应商配置和 API Key，但这会把密钥、数据库结构和每家协议都泄漏给工具。

天策在工具进程与供应商客户端之间增加一条受控能力桥：工具只得到一次性授权和统一接口，后端保留密钥并选择具体协议适配器。

## 为什么不是把 API Key 传给工具

如果工具直接拿到密钥：

- 任意工具都可能读取或记录它；
- 工具必须理解供应商配置文件；
- 每个工具都要重复处理 OpenAI、Anthropic、Gemini 差异；
- 密钥轮询、用量统计和错误转换会分散；
- 工具市场中的第三方代码获得了不必要的权限。

能力桥只授予“本次工具调用可以使用当前会话的网络搜索”，而不是“这个进程可以读取当前供应商所有秘密”。

## 授权模型

后端在启动已登记的工具时生成高强度随机授权，绑定：

- 能力类型，目前为 `web_search`；
- 工具调用与工具身份；
- 当前项目、会话；
- 当前供应商和模型；
- 创建与过期时间。

授权只存在后端内存。工具把短期 Bearer 凭据提交给本机能力接口；后端验证能力和有效期后，从绑定上下文解析真实供应商配置与加密密钥。工具结束后授权被撤销，过期授权也会清理。

## 通用网络搜索工具

内置 `network_search` 是普通 Python 工具。对模型而言，它只有稳定的查询合同；对工具而言，它只调用天策本机的统一网络搜索能力；真正的供应商请求由后端适配器完成。

当前适配器覆盖 OpenAI Responses、Anthropic 和 Gemini 的供应商内置搜索形式。后端负责：

- 选择供应商与模型；
- 构造各协议需要的搜索工具或请求；
- 使用本地加密凭据；
- 解析答案与来源；
- 记录独立的 `provider_web_search` 用量；
- 把上游错误转换成稳定错误。

因此工具不需要出现 `if provider == ...`，新增协议也优先扩展后端适配器，而不是复制一份新搜索工具。

## 三条桥的分工

天策当前常被混称为“桥”的结构实际有三条：

| 桥 | 连接什么 | 解决什么 |
| --- | --- | --- |
| Python 工具运行桥 | 后端工具循环 ↔ 独立 Python 进程 | 隔离运行、JSON 输入输出、独立依赖 |
| 前端能力桥 | 后端工具循环 ↔ 前端白名单执行器 | 使用标签页、会话、界面等实时前端状态 |
| 后端供应商能力桥 | 工具进程 ↔ 后端供应商适配层 | 不暴露密钥地复用当前供应商能力 |

三者都使用标准工具调用结果，但信任边界完全不同，不应合并成一个“万能桥”。

## 安全边界

- 能力必须由后端明确授予，不能由工具参数自称；
- 授权绑定当前调用，不能长期保存；
- 工具不能指定另一个供应商或窃取另一个会话身份；
- API Key 不进入工具参数、标准输出或日志；
- 供应商能力接口只暴露已经定义的动作，不是通用 HTTP 代理。

## 当前边界

供应商搜索能力目前包括当前会话模型的 `web_search` 和独立的 `deepseek_web`。新增供应商原生能力应逐项建立能力枚举、请求合同和适配器，不能把接口放宽成任意上游调用。

## DeepSeek 独立搜索与网页读取

`deepseek_official_web_search` 使用官方 `/v1/tools/search` 和 `/v1/tools/fetch`，不再调用 Responses 或任何对话模型。工具保持普通 Python 工具的注册、权限、执行与结果回传机制。

凭据只有两条路径：工具 `program/config.json` 的 `deepseek.api_key` 非空时直接使用；未填写时调用 `deepseek_web` 能力桥。桥在后端读取模型集中 ID 为 `deepseek` 的供应商，要求供应商已启用，并复用现有密钥解密和加权轮询。它不依赖当前会话选择的模型、协议或生成地址，不向工具返回密钥。只有该工具获得的专用短期授权能调用 `/llm/provider-capabilities/deepseek-web`；原来的 `network_search` 授权不能调用此接口，反向也不允许。

JSON Key 已配置但请求失败时不改用模型集。没有可用凭据时，工具返回配置位置并提示在模型集配置，或用 `action=configure` 写入本工具 JSON；传空字符串可清除 JSON Key。`config_info` 只读取配置，不发起网络请求或回显密钥。环境变量凭据、旧 Responses 配置和旧响应解析均已移除，不保留兼容分支。

`search` 支持 `query`、`count`（1～50，默认 10）、`need_content`、`ori_question`、`localization`；`fetch` 接收单个 `url`。只传调用者明确提供的定位信息。错误保留上游 HTTP 状态与实际使用的凭据来源；搜索空结果正常返回，Fetch 的 HTTP 成功不代表内容是有效资料，仍需 AI 阅读核实。没有模型用量的 Search/Fetch 不登记为对话模型 Token 消耗。

返回策略按字段及本次文本总量控制：默认单个 `snippet`、`summary`、`content` 超过 4,000 字符，或加入该字段会超过本次 12,000 字符文本预算时，将该字段完整保存到工作区 `web_searches/deepseek_<时间>_<随机标识>/`。阈值位于 JSON 的 `output.inline_field_chars`、`output.inline_text_budget`，统计不包含标题、网址等元数据。短字段保持原文直接返回；长字段由 `text_files` 给出相对路径、UTF-8 字节数、字符数和行数。存在落盘字段时另存索引 JSON，索引只引用长文本文件，不再复制正文；全为短内容或空搜索结果时不创建文件。保留上游原文，不裁剪、不伪造完整网页或修复上游排版。
