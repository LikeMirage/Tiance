# 测试包制作与验证流程

测试包用于验证已经完成并提交的源码改动。它拥有与正式完整包相同的运行结构，但不代表新版本发布。

## 与正式发布包的区别

- 测试包从当前源码提交 `HEAD` 提取，不要求创建 Git 标签。
- 测试包沿用 `system/version.json` 中的当前版本，不修改任何版本配置。
- 测试包不生成在线更新包、更新清单或 GitHub Release。
- 测试包只包含 Git 已跟踪的运行文件，不带入工作区中的项目、会话、数据库、日志、密钥、工具依赖缓存和其他未提交状态。
- 只有用户明确确认正式发布后，才升级版本号并执行正式发布流程。

## 制作前准备

前端有改动时，先完成构建：

```powershell
cd 2_ReactWeb
pnpm check
pnpm build
cd ..
```

完成必要验证并提交本次源码改动。测试包只读取当前提交，不读取尚未提交的代码，这样测试结果可以准确对应到一个源码提交。

## 生成测试包

在仓库根目录运行：

```powershell
./scripts/package-test.ps1
```

输出目录为：

```text
测试包/Tiance/
```

直接运行其中的 `Tiance.exe` 即可测试。脚本会输出源码提交号和程序版本，程序版本保持不变。

如果 `测试包/Tiance` 已存在，脚本会停止并提示先关闭、移走旧测试包，不会覆盖一个可能正在运行或保存测试数据的目录。

## 正式发布边界

测试通过不等于已经发布。只有用户明确决定发布后，才执行以下动作：

1. 确定新版本号并修改正式版本配置。
2. 完成发布验证和发布提交。
3. 创建不可移动的正式 Git 标签。
4. 运行 `scripts/package-release.ps1` 生成完整发布包、差分更新包和 `update.json`。
5. 推送源码、标签和 GitHub Release 附件。
