# 记忆压缩：从连续退化到累计快照

> 实现基线：2026-08-23。本文把历史方案、当前实现和待恢复方向分开记录。

长会话的难题不是“把旧消息删短一点”。真正的问题是：上下文窗口有限、模型缓存依赖稳定前缀、工具调用不能被拆断，而用户又希望数十万乃至数百万 Token 的工作仍能继续。

天策的压缩机制经历了两条很不同的路线。第一条追求像人类记忆一样连续退化；第二条追求更低成本、更稳定地继续当前工作。现在运行的是第二条，但第一条并没有失去价值。

## 最初方案：无限层级的连续退化

最初设计只有两个操作：

1. **一级压缩**：把超过保护尾部的原始历史压成结构化事项。
2. **次级合并**：把已经成功的低层摘要再次合并。

次级合并也可以继续作用于自己的结果，因此无需预先规定“最多三级”或“五级记忆”。信息会随着时间和使用频率逐渐降低分辨率：近期保留原文，中期保留细节摘要，远期只留下稳定结论、关键词、重要性和来源编号。

这个方案最有魅力的地方，是摘要并不等于删除。原始记录仍然存在，摘要项可以携带来源消息、关键词和身份，模型需要时再通过工具向下追溯，恢复更高分辨率的材料。

它接近一种可检索的记忆树，但代价也明显：压缩次数多、成本高，层级合并与检索合同复杂，任何一次错误合并都可能把失真继续传到更高层。

## 缓存实验带来的修正

天策随后对 OpenAI Responses 风格的上下文缓存做了分支复用实验。结果显示，缓存更接近一条正在增长的活动链，而不是永久保存所有历史分叉的树：

- 在当前尾部继续追加，通常最容易复用；
- 从当前边界派生一次分支，可能命中；
- 主线继续增长后再回到很早的旧节点，可能完全失去命中；
- 即使字符串前缀相同，只要消息边界或序列化结构不同，也不能保证复用。

因此，缓存只能是优化条件，不能成为会话正确性的前提。为了命中缓存而制造大量短分支，也可能让多条活跃链互相竞争。

## 当前方案：累计摘要快照

当前实现采用“累计摘要 + 原始保护尾部”：

1. 统计真实请求上下文；供应商未返回准确用量时才使用本地估算。
2. 达到阈值后，从最早的可压缩消息组开始选择材料。
3. 工具调用与工具结果被视为不可拆分的原子组。
4. 最近一段历史按 Token 预算保留原文。
5. 系统创建一个可见的记忆压缩功能会话，让指定模型生成新的完整累计摘要。
6. 只有压缩结果成功提交后，新摘要才替换请求中的旧摘要与已覆盖历史；失败时保留原上下文。

新的摘要不是只总结“本次新增部分”，而是把旧累计摘要和新增历史合并成下一份完整快照。它包含事项列表与交接总结，并明确保留目标、决定、失败原因、验证结果、路径、数值、禁止项和未完成工作。

长期记忆变更通知有独立标记。压缩提示词要求这些通知块逐字、按序保留，不得概括或吞掉，从而避免会话压缩后失去“模型为何知道某项新背景”的证据。

## 全局记忆的人工管理与事件日志

全局记忆的权威事实是 `Data/memory/global_memory.jsonl` 中按真实提交顺序追加的事件。AI 的 `manage_memory` 工具和设定集中的人工管理看板共用同一个记忆管理服务与同一种 `add`、`update`、`delete` 事件，不直接覆盖当前结果，也不建立第二份看板数据。

设定集看板提供当前记忆、已删除和变更日志三个投影。删除只追加删除事件：该记忆从此不再进入模型上下文，但删除前的内容、关键词、变更依据、来源和全部事件仍可重放并查看。完整日志还显示每次事件的变更前与变更后内容；最后成功追加的更新决定当前结果，事件时间只用于展示，不反过来改变事件顺序。

人工编辑采用明确保存。输入过程不会自动产生正式事件，新增、更新和删除都需要用户提交变更依据。保存成功后也不会遍历或重写所有会话：每条旧会话继续使用自己的基线和全局事件游标，在下一次用户消息发送前取得游标后的变化；已经开始的模型请求不会在半轮中途被改变，新会话则直接以当前有效记忆建立基线。

## 为什么当前方案更适合运行

- 每次请求只需要一份有效累计摘要，不需要装配多层摘要树；
- 成功后替换、失败不破坏原文，边界容易验证；
- 保留近期原始上下文，降低正在进行任务的细节损失；
- 功能会话可见，可以检查用的模型、提示词、工具调用和结果；
- 与供应商前缀缓存更容易共存。

它牺牲的是更细腻的长期退化层次和按摘要节点反向检索的能力。

## 值得恢复的方向：双模式共存

连续退化不应简单替换当前累计快照。更合理的未来是让两者承担不同目标：

- **工作连续模式**：继续使用累计快照，优先成本、稳定和当前任务接续。
- **高保真记忆模式**：保留多层摘要、来源映射与反向检索，适合研究、写作、长期策划等需要回望演进过程的项目。

恢复这条路线前至少要先确定：摘要节点身份、来源图、成功替换事务、检索工具合同、层级合并触发条件，以及如何避免与项目/全局长期记忆重复。它是明确的后续设计方向，不是当前版本已经隐藏实现的功能。
