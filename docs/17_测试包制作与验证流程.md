# 测试包制作与验证流程

测试包用于验证已经完成并提交的源码改动。它拥有与正式完整包相同的运行结构，但不代表新版本发布。

## 与正式发布包的区别

- 测试包默认从当前源码提交 `HEAD` 提取；需要验证尚未提交的指定改动时，可以显式传入受限工作区路径生成临时 Git 树快照，不要求创建 Git 标签。
- 测试包沿用 `system/version.json` 中的当前版本，不修改任何版本配置。
- 测试包不生成在线更新包、更新清单或 GitHub Release。
- 默认模式只包含 Git 已跟踪的运行文件。工作区快照模式也只接收用户明确列出的允许路径，不会扫描整个工作区；项目、会话和数据库不在允许范围内。传入公开预置集合路径前仍须检查其中是否存在未被 `.gitignore` 排除的本地配置或密钥，路径白名单不能代替内容审查。
- 只有用户明确确认正式发布后，才升级版本号并执行正式发布流程。

## 制作前准备

前端有改动时，先完成构建：

```powershell
cd 2_ReactWeb
pnpm check
pnpm build
cd ..
```

正式回归优先先提交本次源码改动，使测试结果准确对应到一个源码提交。若当前目的只是把少量尚未提交的源码或最新前端 `dist` 提取成可运行测试包，可以使用下方的显式工作区快照模式；它不会改版本号，也不会修改真实 Git 暂存区。

## 生成测试包

在仓库根目录运行：

```powershell
./scripts/package-test.ps1
```

需要包含尚未提交的指定路径时，例如只测试后端和最新前端产物：

```powershell
./scripts/package-test.ps1 -WorkingTreePaths @(
  "1_PythonServer",
  "2_ReactWeb/dist"
)
```

允许范围由脚本白名单限制，包括后端、前端 `dist`、桌面壳、公开预置集合、本地化文本、供应商公开定义、`system`、启动文件和许可证。不能传入 `Data/projects`、运行数据库或任意外部目录。脚本通过临时 Git 索引生成快照，不会执行 `git add` 污染真实暂存区；但它会收集所选允许路径中的未提交内容，因此选择 `Data/tools`、`Data/providers` 等集合前必须先检查密钥和本地配置，优先传入具体项目目录而不是整个集合。

输出目录为：

```text
测试包/Tiance/
```

直接运行其中的 `Tiance.exe` 即可测试。脚本会输出源码提交号和程序版本；使用工作区快照时还会输出临时树摘要。程序版本始终保持不变。

如果 `测试包/Tiance` 已存在，脚本会停止并提示先关闭、移走旧测试包，不会覆盖一个可能正在运行或保存测试数据的目录。

## 正式发布边界

测试通过不等于已经发布。只有用户明确决定发布后，才执行以下动作：

1. 确定新版本号并修改正式版本配置。
2. 完成发布验证和发布提交。
3. 创建不可移动的正式 Git 标签。
4. 运行 `scripts/package-release.ps1` 生成完整发布包、差分更新包和 `update.json`。
5. 推送源码、标签和 GitHub Release 附件。
