# 工具参数权限与执行确认机制

> 实现基线：v0.3.23。

天策的工具权限建立在真实工具调用边界上。工具开发者在输入参数合同中声明能力类型，工具项目在独立配置文件中决定不同作用范围是禁止、询问还是允许，执行器在任何工具真正运行前统一检查。前端按钮只提交一次性决定，不承担权限判断本身。

## 一、权威数据

每个顶层输入参数的权限类型保存在 `.tool/input.schema.json` 的 `permission_type` 字段中。没有该字段或字段非法时，运行时按 `unknown` 处理；明确配置为 `none` 时，该参数无需检查。权限元数据不会发送给模型供应商。

每个工具的处理策略保存在 `.tool/permissions.json`：

```json
{
  "version": 1,
  "fallback": "ask",
  "policies": {
    "filesystem_write": {
      "workspace_inside": "allow",
      "workspace_outside": "ask",
      "unresolved": "ask"
    }
  }
}
```

参数 Schema 决定“这是什么能力”，权限策略决定“这种能力在当前范围如何处理”。权限看板只是这两个文件的编辑界面，不另存一份前端状态。

## 二、权限类型

| 分类 | 权限类型 | 用途 |
| --- | --- | --- |
| 通用 | `none` | 普通内容或配置参数，无需检查 |
| 文件与系统 | `filesystem_read` | 读取或定位本机文件、目录 |
| 文件与系统 | `filesystem_write` | 创建、覆盖或修改本机文件、目录 |
| 文件与系统 | `filesystem_delete` | 删除本机文件、目录或其中内容 |
| 文件与系统 | `program_execute` | 执行命令、脚本或本机程序 |
| 文件与系统 | `process_control` | 查询、等待、终止或管理进程 |
| 文件与系统 | `runtime_modify` | 安装依赖或改变运行环境 |
| 网络与外部 | `network_access` | 向本机、局域网或互联网目标发起请求 |
| 网络与外部 | `credential_use` | 使用密钥、令牌或其他身份凭据 |
| 网络与外部 | `external_data_read` | 读取外部服务、账户或仓库数据 |
| 网络与外部 | `external_data_modify` | 创建、修改或删除外部服务数据 |
| 天策应用 | `tiance_data_read` | 读取项目、会话、记忆或设置 |
| 天策应用 | `tiance_data_write` | 创建或修改天策内部数据 |
| 天策应用 | `tiance_data_delete` | 删除天策项目、会话、记忆或设置 |
| 天策应用 | `ui_control` | 打开、切换或关闭界面内容 |

`unknown` 是运行时权限点，不是写入参数 Schema 的正式类型。用户在参数看板选择“未知权限”时会删除 `permission_type`，调用该参数后按权限策略中的 `unknown.all` 处理。

## 三、作用范围和默认策略

当前正式默认值如下：

| 权限点 | 范围 | 默认处理 |
| --- | --- | --- |
| 未知权限 | 所有调用 | 询问 |
| 文件系统读取 | 工作区内、工作区外、无法识别 | 允许 |
| 文件系统写入 | 工作区内 / 工作区外 / 无法识别 | 允许 / 询问 / 询问 |
| 文件系统删除 | 工作区内 / 工作区外 / 无法识别 | 询问 / 禁止 / 禁止 |
| 程序执行 | 工作区程序 / 系统程序 / 无法识别 | 允许 / 询问 / 询问 |
| 进程控制、运行环境修改、凭据使用、外部数据变更 | 所有调用 | 询问 |
| 网络访问 | 本机 / 局域网 / 互联网 / 无法识别 | 允许 / 询问 / 允许 / 询问 |
| 外部数据读取 | 所有调用 | 允许 |
| 天策数据读取 | 当前项目、其他项目、全局数据、无法识别 | 允许 |
| 天策数据写入 | 当前项目 / 其他项目 / 全局数据 / 无法识别 | 允许 / 询问 / 询问 / 询问 |
| 天策数据删除 | 当前项目 / 其他项目 / 全局数据 / 无法识别 | 询问 / 询问 / 询问 / 禁止 |
| 界面控制 | 所有调用 | 允许 |

`fallback` 只补齐该工具配置文件中缺失的权限点或单元格。整个文件缺失或损坏时，运行时加载产品默认策略，不会把错误配置当作全部允许。

## 四、一次调用怎样决策

执行器只检查本次实际传入的参数，不因 Schema 中存在某个未传参数而触发权限。每个参数先解析能力和作用范围，再读取对应策略。数组或对象中的多个值会展开为多个事实；一次调用包含多个参数时按以下严格顺序聚合：

```text
禁止 > 询问 > 允许
```

任何事实为禁止，整次调用直接拒绝且不运行工具；没有禁止但存在询问时，工具进入等待确认；全部允许或所有参数均为 `none` 时直接执行。

## 五、动态工具和前端工具

权限执行器接收的是调用图，不按工具名称写特殊分支。普通调用只有一个节点；动态调用同时包含 `execute_dynamic_tool` 包装节点和实际目标节点。每个节点使用自己的参数 Schema 和权限策略，最后统一聚合，因此目标工具不能借包装层绕过权限，包装层也不能代替目标工具授权。

client 工具同样先检查权限，再创建前端能力桥请求。禁止或用户拒绝时，前端执行器不会收到调用。

## 六、一次性询问的生命周期

需要询问时，后端生成唯一请求 ID，通过会话流发送等待事件。前端在对应工具调用行显示允许和拒绝按钮：

- 允许：只放行当前这次调用；
- 拒绝：当前调用返回标准工具失败，不执行真实工具；
- 重复、过期或已结束请求：后端拒绝再次提交；
- 会话停止：取消仍在等待的请求；
- 连接恢复：只重放仍然有效且未处理的请求。

当前没有“永久允许”或“永久禁止”按钮。长期策略只在工具项目的权限配置看板中修改，避免一次调用确认和持久配置混成同一事实。

会话另有 `tool_approval_mode` 自动审批方式，它只处理权限聚合结果中的“询问”：

- `follow_tool_policy`：保留一次性询问，由用户允许或拒绝；
- `auto_allow_ask`：自动允许本次询问项，不弹出确认；
- 工具策略明确返回“禁止”时，两种会话模式都不能放行。

新会话当前默认使用 `auto_allow_ask`。角色的 `tools.json` 可以保存同名字段；角色应用到会话时一次性写入会话配置，之后运行时只读取会话自身设置。自动允许复用批准后的工具执行路径，并在审计总账中记录 `tool.permission_requested` 与 `tool.permission_decided`，其中决定来源为 `session_auto_allow`；用户点击产生的决定来源为 `user`。允许决定不是正式对话消息，正常工具结果仍按原合同保存；拒绝则仍返回标准工具失败结果。

## 七、市场和本地配置边界

市场工具包必须包含参数权限分类和一份默认 `permissions.json`。首次安装采用发布者默认策略；更新已有工具时，市场更新参数 Schema、程序和其他标准合同，但保留用户本地 `permissions.json`。工具版本变化不能静默重置用户已经选择的权限。
