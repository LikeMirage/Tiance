# 一切都是项目和会话

> 实现基线：2026-08-02。本文描述当前代码已经形成的结构，不把后续设想写成已完成功能。

天策最重要的简化，不是少做几种界面，而是尽量少发明几种“存在方式”。角色、主题、工具、供应商、知识和经验看起来差异很大，但它们首先都是一个能被打开、浏览、对话和继续加工的文件夹项目；自动命名、记忆压缩和长期记忆管理看起来像后台任务，但它们首先都是可追溯的会话。

这使系统可以不断增加能力，却不必为每个新名词复制一套存储、会话和文件浏览器。

## 两个基础单元

### 项目：工作的空间边界

一个项目提供稳定身份、根目录、分类、排序和生命周期。项目内部可以放普通业务文件，也可以拥有 `.Tiance/` 工作目录，用来保存会话、分支图、压缩记录、长期记忆投递状态和工具调用记录。

项目集的 `catalog.json` 只记录项目身份、路径、分类和排序。真实内容仍然在项目文件夹里。这样做有两个好处：索引损坏可以依据文件夹重新校正；移动或分享项目时，业务文件和 AI 工作历史仍然保持在同一个可理解的范围内。

### 会话：工作的时间边界

会话不只是聊天记录。它同时承担：

- 人和模型的连续交流；
- AI 创建的子任务；
- 从历史节点派生的分支；
- 自动命名、记忆压缩、项目记忆管理、全局记忆管理等功能任务；
- 模型、角色、工具、生成参数和运行状态的绑定；
- 工具调用、用量和最终产物的可追溯链。

AI 协作因此不需要隐藏的“代理运行表”。一个 AI 创建另一个 AI，本质是创建一个带父子关系的会话；发送任务，本质是向目标会话写入用户消息并启动它；等待结果，本质是等待那个会话完成本轮回复。

## 各种“集”为什么仍然有价值

统一底座不等于所有东西只剩一个文件浏览器。每种集仍然需要自己的入口和看板：

| 集 | 共享的项目能力 | 自己增加的语义 |
| --- | --- | --- |
| 普通项目 | 文件、会话、分支、记忆、市场 | 不强加专用格式 |
| 角色集 | 同上 | 角色配置与默认会话种子 |
| 主题集 | 同上 | 主题清单、预览、应用与资源 |
| 工具集 | 同上 | `.tool` 合同、启用状态与运行时 |
| 供应商集 | 同上 | 协议、模型、凭据和适配规则 |
| 知识集、经验集 | 同上 | 当前主要是专用入口；更深业务仍在发展 |

区别不在于“是不是项目”，而在于项目里哪些文件具有专门含义、界面要把哪些操作放到最前面。底层共性由项目承担，领域差异由专用看板和配置承担。

## 扁平，不等于没有边界

天策所谓扁平，是业务对象不再藏进多层数据库和服务内部。用户能看到文件夹、JSON、会话和产物，也能把它们移动、备份或共享。但以下边界仍然存在：

- `catalog.json` 管本机分类与排序，不替代项目内容；
- 专用配置只由对应业务解释，普通文件浏览器不会猜它的含义；
- `.Tiance/` 是项目内 AI 工作状态，不应混同用户正文；
- API Key 等秘密可以属于供应商项目，但必须加密保存；
- 派生索引可以重建，不能反过来成为唯一事实来源。

## 为什么这适合 AI 应用

AI 的基础动作仍然是一问一答，但连续工作需要空间和时间：项目提供空间，会话提供时间。工具、角色、记忆和分支不是另一种宇宙，而是改变“这次会话在这个项目中如何工作”的条件。

当基础单元稳定以后，新能力通常只需要回答三个问题：

1. 它的真实文件放在哪个项目里？
2. 它通过哪一种会话参与工作？
3. 它额外需要哪个专用看板或运行合同？

这就是“一切都是项目和会话”的真实含义：不是把差异抹掉，而是让差异建立在少量稳定关系上。

## 当前边界

这套统一仍在收口。部分前端页面还保留较多集类型分支，供应商和工具也有确实不能由普通项目服务代替的运行逻辑。正确方向不是强行删除这些差异，而是继续把共同的项目总览、会话看板、文件树、市场外壳和状态管理收回共享层，把真正领域专有的部分留在各自模块。

## 2026-08-13：`.Tiance` 会话状态曾改用 SQLite

早期实现把会话索引、消息、分支、压缩记录、注入预览和项目记忆拆成多份 JSON/JSONL 文件。数据直观，但同一次会话操作需要连续改写多个文件；后台任务、界面读取和消息追加并行时，容易出现短暂不一致、重复刷新、锁文件竞争和只完成一半的写入。

当时项目内这些运行状态统一保存在 `.Tiance/tiance.db`，并启用 SQLite WAL。它解决了共享总表频繁改写、半写入和并发读取问题，但也让用户无法直接检查、同步和恢复单个会话。

必须保留为真实文件的内容仍留在文件系统中：会话图片等附件位于 `.Tiance/conversations/sessions/{session_id}/attachments/`，而普通业务文件继续留在项目根目录。SQLite 只收拢天策内部运行状态，不会把用户正文、源码和交付文件锁进数据库。

## 2026-08-17：恢复透明文件事实源

当前会话事实改为按会话独立保存：每个会话拥有自己的 `session.json`、`state.json`、`branch.json`、`messages.jsonl` 和功能记录。SQLite 仍保留，但只位于 `.Tiance/cache/conversation-index.db`，用于消息分页和定位；删除后会从权威文件自动重建，模型完整上下文不从缓存读取。

当前早期阶段不保留旧 `.Tiance/tiance.db` 的自动迁移程序，新工作区直接建立文件事实源。完整结构和验证方法见 `docs/21_新会话数据结构说明及测试方法.md`。
