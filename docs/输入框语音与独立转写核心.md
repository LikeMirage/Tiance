# 输入框语音与独立转写核心

实现日期：2026-11-13。

## 使用与数据归属

输入框底栏的麦克风按钮启动录音。录音期间，输入区显示停止按钮和音波；停止后显示识别状态。识别结果写回草稿，由用户编辑、发送，不自动提交模型。

录音界面使用主题强调色绘制光环和停止按钮，底部波形读取本次麦克风流的实时频谱；没有声音时保持低幅度。可视化不另外申请麦克风、不回放声音、不管理录音轨道。更新限制为约 30 帧/秒，页面隐藏时不绘制，退出录音界面释放音频分析资源；支持紧凑输入区及系统减少动画设置。

- 开始录音时绑定项目 ID、会话 ID、原草稿和光标位置。切换会话、项目或项目集会结束原会话录音，识别结果仍写回原会话。
- 开始录音时输入框有焦点，且原草稿未被其他操作改动，转写文字插入光标后；失焦时追加到末尾。若识别期间草稿已经变化，追加到新草稿末尾，避免替换用户的新输入。
- 回填复用已有会话草稿保存队列和加载版本保护。不会因旧的会话详情响应晚到而覆盖转写结果。
- 录音采用浏览器 MediaRecorder，需要麦克风权限，以及本机地址或 HTTPS 安全上下文。远程明文 HTTP 不具备浏览器录音能力。
- Windows 桌面壳接管本机天策页面的 WebView2 麦克风授权请求，在输入框内显示“允许使用麦克风／取消”，允许后原地开始录音。授权结果由 WebView2 保存；取消不记为永久拒绝。普通浏览器仍使用浏览器自己的权限提示。
- 授权等待期间取消或切换会话，会拒绝该次请求；页面导航、刷新或渲染器失效也撤销待授权请求。只接管天策可信页面、同源请求的麦克风权限，不自动授予权限，不改变摄像头或外部页面的权限处理。
- 音频上传云端识别，采用现有音频转写核心的服务。语音输入不是离线识别。

录音存放在原项目的会话目录：

```text
<项目>/.Tiance/conversations/sessions/<会话 ID>/recordings/<录音 ID>/
  source.webm（或 source.ogg、source.m4a、source.wav）
  recording.json
  result.json
  recording_asr_*/（原始响应、分段记录、完整 JSON 和 TXT）
```

路径通过现有项目工作区解析器确定，遵循该项目实际的 `.Tiance` 存储位置。不会存到独立工具目录，也不会作为用户附件自动加入上下文。浏览器录音可能没有容器时长，识别前逐帧整理为临时 16 kHz 单声道 WAV；识别完成或取消后清理这份中间文件，原录音保留。

## 取消、失败和关闭

- 用户取消后，前端立即标记此次录音取消，任何迟到结果都不能回填。
- 若正在保存已结束的录音，允许原始文件保存完整，但不启动识别；保存完成后将记录置为取消。
- 若已经开始识别，后端终止本次独立工作进程，停止本地转换、上传、等待和结果处理；并等待进程退出，原录音保留。
- 上游未提供已提交识别任务的撤销接口，因此不能承诺取消已在云端排队的任务；本地不再等待、使用其结果。
- 正常退出使用现有后端任务关闭机制。强制退出、浏览器关闭或断电不能保证尚未上传的录音保存；已落盘文件保留，重启后中断任务标记为失败，不自动重新上传或回填旧结果。
- 错误显示在录音区域，不清空已有草稿。网络错误时也尝试取消后端任务，不能仅因前端请求失败就假定后台已经停止。

## 独立性与同步规则

后端拥有 `1_PythonServer/app/services/speech/jianying_asr/` 和所需 `vendor/silk/`；独立工具拥有自己的 `program/jianying_asr/` 和 `program/vendor/`。两份核心直接随各自产品发放，运行时不互相导入，不查找工具 ID，不调用工具执行器，也不依赖工具是否存在、启用或被用户修改。

核心入口 `engine.run(..., budget=..., client_factory=...)` 不读取宿主配置：

- 工具的 `runner.py` 读取自身 `tool.json` 的 `runtime.timeout_seconds`。
- 后端的 `worker.py` 使用后端配置 `SPEECH_RECOGNITION_TIMEOUT_SECONDS`，默认 3600 秒，限制一次识别任务的总执行时间，不是录音时长上限。网络代理、连接和读取超时复用天策网络设置。
- 后端使用独立工作进程承载解码、签名、上传、轮询和长音频分段，防止同步计算阻塞后端事件循环，并提供可终止的任务边界。
- 分段协调器调用宿主提供的 `client_factory(budget, tdid=...)`，宿主必须接收并透传同一任务的设备标识。初版后端适配遗漏 `tdid`，导致首次构造客户端即发生 `TypeError`，尚未请求云端。回归测试只替换远端 HTTP 响应，实际执行录音转换、核心分段、客户端构造、上传协议和结果导出，避免用模拟核心掩盖接口不匹配。
- PyAV 通过后端依赖安装；独立工具继续使用其自带媒体模块，两边均为 16.0.1 系列。

修改任一核心后必须同步并验证：

```powershell
python scripts/sync-speech-core.py --from-backend
# 如果先修改工具核心，则改用 --from-tool；两个方向不能同时使用。
python scripts/sync-speech-core.py --check
python -m pytest 1_PythonServer/tests/test_speech_jobs.py 1_PythonServer/tests/test_speech_worker.py
python -m pytest Data/tools/092dcd37-8d51-467d-b607-5a6441dd989a/tests
```

校验覆盖协议、签名、媒体处理、分段合并、导出、SILK 解码文件，要求逐字节一致。宿主适配层分别测试，不能为了省事让后端动态加载已安装工具。协议来源及第三方许可保留在各自 `NOTICE`、`LICENSE` 和供应商文件目录。

## 主要入口

- 后端 HTTP：`1_PythonServer/app/api/routes/project/speech.py`；沿用项目接口的认证和关闭准入。
- 前端 HTTP：`conversationSpeech.ts` 使用 `/api/projects/{project_id}/conversations/{session_id}/recordings`。网络配置提供服务器地址，不自动添加 `/api`。初版漏写此前缀导致保存录音时返回 404，尚未进入云端识别；已补全，并通过前端真实 HTTP 请求及后端注册路由测试覆盖创建、上传、识别、查询和取消。
- 后端任务生命周期：`1_PythonServer/app/services/speech/jobs.py`。
- 前端录音、切换和取消：`2_ReactWeb/src/features/ai-panel/model/speechCapture.ts`、`useSpeechInput.ts`。
- 原会话草稿回填：`useConversationSessions.ts` 的 `insertSpeechDraft`。
- 录音界面：`ChatSpeechRecording.tsx`；颜色来自主题变量，支持系统减少动画设置。
- 桌面麦克风授权：`3_PyWebView/app/microphone_permission.py` 和 `2_ReactWeb/src/features/desktop-shell/model/desktopMicrophone.ts`。原生事件采用 deferral 等待输入框答复，不能在 WebView2 UI 线程同步等待前端执行。

授权验证：`3_PyWebView/tests/test_microphone_permission.py`、`2_ReactWeb/tests/desktop-microphone.test.mjs`、`speech-input.test.mjs`。另已使用隔离的 WebView2 配置目录和虚拟麦克风验证取消、重新允许及授权复用；未录取真实麦克风音频。
