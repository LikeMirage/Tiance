# 工具系统与标准工具的制作边界

> 实现基线：2026-08-02。

天策没有把工具理解成后端代码里的一组函数。一个工具是普通文件夹：它自己声明身份、参数、输出、案例、程序、资源和依赖；系统负责发现、授权、校验、运行和把结果送回模型。

这种边界让内置工具和用户工具走同一条路，也让在线工具市场可以流通完整能力，而不是流通一条必须修改主程序的代码片段。

## GUI 工具合同（2026-09-22）

五个 GUI 工具使用静态加载、串行执行；本轮不改变通用动态工具调度。单次批量动作也是顺序执行，不代表多套鼠标键盘可以并发。

原版锁定提示层（2026-09-23）：每个显示器使用逐像素透明的柔光边框和顶部小提示条，工作区域完全透明，不再叠加深色遮罩、网格或中央大字。提示随显示缩放调整；仍不抢焦点，并排除在工具截图之外。输入拦截、Esc 退出和生命周期规则不变。

- 所有 GUI 查看和操作（包括 gui_inspect list_windows）必须先等待 gui_runtime start 成功锁定。锁定后 list_windows 可直接调用；gui_inspect start 另用于建立截图会话和坐标依据，不能代替锁定。
- 网格 x/y 接受任意小数，最终取整到物理屏幕像素；直接 click、scroll 不要求 preview。
- 叠加层（2026-09-23）：从未叠加的原图裁剪并放大后才绘制；网格边界只画一次，固定为最终输出的 1 像素。编号字体 9～16 像素，含底色内边距后不得超过最小格宽的 45% 或格高的 30%；无法容纳时整张视图省略编号，返回 `overlay.labels_hidden_reason=cells_too_small`。编号从左上 1 开始逐行先右后下，隐藏也不改变格号或坐标。
- `overlay` 支持 `labels+lines`（start 默认）、`lines`、`none`。zoom 未指定时继承父 View 的请求模式；新截图继承根视图模式，局部 View 的调整不改变根设置。返回 requested/effective、字号、线宽及原始像素尺寸、显示倍率；8 倍时提示无新增细节，不禁止递归。
- `gui_inspect view` 使用最新 `frame_id` 和已有 `view_id`，返回根层、父层或任意已有分支；可同时切换 overlay，不截图、不改变 Frame/网格/坐标、不使预览失效。返回 `parent_view_id` 和完整 `available_view_ids`，不同叠加模式保留独立图片路径，避免改写历史工具结果引用的图片。
- `start target=window` 配合 hwnd 或 window_title 选择窗口，先激活再截取该窗口所在屏幕区域，后续递归流程相同；不是后台窗口抓取，遮挡会进入画面。屏幕选择仅改变截图区域，输入锁仍覆盖整个桌面。
- zoom 的 cell_id 与 cell_ids 二选一，多格必须恰好组成完整矩形。新 View 可以另设网格，不改变 Frame、原坐标映射或预览。放大不增加原图细节。refresh 与动作后保留根网格设置；refresh 也可明确重新指定设置。
- cell_id/cell_ids 按输入 View 的已有网格选择；zoom 的 grid_rows/grid_cols/grid_mode/grid_target_cells 仅设置放大后新 View 的网格。例如来源为 2×2 时只能选 1 至 4，输出指定 3×3 不会让来源增加 5 至 9 格。
- View 属于创建它的 Frame。操作或刷新产生新 Frame 时最初只有 root，不继承旧 Frame 的放大 View；需要放大时从新 Frame 的 root 重新 zoom。VIEW_NOT_FOUND 返回 frame_id、requested_view_id、available_view_ids 和恢复说明；CELL_NOT_FOUND 返回来源 view_id、grid、requested_cell_id 和完整 available_cell_ids，不自动修正目标或代替执行。
- gui_inspect elements 依据明确的最新 frame_id，通过 Windows UIAutomation 返回控件身份、名称、矩形、焦点、可用状态、支持模式及可读取的非密码值。每个 Frame 保存一次完整控件快照，offset/limit 分页并返回 total、complete、next_offset；需要新状态时 refresh。读取或设置控件每次最长 10 秒，超时明确失败。
- 鼠标和键盘可引用 element_id。执行前重新检查窗口、控件身份与状态；键盘输入还检查焦点。没有控件引用时继续使用截图与原焦点校验。set_value 只操作可写、非密码 ValuePattern；超时导致结果无法确认时标记 unknown，不自动重试。
- expected_elements 检查调用方指定的收件人名称、输入内容、选中状态等条件；批量每步还可指定 postconditions。失败返回 completed_actions、从 0 开始的 failed_action_index 和执行状态，并停止余下动作。坐标批量逐步对比依赖区域，界面变化后应重新观察。
- drag（直接执行、预览执行及批量步骤）不做操作前像素比较，忽略 change_check_scope/change_threshold_percent。Frame 在工具运行数据中记录窗口层叠顺序、HWND、进程/线程身份和矩形；拖动核对起点对应窗口未移动、缩放、消失或被遮挡，并用原生命中检查确认，移到起点后按下鼠标前再次核验。窗口矩形归属与原生命中不一致时明确拒绝，不猜测目标。仍要求当前锁、最新 Frame、有效坐标和未取消；完成后返回新截图，操作后画面差异仅作结果信息。批量混有其他坐标动作时保留整批初始像素检查；前一步改变窗口位置后必须重新观察再拖动。窗口状态核验不能消除检查与输入之间的全部竞态。
- gui_runtime start 的 idle_timeout_seconds 默认 120 秒且公开可配置；修改需 stop 后重新 start。无动作执行且无成功 GUI 请求超过该时长自动释放，status 不续期。Esc、动作连接断开都会取消排队操作；旧会话与预览不能继续使用。
- 启动前用临时文件验证共享状态目录的读写、替换与删除权限；运行器发布 starting 状态并回读验证后才安装钩子。不修改 ACL，不在权限异常时切换到第二个锁目录。状态读写或进程查询被拒绝时明确返回状态未知，不能据此删除状态文件或启动第二个锁。
- start 必须核对运行器身份、active、input_mode 与 hooks_installed；完成确认前调用进程断开或 10 秒确认时限到达，运行器自行释放。新建运行器启动失败时，通过本次创建的进程句柄终止并最多等待 3 秒，随后才清理归属已核实的状态文件。错误结果报告 pid、已知 port、process_alive、released；不能确认时 active=null，不宣称已解锁。已有其他运行器不通过 PID 猜测终止。gui_runtime 单次调用时限为 30 秒，包含互斥等待、启动核查和失败回收。
- gui_inspect activate 只接受 action 和 gui_session_id，恢复并激活原窗口目标；核对 HWND 对应进程，确认前台并重新截图。成功后生成新 Frame、保持根网格设置；旧坐标、控件引用及预览失效。screen 目标需要先 start 指定窗口；窗口消失、身份变化或激活失败明确报错。
- 在天策会话中通过既有 TIANCE_API_BASE_URL 连接只读运行状态接口 /llm/chat/completions/stream/status，每秒核对所属生成任务身份，连接超时 2 秒。任务结束、取消、换代或后端失联均释放；独立测试未提供 API 地址时仅使用空闲、Esc 与连接释放机制。

UIAutomation 能识别哪些控件取决于目标应用的可访问性支持。身份检查不能消除检查与动作之间的全部竞态；缺少可访问性信息时仍需截图，不预先假定微信全部控件可识别。

## 标准目录

```text
工具文件夹/
  .tool/
    tool.json
    input.schema.json
    output.schema.json
    examples.json
    permissions.json
  program/
  assets/
  dependencies/
```

`Data/tools/catalog.json` 只负责本地分类、排序和工具项目身份；真正的调用合同在工具自己的 `.tool/` 中。`program`、`assets` 和 `dependencies` 是否需要，取决于运行类型。

## 五份核心合同

### `tool.json`

声明稳定调用名、显示名称、用途、关键词、启用状态、是否动态加载、调用间是否允许并发，以及运行类型、入口和超时。`execution.parallel` 是必填布尔值；缺失或类型错误的工具不能注册。制作新工具时默认明确写为 `true`，确有共享写入或顺序依赖时改为 `false`，程序不会用隐藏默认值替工具做决定。调用名是工具身份的一部分，显示名称只是面向用户的标签。重命名显示名称不会把更新变成一个新工具；修改稳定调用名则会影响会话配置和市场身份检查。

### `input.schema.json`

这是模型看到的参数合同，也是执行前校验和参数权限分类的合同。每个顶层参数可以用 `permission_type` 声明权限类型；未声明时按“未知权限”处理，明确声明为 `none` 时不参与权限检查。这个字段只供天策运行时使用，发送给模型供应商前会从 JSON Schema 中移除。

权限类型描述参数代表的直接能力，例如 `filesystem_read`、`filesystem_write`、`program_execute`、`network_access` 或 `tiance_data_write`。一个参数只配置一个权限类型；一次调用包含多个参数时，执行器会汇总所有参数并采用最严格结果。程序支持而 Schema 不写、Schema 声明而程序不实现，都会产生难以追踪的失败。复杂工具应该用清晰对象、枚举和必填项表达边界，不能要求模型凭参数名猜规则。

### `output.schema.json`

描述工具真实返回。普通结果通常包含 `ok`、`summary`、`data`、`warnings` 和错误信息。图片等富媒体不应塞成长 Base64 或路径文字，而应通过标准内容块和受控资源 URI 返回。

### `examples.json`

案例负责解释典型业务组合，不是第二份参数表。它可以告诉模型怎样创建一份报告、怎样安全覆盖文件、怎样先检查再编辑，但不能引入程序并不支持的动作。

### `permissions.json`

记录该工具各权限点在不同作用范围内的处理方式：`deny` 表示禁止，`ask` 表示本次调用需要用户确认，`allow` 表示允许。权限配置属于工具项目的本地用户设置；市场首次安装会提供发布者默认值，已有工具更新时保留用户当前配置。

当前默认策略以低打扰和明确越界为目标：文件、外部数据和天策数据读取允许；工作区内文件写入与工作区程序执行允许；工作区外写入、系统程序、凭据、运行环境修改、外部数据变更和跨范围天策写入询问；工作区外或无法识别位置的文件删除禁止。完整范围和执行规则见[《工具参数权限与执行确认机制》](26_工具参数权限与执行确认机制.md)。

## 三种运行位置，一套工具体系

| 类型 | 运行位置 | 适用能力 |
| --- | --- | --- |
| `python` | 后端启动的独立工具进程 | 文件、文档、网络、计算等普通工具 |
| `client` | 前端登记的白名单执行器 | 标签页、界面导航、会话交互等浏览器状态能力 |
| `internal` | 后端内部 | 动态工具执行等基础设施 |

Python 工具通过标准输入接收 JSON，通过标准输出返回 JSON。client 工具仍使用同样的模型工具调用，只是执行请求被桥接到前端。internal 工具不是第三方扩展入口。

## 两层启用与执行校验

工具能否执行同时取决于：

1. 工具自己的 `state.enabled`；
2. 当前会话是否启用了它。

执行时还会校验调用名、输入 Schema、运行入口和工作目录。模型即使凭空生成了一个未启用工具名，也不能绕过这些检查。

## 模型上下文与富媒体

工具需要知道当前模型是否能看图时，不应自行查询供应商数据库或按模型名称猜测。Python 工具从 `TIANCE_MODEL_CONTEXT` 获得标准化的供应商、模型和输入模态；client 工具从请求事件得到同一语义。

本地图片通过 `tiance-project:///` 或受控的 `tiance-local:///` 引用。后端重新校验文件、类型、签名和模型模态，再把资源交给模型。普通文本里写一个路径不会自动获得读取权限。

## 注入字符怎样计算

工具看板的“注入字符”不是只统计界面顶部可见的摘要，也不是 Token 数。标准加载工具按最终交给模型的工具定义计算字符数，内容包括：

- 调用名称；
- 工具说明；
- 所有已启用案例的标题；
- 明确开启“正文注入”的案例正文；
- 完整 `input.schema.json`，包括每个参数名、类型、说明、枚举、必填关系和嵌套对象结构。

统计时会把上述内容组装成与模型工具定义一致的紧凑 JSON，再计算字符串长度。界面上的参数卡片默认折叠，所以视觉上看起来不多，完整 Schema 实际可能占绝大部分。

以 2026-08-13 的 Word 制作编辑工具为例：清单摘要 314 字符，启用案例标题合计 68 字符，开启正文注入的案例内容 239 字符，组装后的完整说明为 645 字符；输入 Schema 的紧凑 JSON 为 7,788 字符，最终工具定义合计 8,553 字符。因此数字较大主要来自严格而复杂的输入参数合同，不是摘要被重复注入。

动态加载工具的看板数字使用轻量目录说明计算，只包含调用名、显示名称、摘要和案例标题；详细参数在模型实际选择该工具后再读取，两种数字不能直接横向比较。

## 制作一个标准 Python 工具

最小流程是：

1. 选择稳定、唯一的调用名和项目身份；
2. 写 `tool.json`，明确入口、超时、启用和动态策略；
3. 先设计输入/输出 Schema，并为每个顶层输入参数标注 `permission_type`；
4. 程序只从标准输入读取一次 JSON，只向标准输出写最终 JSON；日志写标准错误，不能污染协议；
5. 所有文件路径、外部响应和用户输入都在工具内部校验；
6. 写少量但真实的案例；
7. 在权限看板确认各作用范围的默认策略，再使用工具体检和针对性测试验证配置、入口、Schema 与返回结果；
8. 如需发布，再增加市场 `manifest.json` 和包完整性信息。

工具调用历史保存在目标工具项目自己的 `.Tiance/tool-calls/records.jsonl`。注册表只是扫描文件得到的进程内派生状态，不是第二份工具数据库。

## 不应由工具做的事

- 直接读取天策供应商密钥或内部数据库；
- 依赖前端隐藏按钮作为权限；
- 发明某个工具专属的聊天消息格式；
- 把绝对路径、巨量 Base64 或密钥写进普通结果；
- 要求聊天后端按具体工具名解释业务结果。

真正需要使用当前供应商能力时，应走后端供应商能力桥；真正需要前端状态时，应做 client 工具并显式登记。
