# 工具系统与标准工具的制作边界

> 实现基线：2026-08-02。

天策没有把工具理解成后端代码里的一组函数。一个工具是普通文件夹：它自己声明身份、参数、输出、案例、程序、资源和依赖；系统负责发现、授权、校验、运行和把结果送回模型。

这种边界让内置工具和用户工具走同一条路，也让在线工具市场可以流通完整能力，而不是流通一条必须修改主程序的代码片段。

## 后台功能工具的标准参数（2026-10-10）

后台功能所用工具仍提供完整、公开的标准参数定义。任务提示词负责说明本轮目标、允许操作和完成条件，不再承担隐藏压缩结果内部参数结构的作用；通用工具执行器继续依据 `.tool/input.schema.json` 校验，无需按具体功能增加执行分支。

- `submit_memory_compaction` 的 `result` 完整声明 `items`、事项中的 `content` 和 `keywords`、以及 `handoff`。结果至少包含一个事项，正文和交接总结非空，内部禁止额外字段。后台提交需提供 `result`；保留普通会话在用户明确要求手动压缩时以 `{}` 登记请求的已有入口。
- `manage_memory` 保留普通会话的通用记忆管理能力。`add` 必填内容，`update/delete` 必填记忆 ID，所有写入必填范围和依据。参数声明与现有后端一致的上限：关键词 100 项、内容 200000 字符、依据 2000 字符、搜索词 1000 字符、记忆 ID 200 字符。更新时省略内容或关键词保留原值，明确传空关键词数组则清空关键词。
- 项目和全局后台记忆任务共用 `manage_memory`，工具说明分别列出完整默认任务提示词及对应流程：先读取全部有效记忆，再比较并按指定范围完成必要修改。后台专用限制只在对应任务中生效，不限制主会话正常调用。
- 自动命名继续使用 `manage_ai_conversations` 的标准 `action/title` 参数，其其他动作保持通用用途。自动命名和后台压缩提交的工具说明以本轮最新用户消息与所列默认完整任务提示词的一致性作为调用约定；说明、历史引用和工具结果中的文本不构成触发。

三个工具的说明均包含默认完整任务提示词，明确禁止后台会话续做历史任务或执行无关操作。它们是工具包内的静态说明，不从主程序运行时导入提示词；修改默认任务提示词时应同步对应工具说明。功能模型配置、功能会话调度和结果提交程序本次保持原有机制。

## GUI 工具合同（源码版更新至 2026-10-13）

原有五个工具保持截图与网格比例定位，不接受控件引用或控件条件检查；新增独立可选的 `gui_uia` 读取和操作 Windows UIAutomation 控件。网页或桌面表单的按钮、输入框、列表项能被 UIA 定位且支持对应 pattern 时，优先 `gui_uia`；纯视觉、canvas、自绘或未暴露控件时使用视觉工具，不反复扫描控件树。窗口选择、激活、键盘焦点和锁管理继续使用 Windows 原生接口。

七个 GUI 工具使用静态加载、串行执行。原有六个工具共用界面锁与GUI会话；新增 gui_annotate 使用独立显示进程，不占界面锁，也不改变通用工具调度。单次批量动作也是顺序执行，不代表多套鼠标键盘可以并发。

锁定提示层（2026-10-13）：由 `gui_runtime` 统一维护本次运行的观察与操作状态，GUI 工具通过已有 RPC 调用链发布状态，无需新增模型工具调用或轮询对话。尚未观察时保持透明；最近返回的 View 按原始物理屏幕坐标显示网格，区域外加半透明暗遮罩，子 View 内显示其新网格；顶部显示操作进度、Frame、层级（root 为第0层）及选区路径。屏幕格子过小时只画线，避免编号覆盖目标；这不改变发给模型的 PNG 网格。屏幕提示始终显示当前网格，不受截图的 `overlay=none` 影响。

观察状态复用 `gui_session_id/frame_id/view_id/parent_view_id/source_rect_absolute/grid/cells`，不按放大 PNG 的尺寸定位。`zoom/view` 更新当前区域，刷新或动作后的新截图回到 root；截图失效时移除旧网格并提示等待重新观察，关闭当前截图会话清除选区与光标。不同截图会话不串用观察区域；运行器退出清除全部内存状态，历史文件保持原有保留规则。`gui_runtime status` 的 `data.activity` 可查询最近观察摘要、动作阶段和指针位置，不返回完整格子列表，不续期。

鼠标预览使用橙色虚拟光标（未执行），实际输入成功发送后使用粉色光标；移动和拖动跟随发送位置，按下与松开改变标记。光标不额外移动系统鼠标，不触发输入；批量操作显示当前步骤，键盘与 UIA 显示动作阶段，不展示输入正文。UIA 控件调用不伪造鼠标点击；独立的 `gui_annotate` 不修改锁定观察状态。锁定层展示的是最近取得的视图及工具执行情况，不推断模型内部注意力。

RPC 线程发布快照，以合并的窗口消息通知显示线程，显示线程不等待动作执行锁。网格变化才更新全屏层；虚拟光标使用独立小图层，计时器仍只更新提示条。所有子层都位于已有排除截图的宿主窗口内，不抢焦点，不拦截工具点击，支持负坐标及跨屏裁剪；缩放只影响字体和光标外观，不改变物理定位。显示失败沿用运行器退出机制，释放输入锁。

锁定时长（2026-10-08）：顶部提示条右侧每秒显示本次锁定已经持续的时间，从输入钩子安装成功后计时；使用单调时钟，不随系统时间调整或空闲续期重置。格式随时长切换为 `59s`、`1m00s`、`1h00m00s`、`1d00h00m00s`，最大单位为天，`365d` 也不转换成年。多屏共用同一起点；每秒只更新小提示条，柔光边框保持静态；解锁时删除计时器，新锁从零开始。

源码版 GUI 的 Pillow 使用随软件提供的共享后端运行环境（runtime/python-packages/backend/py313/site-packages），不在 GUI 工具目录内重复保存 dependencies；沿用通用工具执行器提供的 Python 搜索路径。

- 原有六个工具的 GUI 查看和操作（包括 gui_inspect list_windows）必须先等待 gui_runtime start 成功锁定。锁定后 list_windows 可直接调用；gui_inspect start 另用于建立截图会话和坐标依据，不能代替锁定。
- GUI 操作期间收到用户新消息，表示用户已经解除锁定并暂停上一轮 AI 对话。若后续需要继续操作，必须重新调用 `gui_runtime start` 并等待成功，再用 `gui_inspect start` 建立新会话、重新观察；不沿用旧 `gui_session_id`、Frame、预览或控件引用。
- **最短持锁**：只在当前 GUI 操作及必要界面确认期间持锁。当前 GUI 阶段结束，或下一步不再需要 GUI 时，立即 `gui_runtime stop` 并核实释放；等待用户、失败或取消时也先解锁，不等整件任务结束或空闲超时。
- 收尾如需切换展示窗口，使用真实 `hwnd` 及 `gui_inspect` 的显式激活能力，最多尝试一次，随后立即 `gui_runtime stop`，不以切换成功作为解锁前提。解锁未确认时先核对锁状态，不宣称已释放。
- 等待用户操作前先解锁；用户完成后重新 `gui_runtime start`，成功后用 `gui_inspect start` 建立新会话、重新观察，不沿用旧 Frame、坐标、预览或控件引用。
- 网格 x/y 接受任意小数，最终取整到物理屏幕像素；直接 click、scroll 不要求 preview。
- 窗口清单包括无标题弹窗，提供 HWND、进程、窗口类和 owner_hwnd，不包含运行器自身的锁提示层；仍过滤不可见、最小化及 DWM cloaked 窗口。`list_windows` 按 `offset/limit` 分页，单页默认 100、最大 300，返回 total/complete/next_offset；每页重新枚举当前窗口，并非冻结快照。直接指定 HWND 不依赖枚举或标题，隐藏窗口仍返回 `WINDOW_CLOAKED`。
- 鼠标或键盘输入前，结合 `foreground_window` 和目标窗口的 owner 关系确认前台；不满足时先显式激活并使用返回的新 Frame，不沿用激活前坐标或预览。已有菜单、所属弹窗可用 `refresh` 观察，不反复激活主窗口收起菜单。
- 显式激活（`start target=window activate=true` 或 `action=activate`）的 `activation_timeout_ms` 默认 2000、范围 100～10000 毫秒；发出一次激活请求后每 50 毫秒检查目标是否成为前台，取消即停止等待，超时返回目标前后状态、实际前台、API 返回值和当前/输入桌面信息。只还原最小化窗口，不还原正常或最大化窗口；不修改系统前台锁设置。
- 截图可以保存未知焦点：Frame 的 `focus_window=null` 表示查询失败，`focus_error` 保存错误码；0 表示查询成功但没有焦点窗口。源码版（2026-10-03）键盘执行前核对截图中前台窗口的 HWND 和进程身份，并要求当前存在键盘焦点；同一窗口内换输入框不再因为子窗口句柄变化而失败。前台变成另一个窗口、窗口关闭或身份变化仍停止。批量键盘步骤沿用整批初始截图中的目标窗口，不自动跟随弹窗。
- 叠加层（源码版 2026-10-13）：多格先合并矩形并从未叠加的原图裁剪。`zoom_scale_percent` 是相对父视图中选区显示尺寸的请求倍率；计算期望宽高后，以 `min(1, 父图宽/期望宽, 父图高/期望高)` 统一约束两个方向，在分配图片内存前保证子View宽和高均不超过直接父View。后续子View继承父View实际显示比例，不继承被约束前的请求倍率。返回 `effective_zoom_scale_percent`（取整前实际应用的相对倍率）、`zoom_limited_by_parent` 和明确提示，避免把受限倍率报告为已完整应用。小选区仍可放大到父图范围，连续四分之一宽高选区的400%仍能保持画布大小；选择整行、整列或全部格子可能无法再扩大画布，需要缩小选区。最终尺寸确定后放大干净底图，再重画网格和编号；网格边界只画一次，固定为最终输出的 1 像素。编号字体 9～16 像素，优先缩小字号以控制占格比例，不再自动隐藏编号；只有 `overlay=lines/none` 关闭编号。`sampling.display_pixels_per_screen_pixel` 和 `display_pixels_per_screen_pixel_y` 分别返回实际横向、纵向显示倍率，图片取整不改变屏幕坐标映射。编号从左上 1 开始逐行先右后下。返回祖先/分支视图及切换叠加层保留该视图尺寸；新 Frame 从根视图重新开始倍率。PNG 是最终合成图，外部查看器继续缩放 PNG 仍会缩放其中的线条，不具备独立矢量叠加层。
- 父View尺寸上限只约束新建zoom子View；root仍使用实际截图尺寸，refresh/动作后从新root开始。它不是固定像素上限，也不改写已保存的历史View或会话附件；原始截图本身超出模型限制时仍需单独处理图片发送兼容性。
- `overlay` 支持 `labels+lines`（start 默认）、`lines`、`none`。zoom 未指定时继承父 View 的请求模式；新截图继承根视图模式，局部 View 的调整不改变根设置。返回 requested/effective、字号、线宽及原始像素尺寸、显示倍率；8 倍时提示无新增细节，不禁止递归。
- `gui_inspect view` 使用最新 `frame_id` 和已有 `view_id`，返回根层、父层或任意已有分支；可同时切换 overlay，不截图、不改变 Frame/网格/坐标、不使预览失效。返回 `parent_view_id` 和完整 `available_view_ids`，不同叠加模式保留独立图片路径，避免改写历史工具结果引用的图片。
- `start target=window` 配合 hwnd 或 window_title 选择窗口，默认 `activate=false`，直接截取当前屏幕上该窗口的矩形；refresh 同样不激活，避免观察时收起菜单或弹窗。只有显式 `activate=true` 才先激活。截图使用 `include_layered_windows=true`，包含矩形内可见的分层弹窗；自身锁提示层仍通过 Windows 截图排除标记隐藏。不是后台窗口抓取，其他应用遮挡会进入画面，矩形外的弹窗部分不会被包含。屏幕选择仅改变截图区域，输入锁仍覆盖整个桌面。
- 不激活前台的菜单等弹窗，可以按自身 HWND 建立窗口会话。动作检查允许“所选弹窗的 owner 链属于当前前台”；反方向不放行：主窗口会话遇到已成为前台的独立对话框，仍要求明确选择该对话框。不会仅凭进程相同放行或自动跟随弹窗。
- zoom 的 cell_id 与 cell_ids 二选一，多格必须恰好组成完整矩形。新 View 可以另设网格，不改变 Frame、原坐标映射或预览。放大不增加原图细节。refresh 与动作后保留根网格设置；refresh 也可明确重新指定设置。
- cell_id/cell_ids 按输入 View 的已有网格选择；zoom 的 grid_rows/grid_cols/grid_mode/grid_target_cells 仅设置放大后新 View 的网格。例如来源为 2×2 时只能选 1 至 4，输出指定 3×3 不会让来源增加 5 至 9 格。
- View 属于创建它的 Frame。操作或刷新产生新 Frame 时最初只有 root，不继承旧 Frame 的放大 View；需要放大时从新 Frame 的 root 重新 zoom。VIEW_NOT_FOUND 返回 frame_id、requested_view_id、available_view_ids 和恢复说明；CELL_NOT_FOUND 返回来源 view_id、grid、requested_cell_id 和完整 available_cell_ids，不自动修正目标或代替执行。
- 源码版（2026-10-03）鼠标、键盘、预览执行及批量步骤均不再以截图像素变化阻断动作，移除动作参数 `change_check_scope/change_threshold_percent`。保留锁归属、串行执行、取消、最新 Frame、坐标、窗口身份和尺寸检查；显式 `gui_inspect wait` 仍可按其公开阈值等待画面变化或稳定。动作前不再为像素检查截屏，整批末尾只截图一次。
- 批量任一步失败停止后续动作，错误详情返回 `completed_actions`、从 0 开始的 `failed_action_index`、`action_results` 与 `execution_status`。部分输入已经发出时使旧 Frame 失效，须重新观察，不重放已完成步骤。默认动作结果和窗口信息只报告事实，不宣称画面安全或业务已成功。
- `gui_mouse execute_preview` 只传 `action` 和 `preview_id` 两个字段；`screenshot_delay_seconds` 等动作参数在 `preview` 阶段设置并保存，执行阶段不得补传或覆盖。后续需要观察变化或稳定时使用 `gui_inspect wait`；`mode=stable` 只证明画面连续稳定，不能替代应用成功提示或业务结果确认。
- 动作输入完成与截图取得分开报告：`execution_status=completed` 后，即使窗口关闭、截图失败或截图等待期间退出，仍返回已执行；`observation_status=unavailable`、`observation_error` 和 `frame_id=null` 表示没有新截图。旧 Frame 已失效，须 refresh 或重新选择窗口。成功截图为 `observation_status=captured`。动作工具交付图片失败也保留原执行结果。预览编号仍只执行一次，重复调用返回历史结果。
- Frame 和动作结果返回 `foreground_window`（窗口句柄、进程身份、名称、矩形及是否存在）。动作后另返回 `foreground_changed`；失去前台或键盘目标改变的错误也附当前前台窗口信息。不会自动切换会话截图目标、自动激活弹窗或向新窗口继续输入。
- drag 仍核对截图时的起点窗口身份、位置和遮挡。Frame 在工具运行数据中记录窗口层叠顺序、HWND、进程/线程身份和矩形；拖动核对起点对应窗口未移动、缩放、消失或被遮挡，并用原生命中检查确认，移到起点后按下鼠标前再次核验。窗口矩形归属与原生命中不一致时明确拒绝；前一步改变窗口位置后必须重新观察再拖动。窗口状态核验不能消除检查与输入之间的全部竞态。
- gui_runtime start 的 idle_timeout_seconds 默认 120 秒且公开可配置；修改需 stop 后重新 start。无动作执行且无成功 GUI 请求超过该时长自动释放，status 不续期。Esc、动作连接断开都会取消排队操作；旧会话与预览不能继续使用。
- 启动前用临时文件验证共享状态目录的读写、替换与删除权限；运行器发布 starting 状态并回读验证后才安装钩子。不修改 ACL，不在权限异常时切换到第二个锁目录。状态读写或进程查询被拒绝时明确返回状态未知，不能据此删除状态文件或启动第二个锁。
- start 必须核对运行器身份、active、input_mode 与 hooks_installed；完成确认前调用进程断开或 10 秒确认时限到达，运行器自行释放。新建运行器启动失败时，通过本次创建的进程句柄终止并最多等待 3 秒，随后才清理归属已核实的状态文件。错误结果报告 pid、已知 port、process_alive、released；不能确认时 active=null，不宣称已解锁。已有其他运行器不通过 PID 猜测终止。gui_runtime 单次调用时限为 30 秒，包含互斥等待、启动核查和失败回收。
- gui_inspect activate 接受 action、gui_session_id 和可选 activation_timeout_ms，恢复并激活原窗口目标；核对 HWND 对应进程，确认前台并重新截图。成功后生成新 Frame、保持根网格设置；旧坐标及预览失效。screen 目标需要先 start 指定窗口；窗口消失、身份变化或激活失败明确报错。
- 在天策会话中通过既有 TIANCE_API_BASE_URL 连接只读运行状态接口 /llm/chat/completions/stream/status，每秒核对所属生成任务身份，连接超时 2 秒。任务结束、取消、换代或后端失联均释放；独立测试未提供 API 地址时仅使用空闲、Esc 与连接释放机制。

`gui_uia` 使用约定：

- 先锁定并建立 GUI 会话。`inspect` 在窗口会话读取所选窗口，在屏幕会话读取当前前台窗口；不激活目标。返回名称、automation_id、类型、矩形、支持的 patterns、可用/焦点/选择/展开状态，以及非密码输入框的值。`query` 按名称或 automation_id 包含匹配，不区分大小写。
- 一次读取完整控件树后保存在该 GUI 会话的运行数据目录 `uia/` 中，再执行 query 筛选和分页；`query/limit` 不缩减读取范围。`limit` 默认 100、范围 1～500，只控制单页传输，不截断已读取的树。用相同 query、snapshot_id 和 next_offset 翻页；返回 total/complete 明确是否读完。读取失败或超时不提交残缺快照。
- `element_id` 属于当前锁和 GUI 会话，不绑定 Frame。`read` 重新读取实时状态；`invoke/set_value/select/toggle/expand/collapse/focus` 仅执行控件支持的能力，每次重新核对窗口和控件身份。刷新截图不会直接作废引用；控件消失或身份改变明确失败。set_value 完整替换内容，上限 100000 字符，超出拒绝；密码内容不读取、密码控件不执行这些动作。
- 动作完成后沿用 GUI 会话的目标截图，保持 execution_status/observation_status 分离。`unknown` 表示请求已提交但无法确认结果，旧视觉 Frame 失效，须重新观察或 read，不能直接重试。完成只代表 UIA 调用返回，不保证应用业务已经完成。
- UIA 使用系统自带 PowerShell/.NET，在同一运行器内按需创建并复用一个工作进程，没有私有 Python 环境或新增依赖。首次初始化注册系统 Win32/MSAA 控件提供程序。`timeout_seconds` 默认 10、范围 1～60，包含进程启动和本次读取/动作；管道写入与等待响应都可取消，超时终止工作进程，不重试。错误响应已返回时保留工作进程。工具调用时限 100 秒，RPC 时限 130 秒；动作后的截图等待仍为公开参数 0～30 秒。释放运行器时终止子进程，最多等待 2 秒；清理失败不能绕过解锁。
- 快照属于可重新读取的运行数据，随 GUI 会话结束保留，但旧控件引用不可继续执行，不进入通用会话 Schema 或另建后端事实来源。控件提供程序未暴露的内容仍用视觉工具操作；UIA 不保证所有软件都提供可用控件。
- UIA 工作进程绑定运行器持有的 Windows Job；运行器被强制结束时，系统同时结束其 UIA 工作进程，避免解锁后遗留的进程继续执行。绑定失败则本次 UIA 明确失败，不提交动作。RPC 单次结果沿用 2MB 上限，超出明确报错，列表可减小单页 limit 后继续读取原快照；动作提交后发生通信故障返回 unknown，不声称未执行。



`gui_annotate` 使用约定（2026-10-09）：

- 通用工具包独立实现透明置顶层、后台进程、数据管理与全部关闭按钮；软件本体不识别工具名，不新增会话消息类型或标注业务接口。
- `draw` 批量追加网格框、箭头、文字，返回稳定 `annotation_id`；`update` 按ID部分修改，`delete` 删除指定ID，`list` 查看保存数据；`close` 关闭显示保留数据，`show` 明确重新显示。list/close/show 可省略 gui_session_id，作用于当前项目全部标注。
- 网格框提供当前来源View的 cell_ids；完整连续矩形合并外框，不规则选择逐格绘制。箭头提供 tail/head，文字提供 position/text（支持换行，位置是首行左上起点）。点位复用 cell_id、x、y，x向右、y从底向上，均为0～1；点可单独指定同一Frame中的 view_id。
- 默认红色、自动大小；显式 size 是最终屏幕物理像素。箭头size是杆宽，头长为4倍杆宽、头宽为4倍杆宽，短箭头头长最多为总长60%；文字size是字体像素，框选size是线宽。
- GUI目录不再随 close、解锁、Esc、空闲退出或来源任务结束删除。运行器退出将GUI会话标为closed，释放钩子和窗口；保留原始截图、View网格、映射与预览。键鼠和UIA操作仍须新建有效锁会话，保留文件不延长执行引用有效期。
- 每组标注保存于 `.Tiance/gui-temp/<gui_session_id>/annotations.json`；后台端点和互斥文件位于同一gui-temp根目录。工具通过本地认证RPC更新，窗口和所有写入在显示进程主线程串行处理，后续同项目会话可按GUI会话ID继续编辑。
- 标注进程不绑定AI生成任务生命周期、不安装输入钩子。工具返回或gui_runtime stop后继续显示；用户关闭按钮和close使用同一关闭逻辑，更新显示状态后退出进程。update不重新打开已关闭标注，需show；删除最后一个标注时退出显示。
- 工具升级后，draw/show/update/delete核对后台进程的runtime_version；旧进程通过认证close退出、保留标注与各组原显示状态，然后启动新进程处理请求。不带版本号的早期进程同样可迁移；关闭未确认时不启动第二个进程。list保持只读，close仍能直接关闭旧进程。
- 绘制层鼠标穿透、不抢焦点，小关闭按钮单独接收点击。两者使用系统截图排除能力；Windows 10 2004及以上支持，失败明确报错。效果图作为普通PNG资源返回，以保存的Frame为底图，`preview_basis=saved_frame`，不宣称是实时截图。
- 标注位置固定为保存画面的屏幕物理坐标，不自动跟随内容滚动、缩放或窗口移动。界面变更后重新观察，再update中的frame_id/view_id和位置。历史Frame可用于标注；不作为当前键鼠操作依据。
- 数据持续保留，关闭显示不删除历史图片或标注；本工具不自动清扫GUI目录。数据与进程均由工具包维护，不读取项目会话数据库或修改软件本体。

## 标准目录

```text
工具文件夹/
  .tool/
    tool.json
    input.schema.json
    output.schema.json
    examples.json
    permissions.json
  program/
  assets/
  dependencies/
```

`Data/tools/catalog.json` 只负责本地分类、排序和工具项目身份；真正的调用合同在工具自己的 `.tool/` 中。`program`、`assets` 和 `dependencies` 是否需要，取决于运行类型。

## 五份核心合同

### `tool.json`

声明稳定调用名、显示名称、用途、启用状态、是否动态加载、调用间是否允许并发，以及运行类型、入口和超时。`execution.parallel` 是必填布尔值；缺失或类型错误的工具不能注册。制作新工具时默认明确写为 `true`，确有共享写入或顺序依赖时改为 `false`，程序不会用隐藏默认值替工具做决定。调用名是工具身份的一部分，显示名称只是面向用户的标签。重命名显示名称不会把更新变成一个新工具；修改稳定调用名则会影响会话配置和市场身份检查。

### `input.schema.json`

这是模型看到的参数合同，也是执行前校验和参数权限分类的合同。每个顶层参数可以用 `permission_type` 声明权限类型；未声明时按“未知权限”处理，明确声明为 `none` 时不参与权限检查。这个字段只供天策运行时使用，发送给模型供应商前会从 JSON Schema 中移除。

权限类型描述参数代表的直接能力，例如 `filesystem_read`、`filesystem_write`、`program_execute`、`network_access` 或 `tiance_data_write`。一个参数只配置一个权限类型；一次调用包含多个参数时，执行器会汇总所有参数并采用最严格结果。程序支持而 Schema 不写、Schema 声明而程序不实现，都会产生难以追踪的失败。复杂工具应该用清晰对象、枚举和必填项表达边界，不能要求模型凭参数名猜规则。

### `output.schema.json`

描述工具真实返回。普通结果通常包含 `ok`、`summary`、`data`、`warnings` 和错误信息。图片等富媒体不应塞成长 Base64 或路径文字，而应通过标准内容块和受控资源 URI 返回。

### `examples.json`

案例负责解释典型业务组合，不是第二份参数表。它可以告诉模型怎样创建一份报告、怎样安全覆盖文件、怎样先检查再编辑，但不能引入程序并不支持的动作。

### `permissions.json`

记录该工具各权限点在不同作用范围内的处理方式：`deny` 表示禁止，`ask` 表示本次调用需要用户确认，`allow` 表示允许。权限配置属于工具项目的本地用户设置；市场首次安装会提供发布者默认值，已有工具更新时保留用户当前配置。

当前默认策略以低打扰和明确越界为目标：文件、外部数据和天策数据读取允许；工作区内文件写入与工作区程序执行允许；工作区外写入、系统程序、凭据、运行环境修改、外部数据变更和跨范围天策写入询问；工作区外或无法识别位置的文件删除禁止。完整范围和执行规则见[《工具参数权限与执行确认机制》](26_工具参数权限与执行确认机制.md)。

## 三种运行位置，一套工具体系

| 类型 | 运行位置 | 适用能力 |
| --- | --- | --- |
| `python` | 后端启动的独立工具进程 | 文件、文档、网络、计算等普通工具 |
| `client` | 前端登记的白名单执行器 | 标签页、界面导航、会话交互等浏览器状态能力 |
| `internal` | 后端内部 | 动态工具执行等基础设施 |

Python 工具通过标准输入接收 JSON，通过标准输出返回 JSON。client 工具仍使用同样的模型工具调用，只是执行请求被桥接到前端。internal 工具不是第三方扩展入口。

工具进程按白名单继承基础环境变量。主工具启动器、Python 脚本工具和 PIP 安装子进程都须保留宿主已有的 `SystemDrive`、`SystemRoot`、`WINDIR`、`ProgramData`、`ALLUSERSPROFILE`、`PUBLIC`、`USERPROFILE`、`HOME`、`HOMEDRIVE`、`HOMEPATH`、`APPDATA`、`LOCALAPPDATA`、`TEMP`、`TMP`，以及命令解析所需的 `COMSPEC`、`PATH`、`PATHEXT`。缺失或空值不编造默认路径；无关环境变量继续过滤，工具上下文与显式参数按各自执行合同注入。遗漏 `SystemDrive` 等变量会使 Windows 公共目录解析失败，并可能在项目工作目录中产生字面量 `%SystemDrive%` 文件夹。

## 两层启用与执行校验

工具能否执行同时取决于：

1. 工具自己的 `state.enabled`；
2. 当前会话是否启用了它。

执行时还会校验调用名、输入 Schema、运行入口和工作目录。模型即使凭空生成了一个未启用工具名，也不能绕过这些检查。

## 模型上下文与富媒体

工具需要知道当前模型是否能看图时，不应自行查询供应商数据库或按模型名称猜测。Python 工具从 `TIANCE_MODEL_CONTEXT` 获得标准化的供应商、模型和输入模态；client 工具从请求事件得到同一语义。

本地图片通过 `tiance-project:///` 或受控的 `tiance-local:///` 引用。后端重新校验文件、类型、签名和模型模态，再把资源交给模型。普通文本里写一个路径不会自动获得读取权限。

## 注入字符怎样计算

工具看板的“注入字符”不是只统计界面顶部可见的摘要，也不是 Token 数。标准加载工具按最终交给模型的工具定义计算字符数，内容包括：

- 调用名称；
- 工具说明；
- 所有已启用案例的标题；
- 明确开启“正文注入”的案例正文；
- 完整 `input.schema.json`，包括每个参数名、类型、说明、枚举、必填关系和嵌套对象结构。

统计时会把上述内容组装成与模型工具定义一致的紧凑 JSON，再计算字符串长度。界面上的参数卡片默认折叠，所以视觉上看起来不多，完整 Schema 实际可能占绝大部分。

以 2026-08-13 的 Word 制作编辑工具为例：清单摘要 314 字符，启用案例标题合计 68 字符，开启正文注入的案例内容 239 字符，组装后的完整说明为 645 字符；输入 Schema 的紧凑 JSON 为 7,788 字符，最终工具定义合计 8,553 字符。因此数字较大主要来自严格而复杂的输入参数合同，不是摘要被重复注入。

动态加载工具的看板数字使用轻量目录说明计算，只包含调用名、显示名称、摘要和案例标题；详细参数在模型实际选择该工具后再读取，两种数字不能直接横向比较。

## 制作一个标准 Python 工具

最小流程是：

1. 选择稳定、唯一的调用名和项目身份；
2. 写 `tool.json`，明确入口、超时、启用和动态策略；
3. 先设计输入/输出 Schema，并为每个顶层输入参数标注 `permission_type`；
4. 程序只从标准输入读取一次 JSON，只向标准输出写最终 JSON；日志写标准错误，不能污染协议；
5. 所有文件路径、外部响应和用户输入都在工具内部校验；
6. 写少量但真实的案例；
7. 在权限看板确认各作用范围的默认策略，再使用工具体检和针对性测试验证配置、入口、Schema 与返回结果；
8. 如需发布，再增加市场 `manifest.json` 和包完整性信息。

工具调用历史保存在目标工具项目自己的 `.Tiance/tool-calls/records.jsonl`。注册表只是扫描文件得到的进程内派生状态，不是第二份工具数据库。

## 不应由工具做的事

- 直接读取天策供应商密钥或内部数据库；
- 依赖前端隐藏按钮作为权限；
- 发明某个工具专属的聊天消息格式；
- 把绝对路径、巨量 Base64 或密钥写进普通结果；
- 要求聊天后端按具体工具名解释业务结果。

真正需要使用当前供应商能力时，应走后端供应商能力桥；真正需要前端状态时，应做 client 工具并显式登记。
