# 天策前端专项审查报告

审查开始于 2026-11-23，基线为 `f4a2fb9b`。本报告随审查追加。范围包括 `2_ReactWeb` 中的应用源码、样式、测试、静态资源与构建入口。发布产物单独检查交付方式，第三方库与生成的压缩代码不按自研模块评价。

审查关注用户操作从入口到落盘或回传的路径、模块之间的依赖、状态的所有者、长文件的实际职责，以及这些设计对定位故障和修改功能的影响。

## 总评

**前端的功能分类总体清楚，适合继续沿现有架构演进。复杂度已在工作台、聊天控制器和标签管理三个入口集中，出现局部失控的趋势。** 预览按格式拆分、项目和工具复用文件浏览器、手机和桌面共用会话请求构造，都减少了重复实现。维护单个格式或薄 API 时比较容易定位；一项涉及选项目、切标签、恢复会话或接收手机指令的改动，则要跨过多个状态所有者。这里最容易出现“每个模块看起来正确，组合后却恢复错目标或丢了最后一次输入”的问题。

- **规模与趋势。** 990 个 src 文件覆盖 66 个功能目录及其基础层。960 个 TS、TSX、CSS 文件中，51 个达到 500 行，其中 39 个是代码、12 个是样式，5 个达到 800 行。工作台入口 1251 行，其中一个组件占 1149 行；标签 hook 所在文件 1076 行，其中该 hook 占 1010 行；聊天控制器 995 行，其中主组件占 879 行。8 月以来三个入口中，聊天控制器的提交频率最高。
- **优先修复。** 发现 1 项 P1、12 项 P2、5 项 P3。P1 已在真实 Edge 实测到普通 HTTP 下手机桥挂载失败。P2 里最值得先处理的是错恢复会话看板、已撤回或待保存的设置被错误写入/丢弃，以及完成的工具结果被旧状态遮住。详见后文触发条件、复现方式和验收方法。
- **验证结果。** 类型检查、628 项既有前端测试、独立目录的生产构建通过。额外使用原组件、可控网络和存储、真实 Edge 键盘事件及双端口文件接口，验证了现有测试未覆盖的路径。每个功能目录与全部长文件均有索引和维护判断。

基线跟踪了 990 个 src 文件，包括 822 个 TS/TSX、138 个 CSS、27 个 Markdown 和 3 个语言 JSON。另有 99 个 tests 文件、5 个 public 文件及 293 个跟踪的 dist 文件。行数按物理文本行统计，包含空行、注释、类型和 JSX。

- **工作台总入口，维护优先级高。** `src/pages/workspace/ui/WorkspacePage.tsx` 有 1251 行。第 202 行起处理布局偏好写入，第 290 行起处理项目进入，第 411 行起接管退出/托盘，第 572 行起为多个侧栏构造 catalog 参数，第 874 行起装配标签恢复。修改一种项目集要同时理解导航、选择状态与视图适配。可以先将关闭/托盘事务整体迁入已有桌面模块旁的 hook，再按集提取目录适配。保持页面负责最后的组合，保留“取消切换不能更新活动项目”的回归用例。

## 依赖方向

用 TypeScript AST 解析全部 TS/TSX 的导入、再导出和字面量动态导入，解析相对路径、`@/` 和目录 index。对静态、非纯类型的本地依赖求强连通分量，**文件级未发现多文件循环**。按模块目录聚合后，八个功能目录互相可达。目录循环不等于 JS 初始化死循环，它反映改动时要跨越的所有权边界。

八个功能目录为 access-management、ai-panel、client-tools、conversation-runtime、document-editor-canvas、file-preview、mobile-access 和 office-preview。基础层另有一对目录互相依赖：HTTP 客户端通知网关需要重新认证，网关安全服务又调用 HTTP 客户端。entities 和 services 均未发现指向 features、widgets、pages 或 app 的运行时静态导入。

- `mobile-access` 为连接配置反向引用 `access-management/ui/AccessSwitchControl`，而后者的面板引入三渠道页面。将开关归入通用 UI 或访问控件即可切断这一对依赖。
- `DocumentAssetPreviewContent` 引入 `FilePreviewGate`，gate 又向编辑器借 `UnsupportedDocumentContent`。Office 预览引用分页表格，分页表格又从 Office 引入表格选区逻辑。把表格选区和不可预览状态交给两边共同依赖的模块，仍保留各格式自己的渲染器。
- `client-tools/model/conversationModelQuery.ts` 从 AI 面板取模型选项，AI 面板注册工具并接入手机，运行事件处理器又调回 client-tools。可把纯模型选项归入模型领域，把工具派发函数作为运行器的依赖传入。现有认领、幂等和异步结算测试应保留。
- `shared/online-market/OnlineMarketBoardShell.tsx:4` 直接导入 GitHub 同步按钮，第 47 行把按钮装入公共来源表单。新的市场界面因此被要求提供 GitHub 集类型。预计拆分成本低，公共壳接受操作区，由市场页面提供按钮。另一个反向依赖是 `shared/i18n/I18nProvider.tsx` 直接加载 locale 服务，适合在拆出独立语言包时再整理。


## 跨模块才显现的故障

- **P1，局域网 HTTP 的对话区可能在挂载时直接报错。** 网关生命周期专门使用 `crypto.getRandomValues` 兼容普通局域网 HTTP（`services/security/gatewaySessionLifecycle.ts:106`）。而 `ChatPanelController.tsx:278` 调用的注册 hook 在 `useChatPanelClientToolRegistry.ts:83` 无条件挂载手机桥，`useMobileDesktopBridge.ts:21` 在渲染阶段直接求值 `crypto.randomUUID()`。该方法仅在安全上下文提供。只要页面没有该方法，聊天组件即抛出 TypeError，即使用户未启用任何手机渠道。Word 预览的 `WordPreview.tsx:141` 也使用同一 API，此处异常落入预览错误页。验收应在缺少该方法而存在 getRandomValues 的环境挂载真实聊天入口并打开 Word。将非认证用途的标识生成统一实现，保留需要标准 UUID 格式的合同。[Web Cryptography Level 2，Crypto 接口](https://www.w3.org/TR/webcrypto-2/#Crypto-interface)
- **P2，知识、角色和主题项目可能恢复到错误标签。** 在其中一个项目进入会话总览后退出，此时保存的是 `active_dashboard=conversation_overview`、`active_file_path=null`。重新进入时，`pages/workspace/model/useProjectWorkspaceTabsPersistence.ts:82` 先激活总览，再以“没有活动文件”为条件激活专用看板。两个条件同时成立，后一次写入活动标签获胜。具体写入见 `features/document-tabs/model/useDocumentTabs.ts:522` 起的四个 ensure 方法。应先解析唯一活动目标，再创建标签。当存储有明确看板时，默认看板只用于无历史选择的情况。
- **P2，微信前端把一次状态查询异常当成扫码终态。** `features/mobile-access/ui/WeChatQr.tsx:19` 在 GET 失败后将本地状态写成 error，effect 第 12 行随即停止轮询，界面也隐藏二维码。服务端扫码会话此时可能仍有效。飞书同类轮询对查询异常保留再次查询的机会。可分别表示“暂时无法查询”和“平台已判定失效”。这条结论说明一种可触发的界面行为，无法据此反推过去某张截图的唯一原因。
- **运维限制，外部消息入口依赖 React 挂载。** 手机作业轮询、请求准备、能力回传和 release 生命周期都在 `useMobileDesktopBridge.ts:17` 的 effect 中。桌面页崩溃时后端仍可收到手机消息，却失去准备请求的一端。已有诊断记录实例数、轮询年龄和错误次数。建议先将桥的挂载移到具有明确桌面身份且持续存在的工作台宿主；如果产品要求渲染进程退出后仍能接单，则需重新设计请求准备的进程归属，单纯移动 hook 无法满足该目标。


## 定向复现与工具结果恢复

在独立 Node 进程中加载原 TS/TSX，实现使用已安装的 React 与 react-test-renderer，替换网络、持久化和浏览器能力，不连接运行中的天策。实测网络首次出错仍渲染 status 且无 alert；延迟保存时第二次编辑 B 被 A 替换；在缺少 randomUUID 的模拟环境挂载手机桥抛 TypeError；知识、角色、主题项目均按“会话总览 → 专用看板”顺序激活两次。仓库已有 `shared/model/createUuid.ts`，包含 getRandomValues 回退及 UUID 版本位处理，可直接复用。

**P2，前端工具已完成的结果可能被旧执行状态遮住。** `client-tools/model/clientToolExecutionSession.ts:37` 起的 store 在 sessionStorage 写失败时把新记录放到内存，读取时却优先取持久层。定向复现先成功写入 executing，再模拟较大的 completed 记录超出存储额度，随后同页 read 返回 executing。`clientToolRequestSingleFlight.ts:147` 在需要从 store 恢复时会将 executing 识别为结果未确认。用户可能看到工具动作已完成却无法恢复结果。同页应优先看到最后一次成功记入任一存储层的状态；跨刷新仍只能依赖实际持久化的记录，切勿盲目重跑有副作用的动作。

## 自动保存、工具开关及界面一致性

- **P2，Token 估算设置会提交已经撤回的值。** `features/token-estimation-settings/model/useTokenEstimationSettings.ts:91` 起，卸载会排空待写队列。草稿变回 saved 时 effect 提前返回，先前的 pendingSaveRef 并未清空。通过原 hook 复现：初始为 4，改成 5，又在 500 毫秒内改回 4，此时离开，实际 PUT 携带 5。修复应区别尚未提交和已在途的值，并让最终用户选择决定排队状态。验收覆盖撤回后立即离开、前一个 PUT 已发出再撤回两种时机。
- **P2，工具集多行并发更新只显示一行正在保存。** `features/toolset-overview/model/useToolRuntimeSettings.ts:23` 只有一个 updatingFolderId，UI 第 103 行按 ID 禁用相应行。实测 A、B 两个工具依次启动写入，两者都在进行时只锁住 B；先完成 B，A 未结束但标记已经为 null。此时 A 又能接收下一次操作，失败回滚也可能与新选择交错。应按工具 ID 持有进行中请求及回滚快照。
- **P3，市场筛选和布局偏好保存失败反馈较弱。** `shared/online-market/useOnlineMarketSource.ts:130` 延迟 250 毫秒保存筛选，卸载会取消尚未触发的写入，失败被吞掉。`WorkspacePage.tsx:250` 的布局保存串行，失败只写控制台。用户本次看到设置已经变化，重开却可能恢复旧值。明确何时才算保存，优先在当前页面提供失败提示或重试。
- **P3，确认对话框的键盘路径不完整。** `shared/ui/confirm-modal/ConfirmModal.tsx:58` 有初始焦点，危险操作默认聚焦取消。第 66 行处理 Escape，第 92 行声明模态；组件内没有 Tab/Shift+Tab 焦点约束或关闭后的焦点归还，显示标题时也未使用 aria-labelledby 关联标题。应在共享组件中验收键盘循环及关闭后焦点，保留 contained 和自定义 portal 用法。
- **语言覆盖。** 三种内置语言各有 1611 个叶子键，键集合相同；扫描直接以字符串传给 t 的键未发现缺失。另对全部 258 个 TSX 的 JSX 文本及 title、placeholder、aria-label、alt、label、message 字面属性检查，87 个文件共出现 691 处含中文的直接文本。这个数字是代码位置数，含重复文本，不含表达式中的字符串。注入预览与压缩日志预览各有 41 处。改系统语言后这些直接文本仍显示中文，翻译维护应先覆盖常用操作和失败提示。
- **清理信号。** 在现行检查外单独启用 TypeScript 的 noUnusedLocals 和 noUnusedParameters，得到 20 条诊断，包含 ChatPanelController 未使用的解构字段、useDocumentTabs 旧 import 和 HoverSidebar 已不读取的活动项。本次正常的类型检查通过。导入图和仓库引用搜索还发现 useServerHealth、createChatCompletion、discoverSavedProviderConfigModels 等已无应用入口的候选。删除前需核对外部消费者；worker、类型声明和 Vite 资源入口须单独识别。


## 数据写入与刷新顺序

- **P2，主题编辑在离开面板时有丢失窗口。** `features/theme-settings/ui/ThemeSettingsPanel.tsx:204` 起将有改动的主题延迟 450 毫秒提交，effect 清理只取消计时器。主题选择框在保存期间禁用，但如果父视图在计时器触发前卸载面板，本次编辑不会发出。组件在请求成功后按草稿指纹保护更新期间的新编辑，这部分值得保留。验收应覆盖修改单个颜色后立即关闭看板，再次打开读取的值。
- **P2，绑定私人项目仓库可以只完成一半。** `features/project-private-sync/model/useProjectOnlineMode.ts:111` 先保存绑定，再切换在线源，两个请求均成功才刷新本地 binding 和 source。若第二个请求失败，第一个操作已在服务端成功，界面仍按旧值显示。建议分别反映已保存的绑定与当前来源，失败后重新读取实际状态，提供只重试切换的入口。验收可让第一次保存成功、第二次返回错误，再重开页面核对。
- **P2，供应商配置刷新存在响应倒序覆盖。** `features/provider-config/model/useProviderConfigState.ts:123` 每收到匹配的用量变化事件就读取完整配置列表，并将结果合入 persistedConfigs。取消标志只区分订阅是否卸载，同一订阅连续发出的请求均可更新状态。较早快照最后返回会覆盖较新快照，也会替换加载错误表。此项由代码时序确认；未在真实服务器测得发生频率。相邻的模型发现模块已有按供应商识别请求版本的做法，可作为修复参考。

## 浏览器与渲染资源核验

- **真实 Edge 验证了局域网 HTTP 的聊天故障。** 在独立的无头 Edge 配置中，把测试域名仅解析到本机，以普通 HTTP 加载用仓库源码打包的手机桥。浏览器报告 `isSecureContext=false`、getRandomValues 可用、randomUUID 缺失；React 错误边界捕获到 `TypeError: crypto.randomUUID is not a function`。这验证了真实浏览器能力和组件挂载路径。测试没有登录正在运行的天策，也没有发送手机消息。
- **真实键盘事件验证了共享弹窗问题。** 同一隔离环境中，危险操作弹窗打开后焦点位于“取消”，Tab 到“确认”，继续 Tab 可以到背景的打开按钮。重新打开后，在弹窗内按 Escape，关闭后的焦点为 body。此结果补足了静态代码与 renderer 测试无法验证的浏览器行为。
- **长任务资源释放有可保留的实现。** Markdown 的 DOM 块缓存同时限制 16 份文档、100000 个后代元素和 800 万字符权重（`features/markdown-preview/model/markdownDomCache.ts`）；PDF 卸载时销毁 loading task，单页渲染有取消路径；PPT 替换和卸载时销毁 viewer。桌面诊断注册源和渲染错误记录也已有边界，错误日志最多保留五条。这些源码证据说明确实做了资源治理。此次没有对持续数小时的真实项目测量堆曲线，无法据此确定历史白屏的根因。
- **样式与静态资源。** 使用项目现有 PostCSS 解析全部 138 个 CSS，计得 4246 个样式规则、16756 条声明、41 个 media 规则，18 条 important 分布在 7 个文件。长样式集中在侧栏、预览和聊天。本次扫描没有发现 CSS 语法解析失败。5 个 public 文件分别为图标、两个 SVG、字体及其许可；27 个随应用加载的 Markdown 分布在 GitHub 帮助（12 个）和手机接入帮助（15 个）。

## 分支图在长会话中的成本

**P3，有大量分支的关系图提前为所有节点保留后续分支点。** [分支节点分析函数](../2_ReactWeb/src/features/conversation-branch-dashboard/model/conversationBranchLayout.ts) 第 110–134 行按反向拓扑复制子节点的分支点集合，再为每个节点生成排序数组。[节点卡片](../2_ReactWeb/src/features/conversation-branch-dashboard/ui/ConversationBranchTurnCard.tsx) 平时显示数量，展开后才使用完整列表。

用原函数构造连续分叉的有效图，每层两个变体，仅一个继续延伸。200、600、1200 个节点分别产生 4950、44850、179700 个后续分支引用，单机一次纯函数计算约 2、8、21 毫秒，未包含图布局和 DOM 时间。实际长度取决于分叉形态，普通无分叉长会话不会产生该增长。若要支持超大关系图，可先按选中节点获取明细，比较首次打开与展开的耗时和留存内存。

## 外部输入、存储与故障可见性

- **P3，网页标签的外观偏好可以阻止页面挂载。** [EditorWebAppearance](../2_ReactWeb/src/features/document-editor-canvas/ui/EditorWebAppearance.tsx) 第 54 行在渲染期间直接读取 localStorage，第 75 行在点击时直接写入。隔离测试让读取抛错，原组件即挂载失败，连宿主外观能力的可用性都来不及判断。邻近的 [网页标签恢复](../2_ReactWeb/src/features/document-tabs/model/workspaceTabEntries.ts) 与更新偏好都能在浏览器存储不可用时返回默认值。这个非必要偏好应以同样方式降级；写入失败时可保留本次窗口选择。
- **富文本渲染的入口集中。** 对全部 TS/TSX 搜索直接写入 HTML 的位置，共落在四个 Markdown 组件。正文管道在解析原始 HTML 之后使用 sanitize；KaTeX 配置关闭 trust，Mermaid 以 strict 初始化。HTML 文件预览另有 sandbox iframe。应在升级渲染库时分别回归这些路径。本次核对了配置与调用边界，未做第三方库安全评估。
- **资源和故障可见性。** 检查了包含重复计时器、Resize/Intersection/MutationObserver、对象 URL 及本地存储的源文件。9 个出现 setInterval 的源文件均可找到相应 clearInterval；24 个直接构造上述 observer 的文件均可找到 disconnect；两处直接创建对象 URL 的文件都有回收路径。同文件存在清理调用不能证明每个异常分支都执行清理。会话缓存有非活跃项目裁剪，诊断采样在上次上报完成后再安排下次。上线排障宜关联入口、项目/会话、错误阶段及请求代次；布局和市场筛选等静默写入目前仍难追踪。
- **异步问题补充验证。** 用原组件或 hook、可控网络与时钟再次验证四条路径：微信获取二维码成功后，第一次状态请求失败即隐藏图片并停止安排轮询；私人仓库模拟服务已保存新绑定，切源失败后界面 binding 仍为空；同一供应商两次用量刷新倒序返回，后到的旧错误替换新错误；主题字段在 450 毫秒内改完即关，排队计时器被清除，服务写入次数为零。这些操作都在测试夹具完成，没有动用真实账号或项目。


**P2，开启认证的跨端口开发环境可能通过文件检查，却打不开 Excel/PPT。** [开发环境地址解析](../2_ReactWeb/src/shared/config/env.ts) 默认让 18100 的页面访问 18000 的 API。[预览检查](../2_ReactWeb/src/features/file-preview/model/filePreview.ts) 经 HTTP 客户端携带会话凭据；[Excel 原文件读取](../2_ReactWeb/src/features/office-preview/ui/ExcelPreview.tsx) 第 235 行、[PPT 原文件读取](../2_ReactWeb/src/features/office-preview/ui/PresentationPreview.tsx) 第 193 行直接执行 `fetch(src, { signal })`。在独立 Edge 中搭建同一主机两个端口、凭据有效且允许跨域的测试页面和文件接口，使用这两种请求参数得到 401 与 200。该实验验证浏览器请求行为，未在用户真实网关打开私有文档。受影响条件是跨源且文件端点要求凭据；同源发布版或允许本地免登录时可能看不出差异。修复应统一受信 API 文件的读取策略，保留二进制响应、取消和版本参数，并验收跨端口登录后的真实文件预览。

| 4 | 按行为逐次收窄三个核心入口。先独立手机桥的宿主责任；工作台再提取关闭/托盘事务；标签 hook 分出专用标签构造。 | 每一步保留正常进入、切项目、恢复上次标签、未保存取消与已有工具回复路径。一次结构调整只转移一项状态或生命周期的所有权。 |
| 5 | 优化启动与运维。延迟装载已认证的工作台，显式反馈持久化失败，并按访问频率补翻译。 | 用同一干净构建比较登录页初载字节和可交互时间；失败时能看到未保存的设置及重试入口。 |

### 复核方式与边界

- 在 `2_ReactWeb` 下运行 `pnpm check` 和 `node --test --test-concurrency=3 tests/*.test.mjs`。构建使用仓库的 `vite.config.ts` 并将带 manifest 的产物输出到独立临时目录，以免正在使用的桌面窗口加载到变化的资源。测试夹具、临时浏览器配置及构建结果均独立于用户的运行数据。
- 全量核定包含上述目录下所有受版本管理的源文件，语法树/依赖图、CSS 解析、字典、资源、测试目录及长文件清单都以同一基线为准。逐功能检查了入口、调用方向和主要状态；对高风险的跨模块链路做了源码追踪、可控故障注入或独立浏览器复现。未采集真实账号数据，未在物理手机逐渠道联调，也未测量数小时生产负载或全部屏幕分辨率。
- 优先级按影响定。P1 表示受支持的使用方式可能直接失去核心入口；P2 表示可见的功能、数据一致性或首载成本问题；P3 表示体验、诊断或特定数据规模下的改进。未分级项记录结构、现有保护和维护成本。
