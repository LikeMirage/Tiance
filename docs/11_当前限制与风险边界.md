# 当前限制与风险边界

> 本文描述 `0.3.23` 的真实部署边界，不把“本地应用”自动等同于“已经认证”。后续修复代码后应同步删除或收窄对应条目。

## 本机服务身份

后端和桌面壳默认监听回环地址，但当前多个高权限接口仍依赖“只有可信前端能访问本机端口”的假设。回环地址、CORS、`localhost` 和 `file://` 都不是完整身份认证，WebSocket 也不受普通 HTTP CORS 自动保护。

使用要求：

- 不要把 `TIANCE_API_HOST` 或 Shell API 暴露到局域网/公网。
- 不要在前端开发端口运行不可信页面或代理。
- 不要把当前后端端口提供给网页、浏览器扩展或不可信本机进程。
- 供应商配置、client tool、文件接口和模型调用应视为本机高权限能力。

## 供应商密钥

API Key 加密保存在本机，但能修改供应商 endpoint 并触发请求的调用方可能让后端把已保存密钥发送到新的上游。当前版本必须只允许可信本地 UI 使用供应商配置接口，并核对自定义 API 地址。

错误和审计输出也应避免保存包含密钥的 URL 查询参数。排查日志或导出审计前先检查其中是否包含 Token、路径和请求正文。

## 工具执行

Python 工具在独立进程和私有依赖目录运行，但没有通用 OS 沙箱。工具权限是应用层控制；恶意 Python 包仍可能使用当前用户权限访问本机。

- 只安装可信市场和工具。
- 对工作区外文件、网络、凭据、环境修改和程序执行保持人工确认。
- 动态工具包装不会提高隔离级别。
- 依赖安装中途关闭程序可能留下不完整环境，需要重新安装或清理对应工具依赖目录。

## 在线市场与远端资源

远端索引、ZIP、Markdown 图片和重定向都属于不可信输入。当前实现仍需加强 DNS 重绑定、重定向前验证、解压总预算和同项目并发更新事务。不要连接不可信市场，也不要把私人项目中的 `.Tiance` 会话、路径和记忆当作可公开内容。

## 长会话

模型上下文由后端完整历史重建，没有“最近 100 条”限制；但前端打开主会话仍可能一次读取大量历史并受固定请求超时影响。极长会话可能出现加载慢或页面无法完成加载，不能用删除历史或缩短后端事实作为修复。

## 文档与大型文件

- DOCX 目录页码可能需要 Word 刷新。
- 复杂 LaTeX/HTML/Mermaid 可能降级为图片或警告。
- Office/PDF 预览对大型文件有较高内存峰值。
- 自动表格布局受字体和 GDI 可用性影响。
- 从不可信 Markdown 转换文档前，应检查本地图片路径和远端资源。

## 更新

正式更新包包含哈希和更新清单，但应用阶段仍应重新验证并采用安装目录级事务。更新前关闭正在运行的工具安装和文件写入；重要安装目录应保留可恢复备份。

## 非目标平台

当前正式发布主线为 Windows。macOS 和 Linux 没有经过同等打包、桌面壳、文件监听、字体测量和更新流程验证。
