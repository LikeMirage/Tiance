# 文档转换、预览与文件监听

## Markdown 转 DOCX

后端转换服务位于 `1_PythonServer/app/services/document_conversion/markdown_docx/`。它处理 Markdown 解析、模板、图片、HTML/Mermaid、公式、表格布局和 DOCX 包级校验。

数学公式优先走：

```text
LaTeX → MathML → MML2OMML → OMML 校验 → Word 原生公式
```

无法忠实转换的二维图式可降级为图片；仍无法处理时保留源码并返回警告。不能静默丢失公式、图片、表格或关系。

表格列宽会结合页面宽度、字体测量、不可拆分内容和换行代价分配。Windows 优先使用 GDI；GDI 不可用时启发式测量可能产生跨机器版式差异，正式交付仍需打开检查。

## 图片与远端资源

本地图片必须相对明确的项目/文档根解析并校验 canonical path，不能让 Markdown 的绝对路径或 `..` 读取任意本机文件。远端图片需要在 DNS、重定向和实际连接阶段持续执行 SSRF 防护，并有大小、数量和超时预算。

Markdown 预览与可视化编辑共用文档相对路径解析器：先还原渲染器产生的 URI 编码，再生成项目/工具文件夹的资产地址，避免中文文件名被重复编码。可视化编辑只转换图片的 DOM 显示地址，保存时仍使用 Markdown 中的原始相对引用，不把本机 API 地址写入文件。

## 工作台预览

前端支持 Markdown、DOCX、Excel、PPT、PDF 等预览。预览是展示投影，不是文件正式内容。文件版本变化后，旧选区、画布和缩略图必须失效或重建，不能把旧选区坐标应用到新文件。阅读位置与这些渲染数据分开：打开的编辑器标签只在内存中保存页码、工作表名、滚动锚点和缩放等轻量状态；新内容就绪后，格式适配器校验并恢复位置，页码/行列超出新范围时收敛到有效范围，关闭标签后释放。它不写入会话、审计或文档正文。

大型 Office/PDF 文件会产生明显内存峰值；页面、缩略图和画布需要按需加载和释放，不能无限保留全部渲染结果。

### 统一的资源检查与生命周期

真实文件继续使用原有的 `fileSource + path + version` 身份；项目文件和工具文件夹分别经过自己的路径权限校验，再进入同一预览服务。人工点击、引用打开和客户端工具打开最终共用编辑器入口。预览不创建 AI 会话、运行记录或长期任务表，不写入正式源文件。

图片、Office、PDF、视频、数据库在挂载预览器前经 `FilePreviewGate` 检查。检查/Excel 分页在可终止的独立 Python 子进程中执行，全局最多 2 个，排队及计算各有明确的 30 秒预算；失败显示原因和重试/外部打开入口。断开请求、停止预览、关闭标签或退出程序会终止对应后台任务并回收临时目录。每页独立读取，不落盘保存整本工作簿或重复上下文快照。响应体最多 4 MiB。

检查结果携带文件的设备、文件号、修改时间及大小构成的版本；后续资产读取和 Excel 分页校验此版本。通知触发重新核对期间保留当前画面并暂停其交互；核对后实际版本不变则复用渲染器。切换文件、实际版本变动、停止后重新检查会卸载旧渲染器，取消旧请求，清空选区；新渲染器从标签的阅读状态恢复位置。异步结果必须仍属于当前实例才能显示或提交引用。Word 的 SHA-256 指纹和原选区引用机制保留。

统一约束的是生命周期与资源预算，格式的真实差异由适配器处理：

| 格式 | 读取与展示策略 |
| --- | --- |
| 文本/代码 | 读取前及读取中均执行 20 MiB 编辑器上限；不返回可保存的截断正文。超过 50 万字符或单行 1 万字符使用无语法分析、无自动折行的完整文本编辑。重读/关闭会取消旧请求。 |
| Markdown | 原有 Worker 完整解析和渐进显示保留；可视化编辑超过 20 万字符时使用完整源码，避免构建大编辑 DOM。 |
| HTML | 超过 20 万字符时展示完整源码；小文件继续使用禁脚本 sandbox 预览，不把 iframe 当作进程隔离。 |
| Excel | 检查实际单元格数、合并区域和稀疏范围。超过 2 万单元格/范围面积、128 个合并区域或解压后 4 MiB 时，使用后台流式解析的分页数据视图，每页 50 行 × 20 列。可切换工作表、翻行/列、复制和引用本页选区，保留原单元格地址。该视图展示保存值，不执行公式；明确提示不还原合并、图表和原排版。小工作簿保留原格式预览器。旧 XLS 提示用原生应用打开或另存 XLSX。 |
| CSV/TSV | 与 Excel 共用 `PagedTablePreview`，通过原项目/工具文件夹的预览接口进入同一个可取消子进程。逐条解析记录，前端每页最多 50 行 × 20 列；首行不自动丢弃为表头，前导零、空值、引号内分隔符和换行原样保留，不执行公式。UTF-8/BOM、UTF-16/BOM、GB18030 自动判断，逗号/制表符/分号/竖线可自动或手动选择；自动判断不保证适用于所有文本，错误时可切换设置重试。实际识别结果随分页请求固定，改变设置使旧选区失效。最多 256 MiB、1048576 行、16384 列，单条逻辑记录最多 100 万字符；超限或格式错误明确提示。首次检查流式统计行列数，后续页从文件流定位目标记录，不保存永久索引。 |
| Word/PPT | 现有 DOM 排版引擎保留，先在子进程检查 XML/SVG、解压及嵌入图片预算；超出预算明确拒绝内置排版。XML/SVG 最多 4 MiB、2 万节点，包展开最多 32 MiB，Word 最多 1500 段/2000 个表格单元格，PPT 最多 40 页。Word 屏幕外页面使用 `content-visibility` 减少布局/绘制。**此路径不是完全脱离主线程的排版，停止操作不能抢占已开始的同步 DOM 调用。** |
| 图片 | 解码前读取头部：最多 32 MiB、2400 万像素，动画累计最多 4800 万像素；SVG 最多 1 MiB。超限由外部应用处理。 |
| PDF/视频 | 复用 PDF.js Worker、按页画布取消/释放，以及视频原生流式播放和 metadata 预加载，不用文件总大小代替内存开销。 |
| SQLite | 仅读取文件头，不将整个数据库读入内存；全部预览查询进入同一子进程调度，断开请求会终止查询。保留分页查询；单次预览查询最多 10 秒，单页内容最多 4 MiB，对象清单最多 2000 个，超限明确失败，不静默裁掉字段。 |

压缩包通用保护：压缩文件最多 64 MiB、4096 个条目、展开最多 256 MiB；流式 XML 对实际读入字节、节点数和超长文本/属性持续计数，拒绝 DTD/实体声明。阈值集中在 `services/file_preview/policy.py`，前端纯展示阈值在 `features/file-preview/model/previewPolicy.ts`；这些是当前实现的公开资源预算，不是源文件、模型输入或文件工具读取上限。

已加载文本缓存保留最近 8 个非活动干净标签，累计最多 1000 万字符（正文与保存基线合计）；小文件也计入预算。当前文件、未保存内容、冲突和保存中的标签不作为可丢弃缓存。图片/Office 分页结果随组件卸载释放，不增加永久预览存储。

桌面窗口的关闭确认、未保存内容处理和退出准备沿用原协议；本次未将 HTML 标题栏替换为原生窗口按钮。不能据此承诺任何第三方排版器异常下原生按钮都不受影响。

## 文件监听

Windows 原生目录监听由后端独立进程/线程处理，事件进入项目 workspace event 流，前端据此做局部刷新。监听只负责“可能发生变化”的通知，项目列表和正式文件内容仍由 repository/文件系统读取。

前端的项目集、主题和项目文件通知使用同路径的 WebSocket，避免 SSE 长连接占满 HTTP/1 普通请求名额，导致图片或接口一直排队。现有 HTTP SSE 接口保持可用；前端不自动退回 SSE。同项目文件监听仍共享连接。通知断线时每 3 秒尝试重连，最后一个订阅者关闭即停止；恢复 `ready` 后核对断线期间可能改变的展示状态。保活每 15 秒发送 `heartbeat`，不触发文件刷新、不限制订阅时长，也不取消等待中的事件读取。

过载时应进入明确的降级或重扫状态，不能通过永久排除 `.Tiance`、Office 临时文件或某类目录来伪装稳定，因为内部状态变化和真实文件变化都可能影响页面。

前端收到事件后应按项目和资源类型失效，不应让后台项目事件抢走当前项目，也不应每个事件触发整棵文件树、全部预览和所有会话重载。

目录路径通知只表示该目录内可能有变化，不能当作其中所有已打开文件都被修改。前端先核对候选文件的元数据；只有精确命中文件的通知或核对出的元数据变化才更新资产版本。Markdown 内容更新保留已显示的分段，源码编辑按变化区间更新，避免先清空正文引发滚动归零。
