# 通知公告仓库结构与发布流程

## 1. 能力边界

通知公告是独立的在线内容能力，不属于项目、会话或在线市场安装包。

* 远端年度索引是公告标题、摘要、修订号、状态和正文位置的权威来源。
* `Data/announcements/settings.json` 只保存公告源和启动检查开关。
* `Data/announcements/read-state.json` 只保存已读修订和最后成功联网检查时间。
* `Data/cache/announcements/<源哈希>/` 只保存可以重新下载的索引、正文和图片缓存。
* 公告数据不进入 SQLite，不写入任何项目的 `.Tiance`，也不克隆整个公告仓库。
* 删除缓存不会改变已读状态；已读状态文件损坏时会明确报错，不会把全部公告静默重置为未读。

默认公告源：

```text
https://github.com/LikeMirage/Tiance-announcements.git
```

## 2. 远端仓库结构

```text
index.json
indexes/
  2026.json
announcements/
  2026/
    08-23-1/
      r1/
        content.md
        assets/
          cover.png
    08-23-2/
      r1/
        content.md
```

公告 ID 使用 `YYYY-MM-DD-N`。`N` 是当天从 1 开始的正整数序号，因此同一天可以发布任意多则公告，没有固定数量上限。公告目录不需要英文简称。

同一公告修改已发布正文时必须增加修订目录，例如从 `r1` 变为 `r2`。不能直接覆盖 `r1/content.md` 后仍沿用修订号 1；客户端以 `(公告 ID, 修订号)` 判断是否已读。

## 3. 根索引

根目录 `index.json` 只负责指向最新公告和各年度索引，不重复保存公告标题等业务事实。

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-08-23T18:00:00+08:00",
  "latestAnnouncementId": "2026-08-23-2",
  "latestAnnouncementYear": 2026,
  "years": [
    {
      "year": 2026,
      "indexPath": "indexes/2026.json"
    }
  ]
}
```

约束：

* `schemaVersion` 当前必须为 `1`。
* `updatedAt` 必须是带时区的 ISO 8601 时间。
* 年份不能重复。
* 年度索引路径必须是 `indexes/<年份>.json`。
* 最新公告 ID 的年份、`latestAnnouncementYear` 和年份列表必须一致。

## 4. 年度索引

`indexes/2026.json` 是该年度轻量元数据的唯一远端权威来源。

```json
{
  "schemaVersion": 1,
  "year": 2026,
  "updatedAt": "2026-08-23T18:00:00+08:00",
  "announcements": [
    {
      "id": "2026-08-23-2",
      "revision": 1,
      "title": "天策新版本预告",
      "summary": "本次公告的简要说明。",
      "publishedAt": "2026-08-23T18:00:00+08:00",
      "importance": "normal",
      "status": "published",
      "contentPath": "announcements/2026/08-23-2/r1/content.md"
    }
  ]
}
```

字段约束：

* `revision` 是从 1 开始的正整数。
* `importance` 只能是 `normal`、`important` 或 `critical`。
* `status` 只能是 `published` 或 `withdrawn`。
* 公告 ID 日期必须与 `publishedAt` 的本地日期一致。
* 正文路径必须与 ID 和修订号精确对应。
* 年度索引可以包含该年度全部公告。程序没有“最近 N 条”读取或展示上限；界面可以滚动访问全部元数据。

撤回公告时将原条目的 `status` 改为 `withdrawn` 并更新年度索引时间。根索引的最新公告指针必须指向一则仍为 `published` 的公告。

## 5. Markdown 正文和图片

正文只使用单语言 Markdown，不需要多语言目录。

公告标题和发布时间由年度索引提供，并由客户端统一显示在正文上方。`content.md` 只写公告正文，不要再次写同名一级标题，也不要写公告 ID、修订号等内部索引字段。

图片必须放在该修订目录的 `assets` 下，并使用相对路径：

```markdown
![说明图片](assets/cover.png)
```

客户端拒绝绝对网址、`file://`、盘符路径和包含 `..` 的公告图片路径。Markdown 继续使用天策现有的安全渲染器；图片由后端按需下载、校验路径并缓存。

传输边界是明确失败而不是截断：根索引最大 1 MiB，年度索引最大 4 MiB，单篇正文最大 2 MiB，单个图片资源最大 25 MiB。超出时接口明确报错，不会返回不完整内容。

## 6. 客户端检查和已读规则

启动检查流程：

1. 读取本地 `checkOnStartup`。
2. 开启时下载根索引和最新公告所在年度索引。
3. 精确查找根索引指向的最新公告。
4. 比较本地 `(公告 ID, 修订号)` 已读记录。
5. 只有最新修订未读时才下载正文并弹出一次。

不会把多则漏读公告连续弹出。其他未读公告保留在历史看板中。

弹窗点击空白背景不会关闭；按 Esc 或点击“关闭”都会先保存已读状态，保存成功后才关闭。正文加载失败或已读状态保存失败都不会把公告误记为已读。在看板中成功打开正文后会保存该修订为已读。

通知公告设定页分为“公告”“历史公告”和“检查设置”三个标签页。“公告”页首次显示最新公告，也承载从历史列表打开的任意公告；点击历史条目后切换到“公告”页显示对应正文。“检查设置”只管理启动检查、手动检查和上次成功检查状态。这些页面共用同一年度索引、正文缓存和已读状态，不复制公告事实。

联网下载失败时可以显示已验证的本地缓存，但不会更新“上次成功检查”时间。远端返回结构无效时不会用旧缓存伪装成一次成功更新。

## 7. 发布步骤

发布一则新公告：

1. 确定当天序号，生成新的 `YYYY-MM-DD-N`。
2. 新建 `announcements/<年份>/<MM-DD-N>/r1/content.md`。
3. 将图片放入同目录 `assets/`，正文只写相对图片路径。
4. 在对应年度索引加入完整元数据并更新其 `updatedAt`。
5. 更新根索引的 `updatedAt`、`latestAnnouncementId` 和 `latestAnnouncementYear`。
6. 提交前按下面的测试方法检查结构和实际渲染。

修订已有公告：

1. 复制正文和仍需使用的资源到新的 `r<修订号>` 目录。
2. 修改新目录内容，不覆盖旧修订目录。
3. 更新年度索引中该公告的 `revision` 和 `contentPath`。
4. 若它仍是最新公告，同时更新根索引 `updatedAt`。

## 8. 测试方法

后端契约测试：

```powershell
cd 1_PythonServer
python -m pytest -q tests/test_announcements.py
```

前端类型检查：

```powershell
cd 2_ReactWeb
pnpm check
```

人工检查至少覆盖：

* 启动检查关闭后，启动时不请求在线公告；手动打开公告看板仍可检查。
* 同一天发布多则公告时，ID、排序和正文目录都正确。
* 最新公告只弹一次；提高修订号后会重新提示一次。
* 点击弹窗背景不关闭；关闭时保存失败则保持打开。
* 断网且有缓存时能阅读，且“上次成功检查”不被刷新。
* 清除 `Data/cache/announcements` 后已读状态仍在。
* 历史年度按需加载，年度内所有公告都可访问。
* 外部图片网址、绝对文件路径和越界相对路径不能加载。
