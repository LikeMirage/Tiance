# 待完善：Word 选取改善记录及后续完善方向

> 更新日期：2026-08-14
> 当前范围：仅改进独立的 `word_document_editor` 工具；软件本体、预览器和引用注入暂未修改。

## 一、问题来源

Word 预览引用已经能够提供文件、表格、行列、段落和字符偏移。实际测试证明，表格、行列和段落可以正确映射到 DOCX 内部位置；失败主要发生在原生公式的字符偏移上。

浏览器预览会把分数、上下标等公式结构转换为可见文本，Word 工具则从 OMML 公式结构提取语义文本。两边表达的是同一公式，但线性文本可能相差少量字符。例如预览结束偏移为 16，工具解析出的公式文本长度为 15。旧实现会直接返回“字符偏移超出范围”，迫使 AI 全量 inspect 后改用 `formula_ref`。

字符偏移是光标在当前段落语义渲染文本中的零基位置，采用“起点包含、终点不包含”的范围约定。它适合普通文字，但不能作为公式、图片等结构对象的唯一身份。

## 二、本次已经完成的工具改进

### 1. 公式边界校准

工具仍先按正文或表格、行列和段落确定容器。容器确定后，将内容拆分为普通文字和公式对象片段，并建立预览字符位置到 Word 纯文字位置、公式对象之间的映射。

当范围落在同一段落或单元格内、确实包含原生公式，并且结束偏移只相差少量字符时，工具会把范围校准到当前公式边界。校准结果会在 dry-run 或 inspect 中明确返回：

- 原始起止偏移；
- 实际解析后的起止偏移；
- 偏移差值；
- 使用的解析策略；
- 是否发生自动校准。

该校准只处理原容器内的小幅公式边界差异，不进行全文模糊定位。

### 2. 公式和混合选区的语义结果

局部 inspect 和编辑 dry-run 现在可以返回：

- `content_kind`：`text`、`equation` 或 `mixed`；
- `selected_rendered_text`：Word 工具解析出的语义渲染文本；
- `content_markdown`：便于 AI理解的 Markdown 语义内容，公式以 `$...$` 表示；
- `segments`：按顺序列出普通文字、公式和段落分隔；
- 公式片段对应的 `formula_ref` 与 `formula_text`；
- `resolution`：本次选区采用精确坐标、公式边界校准或稳定公式引用等策略。

这里的 `content_markdown` 是工具根据现有 Word 内容生成的语义表达，不要求文档原本由 Markdown 创建，也不等同于原始 Markdown 源码。

### 3. 局部候选与错误诊断

偏移差异较大或内容校验失败时，工具不再只返回笼统的“偏移超出范围”，而是返回：

- 容器是否找到；
- 请求的起止偏移；
- 当前段落的实际语义文本长度；
- 当前容器标识；
- 字符偏移的含义；
- 同一段落或单元格内最多五个候选范围；
- 每个候选的内容类型、语义文本、Markdown、片段清单和相似度。

候选仅用于 AI诊断和下一次调用。除“小幅且明确落在公式边界”的情况外，工具不会自动选择模糊候选执行写入；多个候选必须重新 inspect 或显式选择，避免改到同文档其他相似内容。

### 4. 原位编辑预演

原位编辑或覆盖已有文件时，dry-run 阶段就会检查 `overwrite`。未设置时直接返回需要补充的参数，不再等正式写入才报错。

`validation_token` 现在共同确认：

- 输入文档版本；
- 输出路径；
- 编辑 operations；
- `overwrite` 覆盖策略；
- `backup` 备份策略。

正式提交改变其中任何一项，都需要重新 dry-run。

## 三、当前仍未修改的软件本体

本次没有修改前端预览、引用消息组装、后端会话注入或通用引用协议。因此，软件目前能否把下列信息直接提供给 AI，仍取决于现有引用数据：

- 用户所选内容的 Markdown 语义；
- 文字和公式的片段清单；
- 公式在段落中的对象序号；
- 明确的字符偏移单位；
- 选区前后文及稳定引用版本。

Word 工具已经具备接收 `word_range`、`expected_text` 并返回语义内容和局部候选的能力，但不会反向依赖前端或读取软件内部数据库。

## 四、后续软件本体完善方向

后续应建立独立于具体工具的文档引用契约。预览器只描述“用户选中了什么”，Word、PDF、Excel、PPT 等工具各自解析自己理解的结构字段，双方通过数据合同配合，不直接互相调用。

建议引用数据逐步增加：

1. `reference_version`：标识引用合同版本；
2. `document_fingerprint`：文档变化后明确拒绝过期引用；
3. `content_kind`：文字、公式、图片、表格或混合内容；
4. `selected_text`：面向普通阅读和校验的文本；
5. `selected_markdown`：面向 AI理解的语义 Markdown；
6. `segments`：按顺序描述文字与结构对象；
7. `object_index`：公式等对象在段落内的顺序；
8. `offset_unit` 与 `canonical_text`：明确浏览器和工具共同使用的偏移基准；
9. `prefix`、`suffix`、最近标题：在原容器内进行候选校准；
10. 表格、行列、单元格段落等结构坐标。

其中 `selected_markdown` 应随引用内容发送给 AI，帮助 AI理解分数、上下标和混合内容；工具定位仍以文档指纹、结构范围和对象片段为准，不能把 Markdown 字符串当作唯一定位依据。

## 五、后续验收目标

后续软件本体完善后，应覆盖以下端到端场景：

- 在 Word 预览中选中表格内原生公式，说“改成红色”，只需一次 dry-run 和一次正式提交；
- 选中“左侧文字 + 公式 + 右侧文字”，工具能保持片段顺序并正确识别为混合选区；
- 公式线性文本少量不同仍能在原单元格内安全校准；
- 同一单元格存在多个相似公式时不自动误选；
- 文档变化后引用明确过期；
- 引用数据不绑定某个 Word 工具实现，也不要求前端调用工具。
