# 在线工具市场发布与更新流程

这份文档说明如何把工具发布到在线工具市场，以及客户端如何发现和更新工具。当前工具市场仓库为：

```text
https://github.com/LikeMirage/Tiance-tools
```

公开市场通过 GitHub Pages 提供只读内容，客户端读取仓库根目录的 `index.json`，再按清单下载工具文件。

## 一、市场文件结构

市场仓库的基本结构是：

```text
index.json
tools/
  <tool-id>/
    manifest.json
    ...工具文件...
```

`index.json` 负责列出市场中有哪些工具；每个工具的 `manifest.json` 负责描述稳定 ID、调用名、版本、说明、入口文件、参数和校验信息。

稳定工具 ID 是更新关系的依据，显示名称不是稳定身份。修改显示名称不会产生新工具；修改稳定 ID 会被客户端视为另一个工具。

## 二、发布前检查

进入工具市场仓库，先同步远端并确认工作区：

```powershell
cd <Tiance-tools仓库>
git pull --ff-only origin main
git status --short
```

检查每个工具：

- `manifest.json` 是合法 JSON；
- `id`、`name`、`version`、`entry` 和参数定义完整；
- 入口文件确实存在；
- 工具说明中的调用名与 manifest 一致；
- 依赖清单只包含工具运行时真正需要的依赖；
- 示例和规则文件路径与 manifest 一致；
- 不包含 API Key、Token、个人项目文件、会话、数据库和本机缓存。

如果工具依赖需要安装，依赖应落在工具自己的依赖配置和依赖目录规则中，不把开发机全局环境当作发布包的一部分。

## 三、版本和清单

工具有行为、参数、规则、入口或依赖变化时，递增工具自己的版本号。版本号写入该工具的 `manifest.json`，并同步更新市场根目录 `index.json` 中对应条目。

发布前确认：

```powershell
Get-Content index.json | ConvertFrom-Json | Out-Null
Get-ChildItem tools -Recurse -Filter manifest.json
```

不要只修改 `index.json` 而不更新工具目录，也不要把未实现的参数写进正式清单。

## 四、提交和推送

```powershell
git add index.json tools/<tool-id>
git diff --cached --check
git diff --cached --stat
git commit -m "release tool <tool-id> <version>"
git push origin main
```

GitHub Pages 更新后，客户端重新读取 `index.json`。客户端会校验清单和工具文件的大小、路径及 SHA-256；校验失败时不会安装。

## 五、客户端更新规则

客户端使用稳定工具 ID 查找本地已安装工具，再比较远端版本和本地市场收据。更新时：

1. 下载远端清单和工具文件；
2. 校验 HTTPS、路径范围、文件大小和 SHA-256；
3. 在临时目录完成解压和结构检查；
4. 保留本地不受市场管理的配置；
5. 安全替换工具文件并更新本地收据。

供应商凭证、用户项目、会话、数据库和本地密钥不属于市场包，不能被工具市场覆盖。

## 六、发布后核对

- 在 GitHub 仓库确认提交已经进入 `main`；
- 通过 GitHub Pages 地址直接打开 `index.json`，确认能看到新版本；
- 在软件中刷新在线工具市场；
- 检查工具版本、显示名称、调用名和说明；
- 安装或更新一次工具，确认入口可执行；
- 检查工具本地配置和依赖没有被无关覆盖；
- 删除或改名的工具应在索引中明确处理，不能留下指向不存在文件的条目。

## 七、常见错误

### 只提交工具文件，没有更新索引

客户端只读取 `index.json`，因此看不到新工具或新版本。

### 只更新显示名称

显示名称不是稳定身份。若误改了 `id`，客户端会把它当成新工具，可能造成重复安装。

### 把凭证打进市场包

市场包可被下载和缓存。任何 API Key、Token、供应商凭证和个人数据都必须留在本地，不得进入仓库。

### 直接修改已发布版本

客户端可能缓存旧清单。已经发布的版本内容应保持不变；有修复时递增工具版本再推送。
