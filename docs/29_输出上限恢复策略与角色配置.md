# 输出上限恢复策略与角色配置

实施日期：2026-10-09。用户在方案研究后明确授权“开始”。本文件记录已实现行为；联想笔记本故障证据及此前公开项目研究仍在 `28_联想笔记本上游请求异常排查记录.md`。

## 1. 配置入口与默认值

会话基础设置和角色基础设置均在“最大输出”下面显示同一组输出上限设置。角色文件写入 `response.json`；最大输出额度继续属于 `generation.json` 的 `max_output_tokens`。

| 配置参数 | 新建默认角色的默认值 | 作用 |
| --- | --- | --- |
| `output_limit_action` | `send_message` | `stop` 停止，`retry` 重试原请求，`send_message` 追加普通用户消息后继续 |
| `output_limit_save_partial` | `true` | 是否把本次截断正文、可见思考和用量保存为正式历史 |
| `output_limit_message` | 预设续接文字 | 发送新内容时使用，支持编辑和恢复预设 |
| `output_limit_max_recoveries` | `null` | 一次原始用户任务允许的输出上限恢复次数；空值沿用 `upstream_retry_count`，0 表示不恢复 |

2026-10-10 调整：新建默认角色使用“发送新内容＋保存截断前的正文和思考”，当前开发工作区的默认角色也已同步。角色和会话共用设置组件在选中“发送新内容”时，同时提交 `output_limit_save_partial=true`，自动勾选并保存该选项。

旧配置缺少这些字段时仍兼容“丢弃未提交片段、重试原请求”的行为，已有角色和会话明确保存的其他动作不批量覆盖。已有默认角色的 128000 输出额度和新建默认角色的 128000 初值继续保留，实际允许范围仍由协议及模型能力校验。

角色应用、另存为角色、新建会话继承、角色包导入导出、会话 JSON 保存读取、子会话管理工具配置都携带这四项参数。旧角色包允许缺少新字段；旧会话角色绑定哈希只在确认与旧配置一致时迁移，避免把未改动的角色误标成自定义。

## 2. 输出上限的判定

优先使用供应商的明确结束原因：OpenAI 兼容接口 `length`、Anthropic `max_tokens`、Gemini `MAX_TOKENS`、Responses `max_output_tokens`。流式和非流式都保留该原因。

接口没有提供明确结束原因时，仅对“流缺少完成标记”或“响应不完整”进行数值兜底：供应商提供的真实 `completion_tokens` 达到请求输出额度的 95% 即视为输出上限。用于此判断的 Gemini 输出量包含正文和思考 token；其他协议继续使用自身的输出量定义。

以下情况不按输出上限处理：正常结束但接近额度、本地估算量、余额不足、网络连接失败、限流、内容过滤、明确的其他结束原因。普通异常仍沿原来的失败重试机制处理。上下文不足沿用已有记忆压缩设置，本改动不增加额外的上下文恢复策略。

## 3. 保存与上下文是两件事

截断片段保存为 `assistant` 历史，增加 `finish_reason="output_limit"`；前端明确显示“输出已截断”。不会把生成一半的工具参数保存为正式工具调用，也不会执行本次未提交的工具调用。此前已经完成的工具调用与真实返回结果继续保留。

- **不保留**：本次截断正文和思考不进入正式历史，也不进入后续模型上下文；请求审计和真实消耗统计仍保留。
- **保留并停止**：保存正文和思考，结束本次任务；有正文的片段可进入以后正常发送消息时的上下文。
- **保留并重试原请求**：片段可供用户查看，设置 `include_in_context=false`；当前重试仍复用截断前的同一轮输入，以免叠加片段造成重复或污染。
- **保留并发送新内容**：有正文的片段进入下一轮正常历史组装，新通知随后作为独立用户消息进入历史。
- **只有思考、没有正文**：选择保留时仍保存思考供用户查看，但不构造仅有未完成思考的空 assistant 请求项。续接从已有正文和工具结果继续；保存思考不等于恢复模型内部状态。

`include_in_context` 的筛选放在公共历史消息组装中，记忆压缩和长期记忆使用该组装入口时也会遵循同一规则。原本的手动停止消息保留规则不改变。

## 4. 三种后续动作

### 停止

不发下一次请求，结算当前运行并报告输出上限错误。是否留存片段由保存选项独立控制。

### 重试原请求

在恢复次数范围内重新请求该模型轮次。没有工具调用时，复用原来的用户输入与历史；已执行工具后，复用该轮已有的工具返回结果。不会额外插入一条“继续”用户消息。

### 发送新内容

运行器以普通用户消息的落库、历史组装、记忆检查、工具循环和流式交付流程继续执行，自动消息带有固定前缀 `【天策自动续接通知】`，后面是用户配置的文字。默认正文为：

> 上一轮生成达到单次输出上限，任务尚未完成。请根据当前会话中的已有内容和工具结果继续完成原任务，避免重复已完成的内容。未完整生成的工具调用没有执行，如仍需要，请重新生成完整调用。

消息具有稳定 ID、`message_source="output_limit"` 和 `continuation_of` 父用户消息 ID。用户可以在历史中看到它。运行器不会操作或覆盖输入框草稿。它与子会话前端桥使用相同的正常会话发送基础流程，但续接调度在后端，界面断开后仍能执行。

所有自动用户轮次属于同一个后台管理任务。停止可以取消整条链；原用户轮次因截断结算时，会话整体继续保持运行中，直到真正完成、失败或取消。子会话发送/等待工具跟随自动消息链，返回最后续接的回复，不会把首次截断当作最终成功。

恢复次数在原始用户任务中共享，跨工具轮次和自动用户轮次累计；普通网络异常重试与它分开消耗。超过次数时停止，避免无限追加和请求。

## 5. 用量统计、断线和重放

用量由每次实际模型请求记录，而不是等消息保存后才记。新的 `request_id` 用于幂等记录；不同尝试分别计入，相同尝试重复写入不会重复收费统计。保留原有无请求 ID 的历史消息去重规则。没有上游用量但收到部分输出时仍按既有估算机制补齐，估算值不用于数值截断判定。

实际成功记入请求用量后，消息结算不再重复计入。截断消息自己的 `usage` 仍保存为展示数据。普通重试失败、输出上限失败和收到部分输出后取消的尝试，也会进入统计。

自动消息父子关系持久化，用于相同原用户消息重复提交时找到已完成的续接结果，不重新调用模型。流式恢复点记录保留片段和自动用户消息，前端恢复时不会把截断片段重新并入正在输出的缓冲区，也不会把旧轮工具过程插入新的用户回合。对子会话等待器，重放已经验证过的父轮事件不会把期望身份退回旧用户消息。

若停止发生在自动用户消息写入期间，等待该写入的稳定身份后将其结算为取消，不启动模型；停止发生在两轮之间也会结算未开始的自动消息。
