# 项目、会话与存储

> 本文区分正式事实、运行状态、展示状态和缓存。它们不能互相替代。

## 项目

普通项目、知识、经验、角色、主题、工具和供应商都具有稳定 ID、目录和分类关系，但各自内容合同不同。通用项目仓库组合不同类型的文件目录；页面不应通过扫描磁盘重新定义项目是否存在。

普通项目可以使用天策管理的目录，也可以指向用户选择的外部工作目录。所有文件操作都必须由项目 ID 解析真实根目录并做范围校验，不能根据前端当前选中项目猜测归属。

## 会话

普通对话、分支、AI 子会话和功能会话共享会话身份、父子关系、消息与运行状态。当前功能会话包括自动命名、记忆压缩和记忆管理；具体功能差异来自配置与运行器，不应成为另一套消息数据库。

会话关系至少包含：

- 项目和会话 ID；
- 父会话、来源消息与关系类型；
- 创建者和历史方式；
- 运行状态、模型/角色/工具设置；
- 正式消息、工具调用和工具结果。

## 项目数据库

项目内正式会话状态保存于：

```text
<项目根>/.Tiance/tiance.db
```

会话附件仍位于项目 `.Tiance` 下的会话附件目录。JSON、JSONL、缓存和前端 store 不应成为同一正式消息的第二个权威来源。

SQLite 中的主要事实由 repository 读取和写入。合法 JSON 但结构不符合领域合同的数据不能被当作“不存在”；损坏数据应明确报错或进入可观察修复流程。

## 审计快照的增量存储

数据库 schema v6 起，逻辑模型记录 `model_exchanges` 和物理 HTTP 交换使用 `audit-manifest-v2`。对外仍返回每一轮完整、脱敏后的请求与响应；存储层记录实际 JSON 结构的变化，不重新运行上下文组装、记忆压缩或工具选择逻辑来猜测历史内容。

- `conversation_session_events` 的模型记录保存版本引用；HTTP 工件的 `conversation_artifact_payloads` 保存 gzip 压缩后的版本引用，标记为 `gzip+audit-manifest-v2`。
- `conversation_audit_snapshots` 按会话、记录类型建立独立版本链，保存追加/替换、删除、列表区间替换和对象键顺序变化。记忆压缩导致消息列表缩短或替换时同样保存实际变化。
- 大于等于 1 KiB 的字符串和工具定义集合进入 `conversation_audit_blocks`，按内容哈希去重并 gzip 压缩。同一项目的不同轮次、会话和审计类型可以共用内容块。
- 最多连续保存 32 层增量，然后保存压缩检查点；增量比检查点更大时也直接保存检查点。检查点仍引用共用大块，不把大块正文复制回来。
- `conversation_audit_snapshot_blocks` 记录检查点和增量新引入的块引用。用户删除会话或替换该会话的逻辑审计记录时，事务内释放无人引用的 v2 块，共用块继续保留。

版本、内容块、引用关系及所属事件/工件在同一个 SQLite 写事务内提交。读取在同一个数据库快照内还原，逐层校验结构哈希，校验块哈希，并核对最终完整正文的大小及 SHA-256。缺失基版本、损坏内容块或跨会话/跨类型引用必须报错，不能返回删减后的请求。

增量基准是同一会话、同一类型上一条已持久化记录。异步任务完成次序不决定业务轮次；业务时间、轮次和尝试编号仍来自原记录，版本链只负责无损存储。

运行错误继续保存在 `conversation_journal` 的 `model.request_attempt.failed` 等事件中，最终状态及兜底错误继续保存在 `conversation_runs`。对话中的实时错误仍来自流事件，历史错误仍由原来的运行/尝试接口返回；不会依赖解压审计快照来显示错误。

存储约束与体积口径：

- 审计只支持增量快照格式。旧的内联 JSON、gzip 全量正文和 `audit-manifest-v1` 不再读取；没有旧格式解码、自动转换、回退或混读分支。
- schema v6 的表结构安装只用于创建增量存储表，不转换旧审计内容。旧审计正文由明确的一次性数据清理处理，不在应用启动或会话读取时运行清理程序。正式聊天、运行记录和错误事件独立保留。
- 2026-10-19 经用户明确授权，一次性清理当前 9 个项目的 3,107 条旧逻辑审计、3,260 条旧 HTTP 正文和 2,345 个旧外部块，保留工件元数据及错误事件关联；逐库校验其余数据不变。清理脚本执行后移除，不作为应用的升级或兼容流程保留。
- `size_bytes` 仍表示还原后的完整正文大小；`stored_size_bytes` 表示工件自身的压缩引用大小，不包括共享版本和内容块。统计实际占用应合计相关表及索引，不能把每条逻辑正文大小当作实际磁盘占用。
- 2026-10-19 对一个真实项目 100 条逻辑记录进行只读抽取及临时库回放：旧记录 JSON 45,059,407 字节、引用外部块 1,501,028 字节，新临时数据库含索引 2,060,288 字节；100 条完整正文逐条 SHA-256 校验一致。这是样本结果，不是固定压缩比。

## 四类状态

| 类型 | 示例 | 规则 |
| --- | --- | --- |
| 正式事实 | 用户消息、完整助手回复、已提交工具调用和结果 | 进入后续模型上下文，不能被展示分页截断 |
| 运行状态 | running、waiting、error、cancelled | 表达生命周期，不冒充助手正式回复 |
| 展示状态 | 当前标签、展开节点、画布位置 | 可重建，不决定业务事实 |
| 审计 | 原始请求、响应、尝试、大小和错误 | 用于排查，不自动进入模型上下文 |

## 分支与派生

分支保留来源消息和父子关系。派生会话可以继承已经成立的压缩覆盖和记忆，但缓存谱系只用于供应商缓存提示，不能决定分支消息是否存在。

工具调用与工具结果构成协议原子组。读取历史、分页或派生时不能从组中间切开；检测到损坏组时应暴露数据问题，不能静默删除后继续生成看似正常的请求。

## 工作区展示状态

打开标签、活动会话、布局和缩放等由前端/工作区状态保存。异步保存必须防止旧请求后返回覆盖新状态。读取失败不能以空对象覆盖原文件。

聊天中自动识别出的裸文件名（例如行内代码 `报告.md`）表示按名称查找，不预先假定文件在项目根目录。点击查看、资源管理器、系统应用或复制路径时，读取当前项目内容文件快照；文件名唯一匹配后才执行，重名列出实际路径，读取不完整则明确提示。此查找沿用内容文件快照范围，不包括根级 `.Tiance`、内部临时文件和符号链接；这些文件应提供明确路径。绝对路径、带目录的相对路径、`./报告.md` 和显式 Markdown 链接始终按指定路径处理，不替换为其他同名文件。消息原文和文件都不因此改写。

文件读取返回不存在时，标签页显示“找不到文件”和实际路径；仅凭找不到不能断言文件曾被删除。
