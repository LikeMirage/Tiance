# 在线市场：公开共享、私人仓库与本地所有权

> 实现基线：2026-08-02。

天策的在线市场不是一台中央应用商店服务器。每一类内容都可以由一个普通 GitHub 仓库发布：仓库根目录提供统一索引，每个可下载项目拥有自己的清单和包，客户端负责校验、下载并安装到本地分类。

这种设计让作者可以用公开仓库群策群力，也允许个人把完整项目保存在只有自己授权的私人仓库中。

## 远端与本地各自保存什么

远端市场使用：

- 根目录 `index.json`：市场名称、更新时间和可下载项目列表；
- 每个项目的 `manifest.json`：稳定身份、版本、作者、说明、文件或包信息；
- 项目文件夹或下载包：真正内容；
- 可选预览图等同仓库资源。

本地使用：

- 各集 `catalog.json`：用户自己的分类、排序和本地项目路径；
- 各集 `market-settings.json`：当前市场地址与筛选条件；
- 市场缓存：断网或刷新失败时展示最近一次通过校验的索引；
- 项目内市场收据：记录安装来源、远端身份、版本和内容摘要，用于判断更新。

远端不管理用户分类。下载时由用户选择本地分类；同一个远端项目可以被不同用户放在完全不同的位置。

## 为什么统一使用 `index.json` 与 `manifest.json`

`index.json` 回答“这个市场里有什么”，`manifest.json` 回答“这个具体项目是谁、是什么版本、应包含什么”。本地 `catalog.json` 回答“我把已经拥有的项目怎样分类”。三者职责不同，不能互相替代。

主题、角色、工具、供应商、普通项目、知识和经验共享同一市场外壳：地址、连接、缓存、搜索、筛选、状态和 GitHub 私库访问共用；每一类只负责自己的索引字段、包校验、安装冲突和更新策略。

## 公开仓库：GitHub Pages

默认开源市场使用 GitHub Pages 地址，例如 `https://likemirage.github.io/Tiance-tools`。客户端读取 `<地址>/index.json`，再按同源路径获取资源和包。

Pages 的优势是面向普通用户的只读静态发布：无需 Git、无需克隆仓库，也不依赖 GitHub 网页结构。仓库的 `.git` 地址仍然适合作者维护源码，但不是普通客户端的下载协议。

## 私人仓库：GitHub App 授权

私人仓库不能用 Pages 公开。用户在设定集通过 GitHub 设备登录完成账号授权，再在 GitHub App 安装设置中选择允许天策读取的仓库。天策只列出 App 安装范围内的仓库。

连接私人市场时使用仓库根地址：

```text
https://github.com/owner/repository
```

后端通过 GitHub API 读取仓库默认分支的 `index.json` 和包文件，因此同一份市场结构既适用于公开 Pages，也适用于私库。给 App 新增仓库后，回到 GitHub 登录页刷新授权仓库列表，再从市场来源下拉框选择。

登录凭据保存在 `Data/secrets/github-auth.json`，其中访问与刷新凭据经过系统秘密保护：Windows 优先使用当前用户 DPAPI。退出登录会删除本地凭据。市场设置 JSON 只保存仓库地址和筛选条件，不保存 Token。

## 下载安全与完整性

远端输入不是可信本地文件。通用下载层会：

- 只接受 HTTPS 或规范 GitHub 仓库根地址；
- 限制资源必须位于同一市场目录或同一 GitHub 仓库；
- 拒绝 `..` 等越界路径；
- 限制索引、资源和包大小；
- 校验包的预期字节数和 SHA-256；
- 只在索引通过各集 Schema 校验后写入缓存；
- 安装时使用临时目录和安全替换，避免半包覆盖本地项目。

## 安装、冲突与更新

稳定身份来自清单中的项目 ID，不来自显示名称。显示名称可以本地化或修改；同一 ID 才被视为同一个市场项目。

首次安装需要选择本地分类。工具还要检查稳定调用名是否与已有工具冲突；若只是名称冲突，可以在明确交互中重命名本地显示名称或调用名，但改变调用名后不能再仅凭名字认定更新关系。更新依据市场收据和稳定项目 ID，并按各集规则保留本地所有权。

供应商是最典型的例子：市场可以更新公开的 `provider.json`、规则和模型清单，但不能带入 `credentials.json`；本地加密密钥、启用状态、创建信息和不受市场管理的本地模型需要保留。

普通项目则可以连同 `.Tiance/` 分享会话、分支、记忆和工作过程。客户端不会替上传者做内容审查，但上传界面和文档应明确提醒其中可能包含隐私、路径、对话与供应商信息。

## 缓存不是安装来源

在线索引会保存在本地缓存，用于快速展示和连接失败时回退。缓存只是一份通过校验的远端目录，不等于已经下载项目，也不能绕过安装时的包校验。预览图可以来自远端资源缓存；安装后的本地主题和其它项目仍从本地文件夹渲染。

## 当前边界

- GitHub 私库连接目前是只读市场访问，不负责向仓库上传项目。
- GitHub App 只能读取安装时授权的仓库；新增仓库必须在 GitHub 安装设置中授权。
- 各集共用市场机制，但其包结构和本地合并规则不会被强行做成完全相同。
- 市场仍处于早期版本，索引 Schema 和发布流程在稳定发行前可能继续调整。
