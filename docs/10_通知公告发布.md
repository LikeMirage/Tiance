# 通知公告仓库与发布

## 能力边界

公告是远端只读内容。远端索引和正文可以缓存；用户已读状态是本地正式状态，不能由缓存文件是否存在决定。撤回公告仍保留稳定 ID 和 revision 语义。

## 仓库结构

```text
index.json
announcements/
  2026.json
  2026/
    08-24-example/
      r1/
        content.md
        assets/
          image.png
```

根 `index.json` 示例：

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-08-24T10:00:00+08:00",
  "latestAnnouncementId": "2026-08-24-example",
  "latestAnnouncementYear": 2026,
  "years": [
    {"year": 2026, "indexPath": "announcements/2026.json"}
  ]
}
```

年度索引示例：

```json
{
  "schemaVersion": 1,
  "year": 2026,
  "updatedAt": "2026-08-24T10:00:00+08:00",
  "announcements": [
    {
      "id": "2026-08-24-example",
      "revision": 1,
      "title": "标题",
      "summary": "摘要",
      "publishedAt": "2026-08-24T10:00:00+08:00",
      "importance": "normal",
      "status": "published",
      "contentPath": "announcements/2026/08-24-example/r1/content.md"
    }
  ]
}
```

`importance` 允许 `normal`、`important`、`critical`；`status` 允许 `published`、`withdrawn`。

## 正文与资源

正文为 UTF-8 Markdown。资源必须使用公告目录内的相对路径，例如：

```markdown
![示意图](assets/image.png)
```

禁止绝对 URL、`file:`、`..` 和脱离公告根目录的资源。客户端通过受控资源路由读取缓存或远端内容。

## 发布步骤

1. 为公告选择稳定 ID；修改已发布公告时增加 `revision`。
2. 写入新的 `rN/content.md` 和资源，不覆盖旧 revision。
3. 更新年度索引；不要只保留最近 N 条公告。
4. 更新根索引的时间和 latest 指针。
5. 发布到 HTTPS 静态站点或受支持的仓库来源。
6. 通过客户端 `/announcements/check`、年度索引、正文和资源接口核验。

已读状态按公告 ID、revision 和读取时间保存。缓存损坏或清理不能重置所有已读记录。
