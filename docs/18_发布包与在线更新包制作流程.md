# 发布包与在线更新包制作流程

这份文档说明如何从已提交的 Git 标签制作完整安装包、跳版本程序更新包和相邻版本增量包。用户要求先制作本地发布包时，可以使用仅存在于本地的标签；未经另行授权不得推送或上传。

本流程只用于用户已经确认的新版本正式发布。日常源码修改后的运行验证应使用 `scripts/package-test.ps1`，测试阶段不修改版本号、不创建标签，也不生成在线更新文件。具体见[《测试包制作与验证流程》](17_测试包制作与验证流程.md)。完整的提交、标签、GitHub Release 流程见[《发布包制作与 GitHub 发布流程》](19_发布包制作与GitHub发布流程.md)。

## 一、三种发布压缩包的职责

### 完整安装包

`Tiance.zip` 是可以在新目录中解压后直接启动的完整程序。它包含后端、桌面壳、前端 `dist`、运行环境和允许公开发布的预置数据。

它不包含：

- `.git`；
- 前端源码、`node_modules` 和测试缓存；
- `Data/projects`、数据库、会话、日志和供应商密钥；
- 根目录 `docs/`、`assets/` 和 `README.md`。

### 在线更新包

`Tiance-update.zip` 是不含 `Data/` 的完整程序更新包，用于跳版本更新和旧客户端兼容。`Tiance-update-incremental.zip` 是两个相邻标签之间的程序文件差分，只允许清单声明的来源版本使用。更新器会先备份将被替换或删除的文件，然后执行清单中的操作；失败时回滚。

在线更新包禁止包含 `Data/`，因为用户项目、会话、工具、主题、供应商设置和密钥都属于本地数据。

这也意味着 `Data/tools`、`Data/providers` 等预置集合的新增或修改不会通过软件差分更新包分发。工具和供应商内容应发布到各自在线市场，由市场稳定 ID 和版本规则负责安装或更新；完整安装包仍可携带标签中已经公开跟踪的预置集合。

## 二、生成命令

必须在仓库根目录执行，并且两个标签在本地存在。正式上传前再确认标签已经推送；打包脚本本身不操作远端：

```powershell
./scripts/package-release.ps1 `
  -Version 0.3.11 `
  -Tag v0.3.11 `
  -PreviousTag v0.3.10
```

脚本会在 `发布包/` 中生成：

```text
Tiance.zip
Tiance-update.zip
Tiance-update-incremental.zip
update.json
```

`发布包/` 被 `.gitignore` 排除，不应提交到源码仓库。

## 三、两种更新包如何产生

增量包执行 `git diff PreviousTag Tag`，然后只保留允许更新的程序路径。完整程序包包含目标标签的全部允许程序文件，并删除历史正式标签中存在但目标标签已删除的程序文件。

- 根目录 `Tiance.exe`；
- `system/`；
- `runtime/`；
- `1_PythonServer/`；
- `2_ReactWeb/dist/`；
- `3_PyWebView/`。

新增或修改的文件进入 `replace`。删除的文件进入 `delete`。更新器不会根据文件名猜测删除内容，而是严格按 `system/update-manifest.json` 执行。

清单必须包含：

```json
{
  "schemaVersion": 2,
  "version": "0.3.11",
  "replace": ["system/version.json"],
  "delete": []
}
```

其中 `system/version.json` 必须在 `replace` 中，清单里的文件集合必须与压缩包实际内容一致。

## 四、`update.json` 的作用

`update.json` 同时记录完整程序包和增量包。客户端仅在当前版本等于 `incremental.fromVersion` 时选择增量包，否则选择完整程序包。顶层字段继续指向完整程序包，保证旧客户端跳版本时不会误用增量包。

- `version`：目标版本；
- `assetName`：更新包文件名；
- `size`：更新包字节数；
- `sha256`：更新包 SHA-256。

它不是更新操作清单。真正的替换和删除清单在更新包内部的 `system/update-manifest.json`。

## 五、生成后检查

```powershell
Get-FileHash 发布包/Tiance-update.zip -Algorithm SHA256
Get-FileHash 发布包/Tiance-update-incremental.zip -Algorithm SHA256
tar -tf 发布包/Tiance.zip | Select-String "Tiance.exe|system/version.json|2_ReactWeb/dist/index.html"
tar -tf 发布包/Tiance-update.zip | Select-String "update-manifest|Data/|Tiance.exe|TianceUpdater.exe"
```

还应检查：

- 完整包能在全新短路径目录启动；
- 完整包没有密钥、数据库和本地项目；
- 更新包没有 `Data/`；
- `update.json` 中的大小和 SHA-256 与本地文件一致；
- 两种更新包的 GitHub Release 下载摘要都与 `update.json` 和本地摘要一致。

## 六、版本迁移边界

新更新协议从 `3.11` 开始使用。旧版 `3.10` 的更新器要求差分包包含旧式核心程序文件，因此不能把当前新协议差分包当作旧版本的通用升级包。无法完成旧版本迁移时，应使用完整安装包安装新版本。

从 `3.11` 开始，后续版本使用 `schemaVersion: 2` 的文件级清单进行更新。

## 七、禁止事项

- 不从当前未提交工作区直接压缩发布；
- 不用完整安装包覆盖用户现有目录；
- 不把 `Data/` 放进差分包；
- 不用新文件覆盖旧版本号的 GitHub Release；
- 不手工修改 `update.json` 中的哈希来掩盖包内容变化。
