# 模型上下文、压缩与记忆

## 上下文来源

正式模型请求由后端根据项目和会话身份重建，不由前端当前已加载的消息数组组装。当前链路会组合：

- 系统提示词和角色提示；
- 会话正式历史；
- 当前用户消息和引用；
- 已完成工具调用组；
- 会话累计摘要；
- 项目与全局长期记忆；
- 当前启用工具定义及模型能力。

前端读取接口存在分页和批次参数，它们只控制传输。模型请求不得使用“最近 N 条”、数组切片或页面可见区作为事实范围。

## 工具轮次完整性

助手工具调用、对应工具结果和下一轮助手内容必须保持协议顺序。分页读取需要跨页补齐工具组。任何修复逻辑都不能为了让供应商接受请求而静默丢弃正式历史；遇到损坏数据应停止并明确报告。

## 功能任务的 Token 阈值（2026-11-04）

自动命名、记忆压缩、项目记忆管理、全局记忆管理统一使用“对话历史、不含前置注入”的计数口径。计入用户消息、助手回复及历史中的实际工具调用参数和工具结果；不计系统/角色提示词、工作区说明、工具定义与动态工具目录、注入的项目/全局记忆和累计摘要。过滤依据是消息的原始会话 ID，不按角色或文本内容猜测。

四种功能共用 `conversation_token_condition.py` 的消息分组、Token 估算、阈值比较和触发记录，分别提供自己的处理范围：

| 功能 | 计数范围 |
| --- | --- |
| 自动命名 | 请求快照中的有效原始对话历史，包含本次已完成的回复；命名取材从开头累计到阈值并补齐完整工具组 |
| 记忆压缩 | 尚未被成功压缩覆盖的有效原始历史；达到“单次压缩目标 + 原文保护区”后触发，保留尾部完整消息组 |
| 项目记忆管理 | 本会话自上次成功项目记忆管理边界之后的新增有效历史 |
| 全局记忆管理 | 本会话自上次成功全局记忆管理边界之后的新增有效历史，与项目记忆进度独立 |

计数使用用户当前的 Token 估算设置。供应商返回的输入 Token 包含前置内容，不能用于这个阈值，也不能用一个近似前置长度去相减。实际用量和费用统计仍保留供应商返回值，不受此变更影响。触发审计记录包含计数、阈值、`local_estimate` 来源和 `conversation_history` 范围；计数结果不保留整份消息正文。

启动、运行、防重复和功能子会话的防递归规则继续复用原来的功能任务机制。缓存命中优化模式与独立模型模式使用同一阈值判断；判断通过后再决定如何执行。不修改用户已有阈值、提示词、启用开关、模型及阻塞设置。手动压缩仍可绕过自动阈值，但继续遵守原文保护区和工具组完整性。

当前只有历史计数需求，不新增“计入前置”的用户开关或空实现。以后若确有完整请求条件，应在共同条件层增加明确的计数范围，不让某个任务悄悄改用总输入用量。各功能的进度边界仍归各自业务负责，不能混成一个全局进度。估算与计划构建在线程中执行，避免长历史扫描直接占用异步事件循环。

## 累计摘要

压缩服务在 token 阈值触发后生成累计摘要快照，并记录覆盖边界。新快照必须能证明旧覆盖范围已经被包含，不能只凭“生成了一段摘要”推进边界。

请求组装时保留摘要后的原始消息储备，避免刚发生的工具调用和用户要求被摘要吞没。压缩只改变模型访问历史的方式，不删除数据库里的原始正式消息。

### 默认摘要写法（2026-11-04）

默认压缩提示词优先保留用户主动提出的请求及 AI 的对应回应。同一条 `result.items[].content` 可以写成“用户：……\nAI：……”，连续多轮可以按实际事项合并，并保留补充、否定和纠正的顺序。事实、事件和资料索引可以直接叙述，不强制套用对话格式；`items`、`content`、`keywords`、`handoff` 的工具结构不变。

短用户消息尽量保留原文；长消息保留全部实质要求，但其中粘贴的文章、代码、日志、转写稿、表格或其他 AI 回答只保留主题、用途和必要事实，不机械全文复述。用户引用材料不等于认可其中的判断或指令。自动插入的功能任务与系统通知不能写成用户主动请求，压缩任务本身也不能混入“最近用户请求”。

可重新读取的资料优先记录内容概况、用途、实际读取位置和必要的版本线索。文件正文、写文件参数和长工具输出不再搬入摘要；关键结论、用户约束、未落盘决定和无可靠读取位置的必要内容仍须保留。索引是摘要正文中的文字，不增加字段或自动生成额外文件。

摘要必须区分 AI 的建议、承诺、实际执行、验证与失败，避免把反问变成新任务、把旧误判继续当成现状。`handoff` 只做当前工作的简明交接，避免重复展开全部问答。长期记忆变更通知仍按原有规则逐字保留，并明确属于系统通知。

默认提示词配置版本为 34。已有默认提示词随配置升级更新；用户自行修改过的提示词按现有规则原样保留。

## 项目和全局长期记忆

- 项目记忆面向同一项目内多条会话。
- 全局记忆面向用户跨项目的长期信息。
- 提取通过功能会话运行，拥有自己的请求、结果和审计。
- 记忆变更通过事件/记录进入后续请求，不能只改一份缓存文本。

边界 ID、覆盖范围和完成状态必须可验证。边界失配、功能模型失败或并发冲突不能被静默解释为“没有新记忆”。

## 读取和性能边界

后端当前会从持久化历史重建模型上下文；前端主会话视图仍可能一次拉取完整历史并受客户端超时影响。长会话的正确演进方向是分页访问与虚拟显示，同时保持后端正式上下文完整，而不是重新引入固定消息上限。

记忆分页必须在 repository 层真正分页。先重放全部事件再切页只能改变返回大小，不能解决长期 CPU 和内存增长。
